# 이전 대화를 이어받는 개별 룰 표

2026-11-01 query-completion 1.19.4와 공통 하네스를 B에 반영했다. 아래는 조회·표시 기능이며 변경 승인과 실행 권한은 기존 기준을 따른다.

## 대화와 표시

| 대화 | 처리 |
| --- | --- |
| `WAF 룰 자세하게 보여줘` → `각각 표로 보여줘` | WAF와 기존 조회 범위를 유지하고 정의 하나당 한 행으로 표시 |
| `IDS 기본 룰` → `표로 정리해줘` | IDS 기본 룰 범위를 유지 |
| `Wazuh 상관규칙 자세하게` → `룰 각각 표로` | Wazuh와 상관 조건을 유지 |
| 특정 ID 조회 → `개별 룰 표로 보여줘` | 해당 ID 필터 유지 |
| `FW 룰` → `각각 표로 보여줘` | 기존 FW 조건·handle 표 사용 |
| WAF 조회 → `IDS 룰 표로 보여줘` | 명시한 새 대상 IDS 우선 |
| `장비별 개수 표` | 개별 정의 대신 요청한 집계 표 |
| 새 대화의 `룰 조회해줘` | 대상 장비를 한 번 확인 |

기본 범위는 기본+커스텀이다. 이전 대화에서 사용자가 기본 또는 커스텀으로 한정했다면 그 조건을 이어받는다. 다른 사용자·대화, 새 주제, 쓰기·승인 요청을 넘어 과거 조건을 찾지 않는다. 공동 채널의 담당 유지와 명시적 멘션 우선 규칙은 [채널 정책](chat-channels.md#짧은-후속-대화와-대기열--2026-11-01)을 따른다.

WAF·IDS·Wazuh 표는 `ID/SID`, `구분`, `설정상 포함`, `설명·조건·동작 (요약)`, `출처 파일`을 보여준다. 같은 ID가 여러 정의에 있으면 별도 행으로 남긴다. “설정상 포함”을 실제 탐지·차단 성공으로 바꾸지 않는다. 조건/동작은 실제 조회 필드로 만들며, 필드가 없으면 임의 보충하지 않는다. 파이프·개행·HTML·Markdown 문자를 이스케이프해 열이 깨지지 않게 한다.

표는 한 페이지 최대20행이며 문자 한도 때문에 더 적을 수 있다. 여러 장비는 공통 표시 예산을 나눠 쓴다. 긴 필드는 `…[표시 축약]` 등으로 표시한다. `룰 표 2페이지`처럼 표시 페이지를 요청할 수 있으며, 조회한 정의 수와 표시한 행 수를 구분한다. 조회하지 않은 다음 MCP 페이지는 표시 페이지 변경만으로 확보되지 않는다. `전체 룰을 각각 표로 보여줘`는 기존 전체 상세 조회 경로를 사용하며 도구/시간 한도를 넘으면 미조회 범위를 남긴다. 원문 요청에는 기존 원문 경로를 우선한다.

## 근거를 재사용하는 조건

단순 표 재정리는 같은 대화의 실제 읽기 영수증에서 대상·필터·스키마·SHA·조회 완전성을 검사한다. 조건을 만족하면 추가 모델/MCP 호출 없이 표를 만든다. 답변에 **이전 조회 결과 재정리 · 새 조회 없음**을 표시하고 원래 KST 관측 시각을 유지한다. 현재 상태를 새로 확인했다고 표시하지 않는다.

개수만 조회했거나 상세 결과가 부족하면 같은 범위로 새 상세 조회를 진행한다. 해시 불일치, 다른 범위, 실패 결과, 현재/새로/다시 조회 요청은 재사용하지 않는다. 봇의 이전 설명을 실제 룰 원문으로 취급하지 않는다. 명시적 교차검토도 독립 조회 경로를 유지한다.

공동 분배기는 기존 `request_context`의 같은 사용자·채널·스레드 및 직전15분/100요청 연결을 사용한다. 완료된 같은 담당의 읽기 결과만 비공개 `request_evidence` 테이블에 보관한다. 건당1MiB 이하·최근200건으로 제한하며 보호 호출이 있는 작업과 쓰기 결과는 넣지 않는다. 기존 배포 전 결과에 상세 영수증이 없다면 새로 조회한다. Native Hermes는 같은 대화의 사용자 이력과 연결된 도구 결과를 검증한다.

Hermes 관리 실행부는 `get_security_rules`도 기존 전체 읽기 감사 경로로 전달한다. 기존5,000자 미리보기 때문에 JSON이 잘리는 문제를 피하며 128KiB 감사 한도와 초과 거절은 유지한다.

## 설치·오프라인 반입·운영 복구

새 설치 진입점은 루트 `deploy.sh` 하나다. 기존 siem, review_chat, soc_runtime, soc_management, ollama_trial 설치 경로가 갱신 소스를 배치한다. Ollama 반입 목록에 공통 `chat_markdown.py`를 추가해 독립 설치 디렉터리의 grounding import도 성립하도록 했다. 새 패키지·이미지·포트·키·승인 권한은 필요 없다.

오프라인 반입에는 다음 갱신 소스와 각 설치 모듈의 기존 의존 파일을 포함한다.

- `infra/ollama-trial/harness.py`
- `infra/hermes/query-completion/{alignment.py,__init__.py,plugin.yaml}`
- `infra/hermes/{review_channel.py,review_channel_worker.py,soc_management_run.py,chat_markdown.py}`
- `deployment/ollama_trial.py` 및 기존 `deploy.sh`/역할별 설치 경로

운영 B에는 유휴 확인 후10:18:48 KST에14개 runtime 파일을 증분 반영했다. 기존 host 전용 관리 실행부와 controller 내장 gate는 해당 감사 조건만 고쳤고 다른 설정을 덮어쓰지 않았다. Hermes1회 재시작, review/Ollama chat 재시작 후 연결 상태를 확인했다. 설정·환경·SOUL·cron 등 보호 파일8개 SHA는 유지됐다. DGX/Thor와 학습은 이 작업에서 변경·조회하지 않았다.

복구 원본은 `/var/backups/capstone-rule-table-20261101-r1/manifest.json`이다. 유휴 확인 후 manifest의 기존 runtime/receipt를 복원하고, 이번에 새로 추가한 trial `chat_markdown.py`만 제거한 뒤 같은 세 실행부를 재시작한다. **queue.sqlite/DB/WAL과 대화 이력은 복원하거나 삭제하지 않는다.** 새 보조 테이블은 구버전에서 무시할 수 있다. 대응 소스14개는 `/opt/capstone-automation/releases/rule-table-20261101-r1`에 보존했으며 이 부분 snapshot은 새 서버 전체 설치 bundle이 아니다.

10:27:54 KST 후속 점검에서 `새로 조회`, `다시 확인`, `재조회`, `refresh`도 재사용을 거절하도록 공통 하네스2사본을 보완했다. 같은 세 실행부를 유휴 상태에서 한 번 더 재시작했고10:28:33 검증을 통과했다. 후속 원본/소스는 각각 `/var/backups/capstone-rule-table-20261101-r2/manifest.json`, `/opt/capstone-automation/releases/rule-table-20261101-r2`에 보존했다. 최신 재현에는 r1 소스 위에 r2 하네스를 사용한다. 후속 보완만 되돌리려면 r2를,이번 기능 전체를 되돌리려면 r2→r1 순으로 원본을 복원한다. DB는 그대로 유지한다.
