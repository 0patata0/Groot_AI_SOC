## 2026-11-13 교차 검토 원칙의 스킬 절 통합

사용자 지시("되도록이면 스킬로 묶을 수 있는 부분은 묶어서 관리하자")에 따라, 공동 채널 작업자 코드에 흩어져 있던 교차 검토 판단 원칙을 `soc-investigate`의 `## 교차 검토 대조` 절로 옮겼다(문구 그대로, 에이전트 상태 원칙 1줄 추가). `workflow_contract.SECTION_ONLY`에 등록된 절은 해당 단계에서만 `section_policy`로 불러오고, 일반 조사·조회 프롬프트의 전체 본문에서는 빠진다. Ollama 교차 검토 합성과 Hermes 교차 검토가 같은 절을 쓴다. 조사 본문에는 "지정 장비 경보 조회로 시작" 원칙 한 줄을 더했다. 도구 범위·인자 제한은 스킬이 아니라 하네스·실행기 코드가 강제한다. [후보](../validation/investigation-scope/README.md).

이후 이 절에 더한 원칙(11/14): 검토자 자신의 조회가 한도에 닿았으면(`scan_capped` true) `scanned`·`returned_count`·`returned_items`·`omitted_items`는 그 한도와 같은 값이라 상대 표본 크기를 확인하거나 반박하지 못한다. 같은 경계는 작업자 코드(`bind_peer_references`)가 `peer_query_scope_mismatch`로 강제한다. [후보](../validation/peer-excerpt/README.md).

## 실제 연결

`workflow_contract.py`는 위의 고정된 다섯 이름만 허용한다. 각 SKILL의 이름·설명·고유 마커·크기와 파일 경로를 확인하며 누락·중복·심볼릭 링크를 조용히 무시하지 않는다. 원본 정의는 위 다섯 폴더에 하나씩 둔다. 설치된 세 프로필의 `skill-soc-*.md`는 같은 원본 바이트의 배포 복사본이다. flat 이름으로 기존 파일별 백업/원복과 충돌 없는 초기 반입을 유지한다.

SDK의 기존 요청 해석과 Native의 같은 공유 하네스가 필요한 업무만 선택한다. Native는 이전 업무 블록을 제거하고 현재 블록을 한 번 넣는다. root 자동조사/검토는 실제 사건·변경 문맥의 절차를 사용하고 단순 조회는 기존 읽기 경로를 사용한다. 선택을 위한 추가 LLM/MCP 호출은 없다. 도구 스키마/영수증 검사·렌더링 코드와 API별 도움말은 기능상 필요한 부분을 유지했다. 전체 하네스 문장을 모두 삭제했다는 뜻은 아니다.

권한·강제 역할·정확 후보 승인·보호 주소·TTL/소유권·결과 불명 시 재실행 제한은 SOUL와 서버 코드에서 계속 검증한다. SKILL을 편집해도 도구 권한이나 승인이 생기지 않는다. Native skill_manage의 임의 자기 수정·배포는 이번에 연결하지 않았다. 환경의 변동 상태를 스킬에 외워 두지 않고 실제 MCP 근거로 확인한다.
