# 교차 검토의 과거 조회 참조와 수치 결속 검증

**세 후보 모두 의미 오류가 남아 운영 채택을 보류했다.** 과거 조회 조건을 새 관측과 구분하고 원문 수치를 결속하는 경계는 검사했지만, 답변 전체의 정확성을 확보하지 못했다. 프로젝트 정본·초기 설치 입력·운영 파일에는 후보를 반영하지 않았다. [현재 상태](../../../STATUS.md) · [검증 원장](validation.json) · [앞선 문맥 전달 후보](../peer-source-context/README.md).

## 비교 조건과 결과

두 군 모두 같은 균형 학습본 `soc-qwen36:35b-balanced-q4km-20261108`을 사용했다. `context`는 앞서 보류한125검사 문맥 전달 후보이며 미학습 모델이나 실제 운영 배포본이라는 뜻이 아니다. 각 라운드는 같은8개 개발 사례에서 context와 해당 후보를 비교한16리뷰다. 세 라운드48리뷰·정정 포함80생성은 독립48문항이 아니다. [입력](cases.json)의 `expected`와 `label_scope`는 모델 입력에서 제외했다. 입력 파일의143검사 군 설명은 첫 R1 동결 당시의 설명이며 실제 후보 버전은 아래 표와 각 원장이 기준이다.

## 경계에서 보완한 것

- 같은 요청의 완료 읽기 감사·원문/인자 SHA를 확인한 과거 조건만 `source_query_scope`로 연결한다. 현재 관측 `observation`과 참조 집합·허용 용도를 나누고, 과거 상태·로그 본문·승인을 새 근거로 승계하지 않는다.
- R1은 참조 종류를 맞춰도 자유 `text`에 “현재 정상·공격0건”을 붙일 수 있었다. [직접 반례](adversarial-free-text.json)는 그 틈을 확인한 실패 증거다. R2는 과거 항목의 자유 서술을 금지하고 원문과 당시 필드를 그대로 표시한다.
- R2에서도 같은 값을 “이견”으로 분류했다. R3는 과거 항목을 중립적인 조회 자료로 제한한다. 모델이 선택한 원문 숫자의 정확한 위치와 당시 숫자 필드를 다시 결속해 값만 비교한다. 날짜·시각·IP·식별자의 숫자 조각, 다른 문장의 숫자, 미등록 참조·변조 원문·비수치 비교를 거절한다. 과거 자료만 내면 검토 전체를 완료로 표시하지 않는다.
- R3의 수치 일치는 **선택한 값의 일치**다. 같은 항목을 선택했는지는 여전히 모델의 의미 판단이며, 전체 사건 판단·정상·승인·실행 완료를 증명하지 않는다. 현재 상태 판단은 새 관측과 기존 검사를 계속 사용한다. 수치 비교로 보안 판단을 대신하지 않았다.

공식 Harness² `6868817518876de8fd170c6a8354daca273b6191`은 세 후보 모두25구성·5스킬·18스크립트·상시 문구 증가0을 확인했다. 준비 기준 대비 전달기·정책·작업자·조사 스킬4개 편집 표면이며 테스트는 편집 표면 밖이다. 구조 통과는 의미 정확도 증거가 아니다. 기존4파일 설치 묶음과 스킬 경로를 늘리지 않았고 운영 설치 입력은 그대로다.

실제 과거 Hermes10실행·20읽기를 운영 SQLite 읽기 전용→격리 메모리 DB로 재구성했다. 원 인자/결과 SHA·범위160필드와 과거 참조238개를 확인했다. R3는 같은 과거 자료를 양군에 주어 문맥20/20개를 확인했다. R1/R2 재처리의 문맥0 대조는 `evidence=None` 호출이며, 실제 모델 비교의 context군에는 과거 문맥이 제공됐다. 이 차이를 종류 참조의 전달 개선으로 계수하지 않는다. 새 독립 조회·운영 DB 수정·현재 상태 캐시 생성은 없다.

## 재현과 복구

준비 소스는 `96d8691723c83bdab12f4ba1be05ca6d9eb85eaf`다. [R1 패치](r1.patch)·[R2 패치](r2.patch)·[R3 패치](r3.patch)는 그 기준의 별도 사본에서 `git apply --unidiff-zero <선택 패치>`로 각각 독립적으로 적용한다. 서로 위에 차례로 적용하지 않는다. 패치의6/6/7파일을 별도 사본에 실제 복원해 파일별 SHA와 일치함을 확인했다. 빈 문맥 줄의 공백 표시를 source의 trailing whitespace로 오인하지 않도록 최종 패치는 zero-context로 저장했고, 다시 복원한 소스 SHA는 동결본과 같다. 원장에는 기준·후보 파일 SHA·패치 SHA·회귀·모델 조건을 남겼다. 실행기·종료 기록·실제 추적 재처리 원문은 로컬 전용 검증 기록에 보존한다.

격리 사본에 선택한 패치를 적용하고 기존 Python으로 `test_peer_source_context`, `test_peer_proof_roles`, 기존 `test_review_channel`·`test_workflow_contract`·`test_review_time_correction`을 실행한다. R3는 `test_peer_query_quantities`도 실행한다. 기존 `infra/hermes`, `infra/ollama-trial`, `infra/mcp`를 해당 사본의 Python 검색 경로로 지정한다. Mac에 도구나 패키지를 설치하지 않는다. 원래113검사는 준비 소스에서, context125는 앞선 문맥 후보에서 실행한다.

운영 배포·새 실제 채팅·실제 Native 생성·새 OS 전체 설치는 미수행이다. 후보의 검사 성공을 이유로 승인 경계를 완화하거나 설치기에 연결하지 않는다. 임시 실험 프로세스의 정상 종료·PID 부재와 근거 보존을 확인한 뒤 이번 작업이 만든 Mac/B 임시 사본만 정리한다. G_Harness2·운영 복구본·기존 사용자 환경·가중치·데이터는 보존한다.
