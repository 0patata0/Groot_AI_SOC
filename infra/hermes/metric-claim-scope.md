# 서비스와 관제 지표의 주장 범위

2026-11-08 공통 하네스1.5.79. 한 문장에 서비스와 관제 파이프라인이 함께 있으면, 서비스 이름을 파이프라인에도 적용해 관제 지연 검사를 건너뛰던 공백을 수정했다. 이는 오답 검사 보완이며 모델 판단 능력 향상과 구분한다. [현황](../../STATUS.md) · [검증 정보](metric-claim-scope.validation.json).

## 발견과 변경

실제 관측을 동결한 모델 출력은 서비스의 과거 잠금 실패와 현재 `b:management-pipeline`의 검토 사건 수를 한 문장에 연결하고, 처리 지연이 확인됐다고 주장했다. 전송·실행·기한 초과 지표는 모두0이었다. 기존 검사는 문장 전체의 target과 unit을 동시에 필터링해 파이프라인 주장을 놓쳤다. 잠금 실패를 재시작 실패로 바꾼 별도 오류는 기존 검사에서 거절했으므로 해당 보고 전체가 올바른 답변으로 통과한 것은 아니다.

- 지표 주장마다 앞에 나온 대상과 시각을 대조한다. 서비스 뒤에 명시한 파이프라인 주장도 검사하고, 뒤에서 다른 서비스로 대상을 바꾸면 파이프라인의0건을 그 서비스에 적용하지 않는다.
- 문장 뒤에 나온 과거 시각이 앞의 현재 지연 주장을 면제하지 않는다. 부정·불확실한 표현, 실제 양수 지표와 누락된 지표의 기존 구분을 유지한다.
- 오류 코드 근처의 숫자라도 명시적인 검토 상태 지표에 붙으면 코드 발생 횟수로 읽지 않는다. 같은 문장에 별도로 잘못 쓴 코드별 표본 횟수는 계속 검사한다.

자연어 검사는 지원 표현 범위의 방어이며 모든 문장의 의미를 증명하지 않는다. `review_required_cases`는 `needs_review/outcome_unknown/review_ready` 합계이며 처리 지연·승인 카드 대기 수가 아니다. 반대로 처리 지표0도 전체 기능 정상·침해 부재·사건 해결의 증거가 아니다. 모델이 조사·판단을 수행하며 고정 정상 판정이나 차단을 추가하지 않았다.
