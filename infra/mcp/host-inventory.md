# OS·Docker 읽기와 호스트별 표

2026-11-08 KST. A/B/C의 `get_host_inventory`를 공통 `soc-query`와 `soc-output`에 연결했다. 조회는 승인 없이 가능하며 기존 보호 변경 승인 절차는 유지한다. 일반 셸·sudo·Docker 실행 권한을 모델에 주는 기능은 아니다.

호스트 생략 시 A/B/C 범위를 명시한다. limit/offset은 호스트·분류별이며 기본20, 최대100이다. 명명 상세는 최대100필드/행이다. 다음 페이지는 새 스냅샷일 수 있다. 같은 사용자 대화의 대상·페이지·실패 필터를 유지하며 변경 승인까지 이어받지 않는다. 지정하지 않은 대상/기간/조건은 만들지 않는다.

상단 요약 표에는 호스트·분류·KST 수집 시각·조건 일치/표시 건수·다음 페이지를 표시한다. 상세는 **A 서버 → B 서버 → C 서버** 순으로 별도 표를 두고 각 호스트 안에서 systemd/Docker를 구분한다. 조회 실패·0건·해당 이름 없음도 해당 호스트에 표시한다.

## 공통 용량 표시

`skills/soc-output/SKILL.md`의 용량 규칙을 두 봇이 공유하고, `harness.capacity_text`가 확인된 수치와 원단위만 변환한다. 디스크·메모리·스왑·서비스 메모리·Docker 메모리/입출력에 같은 SI 단위를 사용한다.

| 원자료 | 표시 |
|---|---|
| 107374182400 bytes | 107.37 GB (107,374,182,400 bytes) |
| 16777216 KiB | 17.18 GB (16,777,216 KiB) |
| 1000000000000 bytes | 1 TB (1,000,000,000,000 bytes) |
| Docker 270.5MiB | 약 283.64 MB (270.5 MiB) |

소수점 최대 두 자리, GB=10⁹ bytes·TB=10¹² bytes다. 원본 영수증·SHA는 그대로 유지한다. 이미 반올림된 Docker 통계는 정확한 바이트 원본으로 취급하지 않으며 `약`을 표시한다. `infinity`, `[not set]`, 미확인과 CPU%·PID·카운트·시간은 변환하지 않는다. 디스크 단문은 로컬 파일시스템 목록을, 메모리·스왑 단문은 자원 조회를 선택한다. 모델이 환산값을 다시 생성하는 단계는 추가하지 않는다.

## 수집·권한·설치

- root의 기존 진단 timer가60초마다 고정 명령으로11개 view를 수집해 `root:diagnostics 0640` snapshot을 원자적으로 게시한다. MCP 계정은 snapshot만 읽고 A/C는 기존 강제 SSH reader로 읽는다. TTL180초·2MiB 제한이며 view별 실패를 숨기지 않는다.
- Docker 로그는 실제64hex 컨테이너ID와 고정 argv만 허용한다. 서비스는 실제 loaded `.service` 이름과 허용된 show 필드만 읽는다. 프로세스 인자·환경·원본 inspect 전체는 반환하지 않는다. 원문은 비신뢰 자료이며 마스킹이 모든 비밀 탐지를 보장하지는 않는다.
- 네트워크 조회는 고정 수집 서비스의 address family에 AF_NETLINK를 추가한다. 기존 AF_UNIX/INET/INET6의 허용은 socket 종류 제한이며 IPv6 활성화나 방화벽 허용을 뜻하지 않는다. 봇 계정의 권한은 확대하지 않는다.
- 단일 `deploy.sh`→진단/봇 내부 설치 경로에 같은 소스·스킬·영수증 검사를 연결했다. 설정 입력·키·공개 포트·신규deb/wheel/image는 없다. 기존 systemd, Docker, procps, iproute2, coreutils를 사용한다. 새 OS 전체 설치는 미시험이다.
- 진단MCP1.4.0, 도구45(읽기36/보호9). 기존44개 schema SHA 불변이며 새 읽기1개만 추가했다. 승인형 변경9개의 권한·스키마·TTL을 확장하지 않았다.
