# Journal 조회 시간과 도구 실패 보고 보완

2026-11-08 KST. 하루치 journal 검색이 약6초 걸려 기존 명령당4초 제한으로 실패한 문제를 수정했다. Hermes review의 CLI 실행은 완료됐지만 도구 조회가 실패했을 때, 성공한 다른 읽기까지 일반 실패 문구로 사라지던 경로도 보완했다. [현재 현황](../../STATUS.md) · [작은 재현 원장](journal-query-budget.validation.json).

## 변경과 제한

| 경로 | 적용한 제한·동작 |
|---|---|
| 고정 journalctl | 각 명령 최대12초, 한 요청의 두 검색·행 처리에 공유20초 상한. 남은 시간을 두 번째 검색에 전달하며 초과는 unavailable |
| 로컬 socket 응답 |24초. peer UID·고정 소켓·입출력 바이트 상한 유지 |
| A/C 원격 MCP |36초. 기존 호스트 키 고정 SSH 강제 reader 경로 유지 |
| Native 읽기 실패 | CLI 완료 여부와 별개로 실패한 도구가 있으면 현재 run의 성공/실패 영수증을 대조하여 근거표 보존. 판단 미완료·partial·비재사용 유지 |
| 보호 작업 | 쓰기가 섞이면 기존 controller 보고 유지. 과거 성공한 차단 조회를 더 늦은 실패·미응답 조회 대신 사용하지 않음 |

오래 기다리는 것을 정확성 향상으로 세지 않는다. 제한을 늘린 근거는 실제 같은 구간 검색6.028초 재현이며, 명령·unit·정규식·경로를 사용자가 임의 지정할 수 없다. 마스킹, 메시지/행/응답 크기, 기간, 계정별/전체 rate limit은 유지한다. 단일 reader의 동시 요청 대기 전체를 해결한 것은 아니다.

6행은 모두 `status=deferred`, `reason=controller_already_running`이었다. 6건의 확정 장애로 세면 틀리며, 정제 오류 이력0행과 journal 후보6행은 서로 다른 자료다. 전체 구간 보존·전체 오류 건수·무장애는 증명하지 않는다.

처음 peer 검사의 mock에는 실제 DB의 completed 필드와 부분 trace 형식이 빠져 있었고 정규화된 서버명 표기가 달랐다. 시험 데이터를 실제 계약에 맞춘 뒤 전체 검사를 다시 통과했다. 실제 과거 run의 state는 completed·detail은 model_tool_failure_requires_review인데 검증 스크립트가 사건 상태 needs_review로 가정한 오류도 원장을 확인해 정정했다. B 첫 가용성 검사는 WS 준비 전이라 실패했고 추가 재시작 없이 정상 연결을 확인했다. 이런 검증 실패를 운영 장애나 품질 성공으로 바꾸어 기록하지 않는다.

## 새 대화와 남은 문제

동일한 하루 구간의 원인·현재 관제 대기를 두 봇에 새 root로 순차 질문했다. 개발 회귀 사례이며 공유 GPU/캐시는 통제하지 않았다. 조회·게시 완료와 최종 의미 판단의 정확성을 구분한다. 실제10조회 모두 성공했고 영수증 SHA·필수4읽기의 대상/정확 구간·게시 본문을 대조했다. 게시문은 각 표1개·코드펜스0이며 보호 작업0이다. 브라우저/모바일 렌더링을 새로 전수 검증하지 않았다.

두 job은 done이지만 조사 품질은 모두 미완료다. 이전 도구 실패가 사라진 사실과60초 목표/정확도 달성은 별개다. 남은 작업은 지표별 의미·근거를 구체적으로 전달하는 수정 피드백, 동일한 잘못된 초안 반복과 무관한 추가 읽기, deferred와 failure 구분이다. 평가 답변을 그대로 외우도록 학습시키지 않는다.

자동 SOC controller/direct gateway 전체 실패 경로, 일반 복합 판단, 반복한 모든 질문의60초 응답, 독립 평가·학습본 적격은 이번 수정으로 완료됐다고 주장하지 않는다.

## 설치·복구·정리

`deploy.sh`의 기존 진단/review 설치 경로가 수정된 canonical 파일을 복사한다. 새 패키지·이미지·포트·키는 없으며 오프라인 의존 목록은 변하지 않는다. 설치63검사와 소스 해시를 확인했고 새 OS 전체 설치는 미시험이다. 초기 설치 영수증은 소급 변경하지 않고 증분 원장으로 남긴다.

A/B/C의 `/var/lib/capstone-journal-budget/20261108`에 정확한 원본/후보·권한·SHA와 원복 스크립트를 보존했다. 각15분 독립 원복 타이머를 두고 검증 후 확정했다. B는 queue 유휴·정지 중 DB 불변·보호10파일을 확인했으며 FW·모델·승인 정책은 변경하지 않았다. 복구 때 해당 호스트의 이번 변경만 되돌리고 필요한 reader/클라이언트를 다시 시작한다. 실제 수동 원복 시험은 별도다.

Mac 자체 임시2폴더8,354,508B, 서버 격리942파일15,035,821B를 목록/SHA 검증 뒤 제거했다. 운영 복구본·로컬 감사 기록은 보존했다. DGX 현황 조회와 공격 시험은 계속 중단했다.
