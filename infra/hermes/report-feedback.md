# 사건 보고 정정 전달과 종결 일관성

2026-11-06 작업. 30초 목표는 아직 달성하지 못했다. 조사 시작부터 보고 outbox 전송까지 측정하며 원 채팅 접수·대기열·단말 렌더는 포함하지 않는다. 같은 사건을 반복한 개발 검증으로, 독립 평가나 공유 GPU를 통제한 성능 비교가 아니다.

## 변경과 경계

- 기존 근거 검사가 추가한 정정 안내가 간결 보고의 root 문맥 재구성에서 빠질 수 있었다. 실제 검사 코드·이전 모델 문구를 현재 turn과 근거 SHA에 결속해 다음 모델 요청에 전달한다. 이전 문구는 미신뢰 자료다.
- 미해결 보고의 제한된 표현 정정에서는 전체 도구 설명·인자 선택 규격을 반복하지 않는다. 상태·판정을 승격할 수 없고 추가 근거/위험 재판단이 필요하면 전체 등록 읽기 규격과 실제 Native 실행으로 복귀한다. 정상 추가 조회에서는 도구 규격을 유지한다.
- 동일 IP의 임시기한 이후 센서 표본이 있는데 재탐지를 미확인으로 부정하는 표현을 검사한다. 침해 성공·공격 지속·전체 부재와 같은 판단을 코드가 대신하지 않는다. 다른 IP·센서·기한 이전/시간대 불명·인용문은 별도다.
- 실측에서 영향 미확인과 resolved가 함께 나온 실패를 발견했다. 명시적 영향/대응 미확인과 종결의 모순을 Native 재작성·최종 출력·host 사건 저장에서 거절한다. 실제 조회 이력만으로 종결의 정확성을 보장하지 않는다. 기존 잘못 종결된 개발 사건은 Store.review의 명시적 재개방 경로로 이력을 보존해 다시 검토했다.
- 현재 읽기/쓰기·현재 turn/nonce·실제 영수증·보호 주소·정확 승인·TTL·Native 반복/시간 예산은 유지한다. 정정 완료는 위험 해소·새 승인·관제 완료를 뜻하지 않는다.
