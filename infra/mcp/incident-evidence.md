# 복합 사건 읽기 묶음 — 2026-11-06

**MCP 구현과 두 봇·root 검증기 운영 연결을 완료했다. 정확한 최종 보고30초는 미완료다.** 현재query1.19.74·security-events1.3.0·진단1.2.2이며 읽기7도구를 제공한다. [최신 연결·실제 모델 측정](../hermes/incident-bundle.md) · [현재 상태](../../STATUS.md). 아래169검사·읽기만의 실측은 활성화 전 단계 기록이며 [당시 원장](incident-evidence.validation.json)에 보존한다.

## 변경 목적과 범위

기존 복합 조사는 센서 조회→웹 대상 선택→접근 로그·등록 agent 조회 사이에 모델을 여러 번 호출했다. `collect_incident_evidence` 후보는 LLM이 지정한 사건/후속 구간과 진단 대상의 관련 **읽기**를 기존 security-events MCP 안에서 수집한다. 고정 Python 분기로 위험 판단·사건 종결·차단·승인을 대신하지 않는다.

| 조건 | 구현 |
|---|---|
| 입력 | 단일 출발지·정확 KST 구간, 센서 최대8/진단 최대4, 구간24시간·각 표본50행 이하 |
| 수집 | 독립 읽기 최대4개 병렬. 실제 WAF 경로와 고정 서비스 prefix가 겹칠 때 등록 대상/agent를 조회하고 그 구간의 웹·Wazuh 자료 수집 |
| 연결 한계 | prefix 일치는 구성상 후보이며 실제 프런트 목적지나 침해 영향의 증명이 아님. 등록 agent 없이 추정하지 않고 백엔드에 공격자 IP 필터를 복사하지 않음 |
| 근거 | 각 하위 조회의 정확 인자·시작/완료 KST·전체 제한 응답·오류·SHA256 보존. 같은 구간/agent 조회만 중복 제거 |
| 실패 | 일부 오류를0건·정상으로 바꾸지 않음. `execution_complete`는 명시한 읽기의 완료일 뿐 사건 전체 조사·복구 완료가 아님 |
| 상한 | 최대32 하위 조회/128KiB 내용. 실제 JSON escaping까지 포함한 wire 상한도 검사하고 초과는 개별 재조회 필요 오류로 반환; 조용히 잘라내지 않음 |
| 권한 | 기존 읽기 계정·고정 index·고정 A/C 진단/웹 reader만 사용. 입력 host/명령/키/경로·일반 셸·sudo·Docker·쓰기 없음 |

진단의 분당30조회/60감사 한도는 병렬 호출에서도 원자적으로 유지한다. 이벤트만 요청하면 웹·진단 의존성을 불필요하게 초기화하지 않는다. 공유 모듈은 root 소유·비쓰기 부모/파일과 NOFOLLOW·단일 링크를 검증한다.

## 현재 검증

- B의 별도 root 소유 디렉터리에서 기존 `mcp` 계정과 읽기 자격으로 실제 stdio 호출. 첫 후보8조회3.040초, 최종 상한 보완 전8조회3.437초, 다른 IDS 사건7조회3.260초. 모두 조회 오류/쓰기0. 최종 wire 상한 보완 소스8조회는3.149초였다.
- 동일 인자의 개별 handler8조회는 프로세스 포함3.293초였다. 경보/접근 행은 같고 다시 관찰한 현재 시각·보존 시작/age 등이 달랐다. 수집 자체의 속도 우위를 입증한 결과가 아니다. 기대 이점인 **모델 왕복 감소**는 아직 미측정이다.
- 고유169검사: B139(19+30+38+29+23, skip0), 로컬 설치 계약30(19+11). 최초 서버 검사에서 테스트용 배포 스크립트가 빠진1건을 보완해 재검사했다. 새 OS 전체 설치·모델 정확성·채팅·공격 E2E와 구분한다.

## 배포와 복구

security-events1.3.0/진단1.2.2와 query1.19.74/common1.5.33을 함께 반영했다. `INCIDENT_BUNDLE_ENABLED=True`가 현재 소스이며 환경변수·프롬프트로 권한을 바꾸지 않는다. 이 고정 스위치를False로 되돌리는 경우에는 해당 도구의 광고·실행이 모두 사라진다. SDK의 정확7도구 계약과 봇/검증기 전체를 같은 검증본으로 함께 복구해야 한다.

최초 설치 진입점은 루트 `deploy.sh`다. SIEM preflight/해시/복사에 `incident_evidence.py`를 포함하고 내부 B 배포기는 백업·실패 복구·7읽기 계약을 확인한다. 새 deb/wheel/image·포트·키·입력 설정0이며 초기 설치기로 운영 서버를 덮지 않는다.

Native/SDK/root가 실제 wire1회와 내부N읽기를 구분하며, 인자·각 응답SHA·부분 오류·실제 인용·종결 근거를 검증한다. 큰 웹 결과는 원본을 보존한 무손실 모델 표시만 적용한다. 마지막 정확 배포·복구 위치·임시 정리와 Git은 [최신 연결 원장](../hermes/incident-bundle.validation.json)을 따른다. 이전 단계의운영 변경0/임시38·17파일 정리는 당시 기록이며 이번 배포에 대한 수치가 아니다.
