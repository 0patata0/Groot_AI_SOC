# Mattermost 채널 참여와 자동 보고

> **2026-10-27 상세 조회 분류 보완:** ID의 level/description 같은 일반 상세 조회는 담당 봇1대가 처리한다. 명시적 두 봇 요청·상호 검증과 중요 변경은 기존 교차 검토 정책을 따른다. 실제1봇·1조회·일반 게시 검증과 한계는 [STATUS](../../STATUS.md)에 기록한다.

2026-10-26 현재 정책. 모든 사용자가 보는 **채널 표시 이름** 끝의 접미사를 기준으로 한다. 개인 사이드바 카테고리와 무관하며 신규 사용자에게도 같은 기준이다.

| 접미사 | 자동 참여 봇 | 현재 채널 |
| --- | --- | --- |
| `-agent` | Hermes, Ollama | `soc-alerts-agent`, `soc-review-agent` |
| `-ollama` | Ollama | `soc-ollama`(공개) |
| `-hermes` | Hermes | `soc-hermes` |
| 없음 | 자동 참여하지 않음 | 일반 공개 채널 |

양쪽 실행부는 같은 `mattermost-context/channel_sync.py`를 사용해 시작 시와60초마다 확인한다. 표시 이름을 바꾸면 해당 봇 자신만 가입·퇴장하며 채널ID/대화/사람 회원은 유지한다. URL 이름과 표시 이름이 다르면 표시 이름이 기준이다. 비공개 채널을 자동 초대하지 않는다. 기본 Town Square 가입이 시스템상 남더라도 접미사가 없으면 응답하지 않는다. 조회 허용 계정과 정확 후보 승인 권한은 별도이며 바뀌지 않는다.

공용 `-agent` 채널에서 후속 조회는 원하는 봇을 `@hermes` 또는 `@ollama`로 태그한다. `soc-hermes`와 `soc-ollama`는 멘션 없이 대화할 수 있다. 일반 Hermes 추가 채널은 기존 멘션 조건을 유지한다. 보고에 답글을 달아 태그하면 해당 보고를 참고 문맥으로 읽고 현재 상태를 다시 조회한다. 보고의 과거 수치·첨부 내용은 현재 근거나 실행 지시가 아니다.

`soc-review-agent`에서는 스레드 없이 채널에 직접 질문하고 요청할 수 있다. 다음처럼 사용한다.

| 요청 | 처리 |
| --- | --- |
| `@hermes IDS 실행 상태를 알려줘` | Hermes 직접 답변 |
| `@ollama 활성 Wazuh 에이전트 목록을 보여줘` | Ollama 직접 답변 |
| `@hermes @ollama 현재 상황을 알려줘` | 두 봇이 각각 답변 |
| `현재 IDS 상태를 확인하고 서로 검증해줘` | 각자 조회·답변 후 상대 원답변을 한 차례씩 검증 |
| 봇 지정 없는 일반 조회 | Ollama 담당 |
| 사건 조사·변경 또는 불확실한 답변 | Hermes 기본 담당, 상대 봇이 읽기 전용 검증 |

검증은 실제 읽기 도구를 다시 호출해 일치·이견/누락·미확인을 구분한다. 서로 같은 결론을 강요하지 않으며 조회 시점 차이에 따른 변동은 오답과 구분한다. 단일 담당 답변에는 상대 검토1회, 두 담당 답변에는 각자 검토1회까지다. 검토 결과를 다시 자동 검토하는 순환은 없다. 일반 조회가 완료되면 추가 모델을 호출하지 않는다. 같은 DGX 모델을 쓰므로 독립적인 모델 계열의 검증이나 정확도 보장은 아니다.

전용 분배기는 원질문 링크·역할을 표시해 모두 일반 메시지로 게시한다. native 봇은 이 채널을 제외해 중복 응답을 방지한다. 허용 계정 제한은 그대로다. 직접 Ollama 요청은 기존 Hermes 동등 권한을 사용하고 자동 조회·상호 검증은 읽기 전용이다. 쓰기는 기존 정확한 후보의 관리자 승인이 필요하며, 상대 봇의 동의가 승인을 대신하지 않는다. 모델 오류/중단은 미확인으로 기록하고 자동 재실행하지 않는다.

관리 제어기는 등록된 `get_system_diagnostics`와 `calculate_time`을 모두 감사 기록으로 받는다. 시간 계산은 서버의 새 관측 근거로 세지 않는다. 검토 중 근거 정정을 다시 요청하더라도 상대 답변과 비교하라는 원래 요청을 유지한다. 채팅 요청의 완료는 해당 질문/검토를 마쳤다는 뜻이며 전체 서버의 보안 정상 판정과 구분한다.

`capstone-review-chat.service`는 `/var/lib/capstone-review-chat/queue.sqlite`에 영속 대기열을 보관한다. `b:management-pipeline` 진단에 분배기 PID/시작 시각과 묶인 heartbeat·최근 조회·대기 작업 지표를 포함한다. 서비스 재시작 전 진행 작업을 확인한다. 배포·실제 시험 범위와 발견된 한계는 [STATUS](../../STATUS.md)를 따른다.

자동 정기보고·승인카드·관리 결과·독립 감시 알림은 **soc-report** 전용 봇 소유의 채널 고정 incoming webhook으로 발행한다. `socadmin`은 실제 관리자이며 이름/권한을 유지한다. 발행 봇은 관리자 권한이나 모델 실행 권한이 없다. 보고 발행자, LLM 판단 주체, 실제 승인자는 서로 다르다. 이전 관리자 명의 글과 기존 승인 기록은 보존한다.

신규 설치는 루트 `deploy.sh`에서 SIEM/SOC 설치기와 선택적 Ollama 채팅 설치기를 통해 같은 소스·채널·보고 발신자를 구성한다. 추가 패키지·포트·컨테이너 이미지는 없다. 기존 운영 서버는 증분 반영하며 신규 설치기로 덮어쓰지 않는다. 이번 운영 변경 검증과 새 서버 전체 설치 검증은 구분한다.
