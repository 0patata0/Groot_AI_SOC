# 미완료 변경안 준비와 모드 보존

사용자가 룰 주석·설명 등의 변경안 또는 승인안 작성을 요청했는데 모델이 조회만 하고 끝내면, 두 봇은 기존 호출 예산 안에서 모델에 준비를 이어갈 기회를 한 번 준다. 이 안내는 도구를 자동 호출하거나 후보 내용을 대신 생성하지 않는다. 모델이 실제 MCP와 인자를 선택하고, 서버가 현재 원문 해시·편집 기준·전체 후보를 검증한다.

`기존 내용과 모드는 유지하고`는 모드를 바꾸라는 요청이 아니다. 공통 `preparation_gap`은 명시적인 긍정형 유지/보존 구문을 구분한다. `모드를 유지하지 말고 바꿔`, `DetectionOnly를 해제`, `inline으로 전환`, 컨테이너 재구성 및 모드 처리 미정은 이 파일 편집 후속 준비 경로에서 제외한다. 영문 모드명 뒤에 붙은 한글 조사도 인식한다.

`승인안 만들어줘`는 준비 요청이며, `기존 승인안 조회해줘`나 `승인안 만들지 마`는 새 작성 요청이 아니다. 새 승인안 작성과 실제 적용 승인은 별개다. 이전 승인이나 두 봇의 합의로 새 후보의 승인을 대신하지 않는다.

이미 보호 도구를 호출했거나 결과를 확인하지 못한 작업은 이 후속 준비 경로로 재시도하지 않는다. 실행 전 확정된 편집 검증 거절과 결과 불명은 구분하여 기록한다. 전자의 기록 뒤에 실제 별도 후보 제출이 확인되면 두 사실을 함께 표시하며, 이 표시 자체가 재시도를 실행하지는 않는다.

## 정확한 요청 범위와 제출 상태

명시적인 주석 한 줄, 맨 앞/맨 끝(선두/말미), 기존 내용 유지가 모두 주어진 경우 공통 하네스는 원문 전체 SHA와 실제 제출 영수증의 후보 SHA를 대조한다. 요청에 없는 빈 줄·규칙 변경이 섞이면 제출 ID는 보존하면서 **승인 보류·준비 미완료**로 표시한다. 원문 해시나 종료 개행을 검증하지 못해도 일치를 추정하지 않는다. LF/CRLF와 앞/뒤 삽입을 검사하며, 문구·위치가 모호한 일반 편집을 이 제한된 검사로 검증했다고 표시하지 않는다. 이 검사에서 계산한 값은 비교용 해시이며 도구에 후보를 전달하거나 새 제안을 만들지 않는다. 보호 호출 뒤 자동 재시도도 추가하지 않는다.

## MCP 제출 전 편집 인자 검사

두 봇은 `propose_rule_edit`와 `propose_rule_change`를 실제 MCP로 전달하기 전에 같은 공통 검사로 모델 인자를 확인한다. 현재 대화 턴의 마지막 실제 대상 조회, 원문 전체 해시와 `base_sha256`, 편집 문구의 유일한 일치·비중첩, 크기·종료 개행·변경 유무를 검증한다. 위의 명시적 주석 한 줄 요청은 추가로 원문 보존과 삽입 위치를 검사한다. 일반 룰 편집의 의미적 정확성까지 이 검사로 보장하지 않는다.

거절 결과는 `stage=before_mcp`, `executed=false`로 기록한다. 모델에는 오류와 원문 편집 기준만 돌려주며 후보 내용을 대신 작성하거나 인자를 고쳐 제출하지 않는다. 모델은 기존 예산 안에서 인자를 정정할 수 있지만 정정 성공은 보장되지 않는다. 같은 후보의 기존 제출 영수증이나 결과 불명 호출이 있으면 중복 제출을 막는다. 서버의 현재 원문 비교·구문 검사·정확 후보 승인도 그대로 필요하다.

- Ollama는 실제 호출 기록과 `proposal_input_rejections`를 분리한다. 로컬 거절에는 보호 호출 시작 콜백이나 MCP 호출이 발생하지 않는다.
- Hermes 플러그인 1.13.0은 해시로 고정한 native `agent/tool_executor.py`의 기존 pre-tool 경로에 검사를 연결한다. 기존 플러그인의 거절·인자 수정·권한 검사와 native 결과 기록을 유지한다. 대화/턴별 근거를 격리하고 같은 실행 묶음의 동일 대상 중복 제출을 막는다. native 이력의 도구 선택 기록이 실제 MCP 실행 횟수와 같다고 집계하지 않는다.
- 초기 설치기의 Hermes 이미지 호환성 검사에 이 native 파일의 해시를 추가했다. 패키지·모델·포트·키·LLM 권한은 추가하지 않았다. 설치 소스 묶음과 영수증도 함께 갱신한다.

2026-10-30 제출 전 검사 복구점은 `/var/backups/capstone-preproposal-20261030-225501`이다. manifest의 원본 SHA·모드·소유권을 확인해 유휴 상태에서 해당 파일 묶음을 복구하고 기존 봇 프로세스·채팅 연결·관리 timer를 확인한다. 새로 추가한 시험 파일은 manifest에서 이전 파일 부재가 확인되는 경우에만 제거한다. 실제 배포와 검사 결과는 [STATUS.md](../../STATUS.md)를 따른다.

## 반복 오류와 호출 한도 소진

명시적 주석 편집의 후보에서 원문 전체가 보존됐지만 빈 줄이 추가됐거나 주석 위치만 틀린 경우, 검사 결과에 그 사실을 표시한다. 편집 기준이 일치한 경우를 JSON 인코딩이나 서버 원문 매칭 실패로 설명하지 않는다. 모델에는 오류의 근거를 전달하고 후보 작성과 정정은 계속 모델이 담당한다. 일반 편집의 의미적 정답을 생성하는 기능은 아니다.

양쪽 어댑터는 모든 미완료 대상에 대해 같은 편집/후보의 로컬 거절이 연속 3회 확인되면 추가 모델 호출을 중단하고 미완료로 보고한다. 다른 후보는 반복 횟수를 새로 계산하고, 아직 처리하지 않은 다른 대상이나 결과 불명 보호 호출은 제출 성공·안전한 미실행으로 바꾸지 않는다. 거절 이력과 이미 제출된 정상 후보를 보존하며 자동 후보 작성·승인·보호 호출 재시도는 하지 않는다.

Hermes1.14.0은 `agent/turn_finalizer.py` 해시를 추가로 고정한다. native 호출 한도 소진 경로에서도 현재 턴의 검증된 변경안 기록을 먼저 연결해, 추가 요약 모델 호출 없이 같은 내용이 native 종료 처리와 대화 저장 경로로 흐르게 한다. 기존 실패·중단·대기 중 검증 응답·다른 대화 및 비대상 모델은 native 처리를 유지한다. 이 경로의 로컬 기록 표시는 LLM의 조사·판단이나 실제 변경 실행을 대체하지 않는다. 기존 종료 조건과 승인 경계도 유지한다.

이번 복구점은 `/var/backups/capstone-proposal-recovery-20261030-232430`이다. 운영16파일과 소스 묶음·설치 영수증을 함께 갱신했다. 초기 설치기의 native 호환성 검사도 같은 핀을 사용하며 새 패키지·권한·포트·모델은 없다. 정상 종료 검사, native 한도 소진 재생, 설치된 코드 검사, 실제 채팅 시험의 결과는 서로 구분해 [STATUS.md](../../STATUS.md)에 기록한다.

채팅 답변의 `탐지 모드/규칙/설정 유지`는 이벤트 관측 주장과 구분한다. 같은 문장에 `경보 0건` 같은 실제 이벤트 주장이 있으면 별도의 근거가 계속 필요하다. 원래 답변은 시각/JSON 및 실행 주장 검사에 유지한다. 독립 자동조사의 root 관리 gate·승인 정책은 이번 변경 대상이 아니다.

## 검증과 운영 반영

2026-10-30 실제 같은 요청에서 Hermes는 중복된 구분선의 편집 기준을 한 번 거절받은 뒤 정확 후보를 제출했고, Ollama는 조회만 수행하고 제출하지 못했다. 실제 요청/호출을 공통 코드에 재생하여 모드 보존 문구가 후속 준비를 막는 조건을 확인했다. 첫 보완 후 동시 시험에서는 Ollama ReadTimeout과 Hermes의 요청 외 빈 줄 추가가 발생했다. 이후 Ollama 단독 시험은 정확 후보를 제출했지만 답변 근거 검사로 partial이었다. 그 정정 전 모델 원문은 저장되지 않아 탐지 모드 용어 오인의 직접 원인으로 단정하지 않는다. 모든 실패를 분모에 보존하고 후속 보완 뒤 새 대화로 재시험한다. 단일 사례의 성공이나 실패를 전체 쓰기 점수로 바꾸지 않는다.

초기 설치기는 루트 `deploy.sh`의 기존 `harness.py`·`read_contract.py` 복사 경로를 사용한다. 추가 패키지·포트·설정 키·도구 권한은 없다. 운영 B에는 두 봇 공통 소스와 복구용 소스 묶음·설치 영수증을 함께 반영한다. 2026-10-30 복구점은 최초 `/var/backups/capstone-write-e2e-20261030-220224`, 후속 `/var/backups/capstone-write-scope-20261030-222417`이며 manifest의 원본 SHA·모드·소유권에 따라 복구하고 유휴 상태에서 기존 봇 프로세스와 연결·관리 timer를 확인한다.

실제 승인·적용·사후 확인·원복은 정확한 후보 승인 범위에서 별도 수행한다. 이번 구현/격리 검사·실채팅의 완료 범위와 미완료 항목은 [STATUS.md](../../STATUS.md)를 따른다.

### 승인 후 실행·파일 조회의 안내 범위 (2026-10-30 후속)

정확 후보 승인 뒤에는 기존 worker가 검증·적용하므로 별도 적용 요청을 요구하지 않는다. `get_rule_change_target` 결과는 파일 SHA와 실제 반환 runtime 필드의 근거이며 개별 룰 적재·탐지/차단 성공까지 입증하지 않는다. 공통 최종 보고에서 이 오설명을 교정하고 코드 블록 원문은 보존한다. 실제 Ollama 응답 재생과 설치본 양쪽18검사를 통과했으며 해당 후속 안내는 새 실채팅으로 재확인하지 않았다. 후속 복구 원본은 `/var/backups/capstone-proposal-metadata-20261030-234418`, 최초 반복 오류/종료 보완은 `/var/backups/capstone-proposal-recovery-20261030-232430`에 보존한다.
