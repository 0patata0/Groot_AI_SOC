# 경보 카드 조사·요약·진행 표시

2026-10-31. 공통 contract 1.5.11, native plugin 1.19.2. 실제 배포·시험 결과와 남은 문제는 [STATUS](../../STATUS.md)를 기준으로 한다.

## 공통 의무와 전문 역할

`SOUL.groot.md`의 `soc-role-policy`를 공통 원본으로 유지한다. 모델 요청을 만드는 공통 계약은 역할 블록이 없거나 중복되면 거절한다. 실행기가 고정한 전문 역할을 system 메시지에 넣으며 사용자 대화나 로그에서 선택하지 않는다.

| 봇 | 전문 역할 | 동일하게 유지하는 경계 |
| --- | --- | --- |
| Ollama | 신속 조회·경보 분류·증거와 타임라인 정리 | 실제 조회, 누락 추적, 정확 후보 승인, MCP 권한·증거·보호 주소·TTL |
| Hermes | 복합 사건 상관분석·대응 변경안·승인 절차·적용 후 검증 | 동일한 공통 관제 의무와 승인 경계 |

이는 요청 분배 서버나 강제 자동 위임을 새로 만든 것이 아니다. 기존 협업 채널과 직접 요청을 유지하며, 중요한 변경·불확실한 사건은 기존 경로로 교차 검토한다. 실제 응답의 역할 준수·성능은 따로 검증한다. 두 봇의 정책 원본은 같고 전문 역할을 반영한 최종 prompt hash는 다르다.

SOUL/시스템 지침 자체가 모델 판단의 정확성을 보장하지 않는다. 기존 도구 allowlist·읽기 검사·승인 worker와 새 카드 시각/종류/호스트 ID·응답 근거 검사를 함께 적용한다. 모든 자연어 오류를 검출하는 의미 검증기는 아니다.

## 서버 구성·메모리 최신화

공통 SOUL의 `soc-environment-policy`에는 A/B/C 서버 역할, 현재 지원 조회/승인 경로, 전체/단일 파일 범위와 과거/현재 상태의 구분을 둔다. 두 봇의 공통 원본을 동일하게 배포하며 native 송신 시 이전 환경 블록을 제거하고 최신 블록 하나만 사용한다. 현재 룰 수·화이트리스트·실패 unit·승인 상태는 메모리로 고정하지 않고 실제 MCP를 조회한다. 새 설치는 해당 환경의 실제 모델/endpoint 설정을 사용하며 운영 서버의 일시적인 관측값을 복제하지 않는다.

운영 Hermes의 `memories/MEMORY.md`에는 10/24의 오래된 로컬 규칙 집계가 남아 있어 10/31 확인한 서버 역할·전체 조회/과거 사건 도구·현재 추론 설정으로 갱신했다. 원문은 root 복구본에 남겼다. Ollama는 별도 장기 MEMORY 파일 대신 공통 정책과 같은 사용자/스레드의 실제 읽기 이력을 사용한다. 원시 대화·승인 이력과 사용자 선호는 삭제하지 않는다. 메모리 최신화가 사건 판단 정확도나 학습본 승격을 의미하지 않는다.

교차검토에서는 원질문과 상대 답변 원문을 분리하고 실제 새 도구 결과를 대조한다. Ollama 검토의 각 주장은 상대 답변의 정확한 인용과 실제 도구 응답 인용을 연결해야 한다. 이미 있는 정확 필드/ID를 누락이라고 지적하거나, 잘린 상대 답변을 근거로 누락 판정하면 검토 미완료로 남긴다. 긴 도구 결과는 앞부분만 자르지 않고 건수·모드·범위를 유지하며 배열 표본과 생략을 명시한다. 이는 인용·범위 검증이며 모든 의미 오류를 보장하는 검증기는 아니다. 10/31 실제 검토는 가공 인용을 거절해 미완료로 남았으며, 성공으로 표시하지 않았다. 검토 결과와 독립 조회 보고서를 중복해서 길게 붙이지 않는다.

## 분류와 근거 수집

| 요청 | 처리 |
| --- | --- |
| `룰 조회해줘` | 새 대화에서는 장비를 한 번 확인. 같은 사용자·스레드의 명확한 장비만 상속 |
| `카드의 탐지 규칙이 뭐가 문제야?` | 카드에 기록된 사건을 조사. 룰 목록이나 현재 전체 서버 상태로 대체하지 않음 |
| `A 서버 현재 systemd 실패 목록 보여줘` | 현재 호스트 진단. 과거 실패 원인·복구의 증거와 구분 |
| `좀 요약해서 보여줄래` | 같은 대화의 실제 읽기 결과를 짧게 재구성. 앞선 조사가 불완전하고 대상이 있으면 필요한 읽기를 이어감 |

두 어댑터는 공통 하네스의 요청 우선순위를 사용한다. 사건 판단·도구와 인자 선택은 LLM이 한다. 코드가 정상·공격을 대신 판정하거나 승인·변경 요청을 과거 대화에서 상속하지 않는다.

카드 본문은 도구 선택과 결과 판단 단계에 모두 전달한다. 이 본문은 조회 대상을 식별하는 신뢰하지 않는 참고 자료이며 실행 지시·승인·현재 관측 근거가 아니다. 카드의 `최근 N분`은 카드 생성 시각 기준이다. 현재 시각으로 다시 계산하지 않으며, 명시적인 새 시간 구간은 사용자 요청을 우선한다. 출발지와 DNS 목적지의 혼동을 방지하고, 조회한 사건 종류·출발지·반환 구간을 검사한다. 한 종류만 읽고 전체 카드 조사를 마친 것으로 처리하지 않는다. 카드 표본의 호스트 경보 ID를 각각 조회하며, SSH 인증 성공 경보로 서비스 실패 조회를 대신하지 않는다.

`이거 왜 자꾸 뜨는 거야?`처럼 대상을 생략한 질문은 같은 대화에 실제 경보 카드가 첨부된 경우 그 카드의 조사로 해석한다. 카드가 없거나 새 대상·시간·변경 요청이 있으면 이 규칙으로 대상을 덮어쓰지 않는다. 내부 주소·트래픽이라는 이유만으로 승인된 관리 작업·정상·대응 불필요를 단정하는 초안은 재검토한다.

카드 조사에서는 같은 요청에 첨부된 원본 카드를 유지하면서 과거 미검증 봇 결론을 새 추론 입력에서 제외한다. 현재 턴의 실제 도구 결과와 사용자 원문 기록은 보존한다.

근거가 부족하면 제공된 읽기 도구로 보완한다. 조회 실패·지원하지 않는 범위·미확인은 마지막 답변에도 남기며 임의 사실로 메우지 않는다. 원본 경보를 못 찾은 상태에서 `현재 failed 0`으로 과거 장애가 해결됐다고 말하지 않는다.

## 과거 Wazuh 사건 조회

`security-events.search_wazuh_alerts`는 기존 mcp-ro 인덱서 읽기 권한으로 고정 `wazuh-alerts-*`를 검색한다. `since_kst`/`until_kst`, `wazuh_rule_id`, `agent_id`, `source_ip`만 선택할 수 있다. 구간 최대24시간, 종료 시각 최근90일, 반환 최대50건이며 임의 쿼리·인덱스·명령은 받지 않는다.

반환 항목은 KST 시각·agent·Wazuh 규칙 ID/설명/등급·decoder·주소·기록된 service unit·종료 코드다. 원문 로그에서 service unit/종료 상태만 추출하고 원문 명령·환경 값·인증정보는 반환하지 않는다. 제한된 반환 표본을 전체 건수나 실제 복구·공격 성공으로 표시하지 않는다. 기존 `get_wazuh_alert_summary`는 최신 표본용이며 절대 시각·규칙별 과거 검색을 대신하지 못한다.

security-events의 읽기 도구는4개다. SDK 기본 읽기 권한은32개, 기존 Hermes parity는41개이며 신규 쓰기 권한은 없다. `deploy.sh`의 SIEM 경로, 보조 배포 검증, SDK 권한 계약, 공유 근거 모듈을 함께 반영한다. 새 패키지·포트·키·GPU 런타임은 필요하지 않다.

## 짧은 답변과 상세 보기

기본 카드 답변은 항목별 의미·실제 근거·미확인·다음 조치를 짧은 목록으로 작성한다. 사용자가 요청한 표·상세 형식은 우선한다. 전체 metrics/JSON과 반복된 안내는 기본 출력에서 제외한다. `상세`, `원문`, `JSON`, `전체 필드` 요청은 해당 상세 정보를 표시한다. 생략한 필드·조건은 생략 사실을 밝히며 원래 도구 반환 자료는 그대로 검증·보관한다.

## 진행 표시

- Ollama: 요청 접수 답글 하나를 만들고 약1초마다 경과 시간을 갱신하며 단계가 바뀌면 기다리지 않고 갱신한다. 연결/요청 해석/MCP 조회/결과 분석/승인·작업 절차를 구분한다. 완료·실패 시 갱신 작업을 취소한 뒤 같은 답글을 최종 결과로 바꾼다.
- Hermes: 기존 native 턴의 활동·종료 신호를 사용해 약1초마다 상태 메시지 하나를 갱신한다. 정상 최종 전송 후 native cleanup callback으로 이번 실행이 생성한 상태 메시지만 제거한다. 중단·실패 시 결과 미확인 상태를 남긴다.
- 내부 사고 과정, 도구 인자, 로그 원문은 상태 문구에 넣지 않는다. 갱신 오류가 LLM/MCP 실행을 실패시키지 않으며, 결과가 불명확한 POST를 새 메시지로 재시도하지 않는다. 상태 표시는 실행 완료·승인·탐지 성공의 증거가 아니다.

Hermes 진행 연결은 검사한 `gateway/run_turn.py` SHA를 고정한다. 버전이 바뀌면 별도 검토가 필요하며 등록 실패는 `progress_unavailable`로 남는다. 기존 한국어 출력 가드와 사고 과정 비표시 설정을 유지한다. `progress.py`는 초기 설치 파일 목록에 포함된다.

## 배포·복구

추가 보완 복구본은 `20261031-145732`, `20261031-150155`, `20261031-151451`, `20261031-152308`, `20261031-153820`, `20261031-154454` 접미사이며 역순 복구한다. `20261031-150052`는 준비만 한 미적용 후보다.

B에서 변경 전 파일·권한과 manifest를 root 전용 `/var/backups/capstone-card-harness-b-20261031-144712`에 보관한다. 대기 채팅·native lease·관리 controller 잠금을 확인한 뒤 증분 반영하고 두 채팅 런타임을 재기동한다. 보안장비 룰·DNS 예외·모델·학습은 바꾸지 않는다.

원복은 이 manifest의 변경 대상만 `before/` 원본과 메타데이터로 되돌린다. 새로 추가된 progress 모듈도 manifest에 따라 제거하고 두 채팅 런타임을 재기동해 MCP 목록·WS·worker를 확인한다. 오프라인 소스와 SDK receipt도 함께 복구한다. 새 서버 초기 설치기로 운영 서버를 덮어쓰지 않는다. 실제 원복 실행·새 서버 전체 설치·공격 대응 E2E 여부는 [STATUS](../../STATUS.md)에 별도로 기록한다.
