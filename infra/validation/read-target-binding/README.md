# 실제 조회 대상과 범위의 서술 검사 후보

후속 [실제 MCP·모델4요청](../host-journal-model/README.md)은 B의5읽기·12모델완료를 확인했으나 의미 오류·검사 오탐·대상 확인/시각 경계가 남았다. 운영 미적용·실제채팅0이며 아래 당시 관측을 성공으로 덮어쓰지 않는다.

후속 [집계 journal](../host-journal/README.md)과 [파일별 native 후보](../host-journal-cost/README.md)는 R6 위의 별도 미승인 수정이다. 파일별후보는24h A/B/C 실제읽기와CLI전체응답일치·Hermes1137생략0을확인했지만 모델/운영/새채팅은 미검증이다. 아래 R6의 실제 무조회 실패 기록을 성공으로 대체하지 않는다.

[실제 모델 후속 검증](../read-target-live/README.md)에서 짧은 systemd 로그 질문의 **읽기 선택 오류가 남아 운영 후보로 채택하지 않았다.** 2질문×2비교본·4요청/실제7읽기/기록된모델13완료를 확인했다. 조회 없이 만든 로그는 새 검사기가 막았지만 필수 읽기를 수행하지 못했다. 같은 새 초안·읽기0을 재처리하면 부모 검사[]/후보는unobserved_read_success 거절이다. 아래840회귀와 당시 model/read0은 원래 동결 검증 단위이며 후속 실제 요청과 합산하지 않는다.

**격리 회귀를 검증한 후보이며 정본·초기 설치·운영에는 적용하지 않았다.** 부모는 미승인 [짧은 조회 후보](../read-intent-scope/README.md)다. 기존19파일과journal9코드의 정확 승인 계획은 변경하지 않으며 이 패치는 그 승인 범위에 포함되지 않는다.

## 문제와 변경

앞선 실제 SDK 요청에서 모델은 `b:systemd`의 현재 snapshot만 받고도 과거 오류 조회에 실패했다고 설명했다. 실제 도구 이름만 찾는 검사로는 `B systemd`라는 대상명·view·기간의 차이를 잡지 못했다. 현재 조회 성공은 과거 journal을 요청했거나 그 요청이 실패했다는 근거가 아니다.

공통 읽기 시도 원장에 도구·인자·대상·호스트·unit/container·view·기간을 연결하는 투영을 추가했다. 응답과 인자의 target/window가 어긋나면 성공 근거로 인정하지 않고, 입력 거절·미실행·반환 오류·전송 예외도 구분한다. 실제 서비스가 실패한 상태와 그 서비스의 조회 실패는 서로 다른 주장이다. `.service`나 명시 container 이름의 점을 문장 경계로 잘못 자르지 않도록 해당 검사에서만 식별자 범위를 보존한다.

Native와 SDK는 같은 공통 검사기를 사용한다. 기존 soc-investigate의 근거 절에 안내1개를 추가했고 별도 스킬·도구·권한은 만들지 않았다. root dispatch·승인·권한·runtime 예산은 AST 및 소스 해시로 불변을 검사했다. 조건·부정 표현을 실제 단정으로 읽지 않도록 공통 modality도 보완했다.

## 재현

공식 `G_Harness2/`의 고정 버전과 저장소의 부모 커밋이 필요하다. 운영 경로가 아닌 **아직 존재하지 않는 임시 출력 경로**를 지정한다. 새 패키지 설치·네트워크·모델·MCP 호출은 없다.

```sh
python3 -B infra/validation/read-target-binding/reproduce.py --repo "$PWD" --output /private/tmp/사용하지않은-검증경로
SOC_TARGET_ROOT=/private/tmp/사용하지않은-검증경로/candidate python3 -B infra/validation/read-target-binding/test_targets.py
```

재현기는 부모 아티팩트·패치·24소스의 SHA를 대조하고 허용된 정의와 metadata 밖 AST 변경을 거절한다. 정본·운영 소스를 직접 수정하지 않는다. 복구는 운영 원복이 아니라 자체 임시 후보를 버리는 작업이며 최소 패치·원문·검증 원장은 보존한다.

## 남은 검증

사람이 쓰는 모든 자연어 표현을 완전히 검증하는 의미 판독기는 아니다. 실제 응답의 unit 매핑 없이 별칭만 보고 unit을 추정하지 않는다. 최신 snapshot과 등록된25개 서비스의 과거 journal은 별도 기능이며 `b:systemd`에 임의 과거 journal 권한을 추가하지 않는다.

새 모델의 정정 경로와 실제 읽기·Native/양봇 채팅, 조사 표본0을 전체 부재로 바꾸는 문제, 규칙 정의를 개별 SID 실제 적재로 확대하는 문제는 남아 있다. 현재 후보를 다른 미승인 후보와 자동 합치거나 기존 승인으로 배포하지 않는다. 후속은 새 실제 근거·필요한 반례를 검증한 뒤 정확 후보 승인·적용·로드·새 채팅으로 이어간다. [STATUS](../../../STATUS.md)·[PLAN](../../../PLAN.md).
