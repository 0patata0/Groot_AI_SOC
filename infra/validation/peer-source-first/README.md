# 원문 해석 분리·의미 검증기 개발 비교

**아래 후보는 모두 미채택이다.** 실제 원문을 해석하는 단계와 새 근거를 대조하는 단계를 나눠도, 최종 설명에서 조건·권고·실행 주체·표본 범위를 바꾸는 오류가 남았다. 운영 스킬·추론 강도·모델 설정은 바꾸지 않았다. [현황](../../../STATUS.md) · [검증 원장](validation.json) · [합성 입력과 모델 출력](model-results.json).

| 시도 | 실행 범위 | 확인한 결과 | 결정 |
|---|---|---|---|
| 원문 먼저 분류 | 6사례×기존 R2/새 후보, 12리뷰 | 분류가 맞아도 이벤트 건수로 봇 미실행을 확인하거나, 자기 조회 한도를 상대 표본의 근거로 사용 | 기각 |

| 별도 의미 검증기 | 같은 초안13개를 학습본/기본모델에 각1회 | 사전 지정한 잘못된 주장5개 중 각2개 검출, 문장 누락0/1, 정상 통제7/7 수용 | 운영 연결 안 함 |

총56개 논리적 리뷰에 모델 생성76회가 사용됐다. 생성용 입력은21사례를 준비했지만 실제 생성 비교에 사용한 고유 사례는9개다. 검증기13개는 실제 개발 초안10개(정상 포함)와 수동 정상 수정안3개다. **13개를 전부 오류로 세거나 일반 정확도로 환산하지 않는다.** 작성자가 지정한 개발 반례이며 독립 전문가·실사건 최종 평가가 아니다. 미사용176개 평가자료는 사용하지 않았다.

기존의 [15사례 비교](../peer-semantics/README.md)와 분모가 다르다. 실제 모순·승인 우회 권고의 안전성 비판을 유지하는지 함께 확인했으며, 오류를 없애려고 모든 검토를 거절하는 방법은 채택하지 않았다. 모델 검사는 실제 B의 비특권 실행환경→Thor 경로에서 **합성 영수증**으로 수행했다. 실제 MCP·새 채팅·보호 작업·새 학습·공격 송신은0이다.

## 구조·회귀와 의미를 구분

공식 Harness² `6868817518876de8fd170c6a8354daca273b6191`의 `core.tree.validate`·`diff_summary`로25파일·5스킬·18스크립트, 작업자/로더/스킬3개 변경·상시 문구 증가0을 확인했다. 같은 기존105개 회귀와 새 정보 흐름 검사는 Mac 및 B Linux에서 통과했지만 위 의미 오류는 남았다. 구조 통과를 품질 향상으로 표현하지 않는다.

기본모델 검증기는 기존 `soc-qwen36:35b-base-q4km-20261027`, 학습본은 `soc-qwen36:35b-balanced-q4km-20261108`을 사용했다. 모두 Q4_K_M·컨텍스트65536이며 운영 봇의 모델 설정은 유지했다. 공유 GPU·캐시·실행 순서를 통제하지 않았으므로 지연 수치는 인과 비교나 SLA가 아니다. 원문 추론 내용은 수집하지 않고 생성 토큰·시간 수치만 보존했다.

패치는 운영 사본에 적용하지 않는다. 별도 검증 체크아웃에서 작업자는 `dfc3e2a` 부모의 `1cff48cc…`, 로더·스킬은 원장에 명시한 기준 바이트를 사용한다. `git apply --unidiff-zero`로 복원한 세 파일의 SHA가 각 후보와 일치함을 검증했다. 기준이 다른 현재 코드에 무조건 적용하면 안 된다.

검증기는 격리 경로에 `workflow-probe.py`와 `skill-soc-investigate.md`를 준비해 사용한다. `semantic-policy.patch`의 스킬/로더 결과를 이 이름으로 배치하고, `probe-inputs.json` 및 빈 `out/`을 둔다. B의 기존 런타임·읽기 전용 설정을 사용하며 새 패키지·자격 복사는 없다. 전체 동결 소스 SHA·원래 실행기·회귀 로그·출력 원문은 Git 제외 로컬 검증 기록에 보존한다.

별도 진단에서 **Hermes 완료 읽기 근거가 전달 단계에서 사라지는 문제**를 확인했다. [읽기 감사 보존 수정안](../native-read-audit/README.md)은 위 의미 후보와 별개이며, 이것만으로 교차 검토의 정확도 문제가 해결됐다고 하지 않는다.
