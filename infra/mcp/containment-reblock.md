# 해제 뒤 새 공격의 재차단 — 2026-11-03

관리자가 임시차단을 일찍 해제했는데도 원래 10분 기한까지 새 차단·카드가 막히던 문제를 수정했다. [현재 상태](../../STATUS.md) · [승인·시간 정책](approved-operations.md).

## 확인한 두 원인

실제 A 기록에서 `192.168.16.233`은 14:26:37 KST에 차단되고 14:26:43에 해제됐으나, `cooldown_until`은 원래 기한 14:36:37에 60초를 더한 14:37:37이었다. 당시 2분 뒤 재시험도 이 대기 구간에 해당한다.

대기 종료 뒤의 SQLi는 별도 문제였다. A의 신뢰된 WAF 현재 세대에서 CRS `942100`과 실제 `Enabled`/403 거래를 확인했다. Suricata의 취약 경로 알림 `1000010`은 공격 차단 근거에서 제외된 룰이며, SQLi의 WAF 탐지를 대신하지 않는다. B의 자동 조사에서는 WAF 공격을 읽고도 실습 여부·Native IDS 확인 이후 요청하겠다고 보고하며 `temporarily_contain_ip`를 호출하지 않았다. 조회 성공, WAF 요청 거부, FW IP 차단, 승인 카드 게시를 구분한다.

## 적용 동작

| 상황 | 기준 |
|---|---|
| 최초 임시차단 | 기존 600초 절대 만료 |
| 유지 승인 | 기존 승인 결정 시점부터 3,600초 |
| 승인된 조기 해제 | 소유권 결속 삭제와 커널 부재 확인 뒤 `closed_at` 기록, 해당 시각부터 60초 대기 |
| 자연 만료 | 원래 절대 기한부터 60초, worker가 늦게 관측해도 대기를 늘리지 않음 |
| 새 차단 | 대기 종료와 이전 차단 종료 이후의 새 적격 공격 근거가 모두 필요 |
| 반복·과거 경보 | 기존 TTL 연장·새 카드 발행 근거로 재사용하지 않음 |
| 해제 시각이 없는 과거 기록 | 파일 mtime이나 빈 집합으로 추정하지 않고 기존 기한 적용 |

원래 승인 계획·해시·`owned_deadline`은 바꾸지 않는다. 카드의 해제와 별도 승인된 Response MCP의 해제가 같은 종료 기록 함수를 사용한다. root 소유의 기존 기록 3건은 실제 `agent_block` 삭제 감사의 UID·logger/worker/syslog 출처·IP·요청 ID·시각을 검증하고 이전 바이트와 감사 좌표를 백업한 뒤 종료 메타데이터만 보완했다. 한 건은 journald의 실행 파일 필드가 없어 root UID·logger comm·syslog transport·rule-change-worker unit을 확인했다. 소수 초 감사시각은 올림하여 대기를 짧게 만들지 않았다.

증거 선별은 신뢰된 원본 reader·보호 주소·승인·소유권 검사를 유지한다. 같은 TCP 흐름의 최신 시그니처별 관찰을 보존하되 독립 흐름 수는 중복 계산하지 않는다. 이전 IDS 공격이 아직 5분 창에 있어도 새 WAF 거래를 가리지 않도록 **종료 이후 필터를 센서 선택 전에** 적용한다. 실제 판단과 호출은 LLM이 맡으며, 일반 WAF 사건을 고정 분기 차단으로 바꾸지 않는다.

자동 조사 지침은 WAF와 Suricata를 대체 근거로 명시하고, LLM이 현재 공격으로 판단했을 때 이 실행에서 기존 제한 MCP를 사용하도록 보완했다. WAF 사건에 Native IDS severity-1을 추가 요구하거나 실습 확인을 기다리는 것은 지정된 절차가 아니다. 거절·cooldown은 실제 차단으로 보고하지 않으며, 거절된 요청을 같은 실행에서 반복하지 않는다.

이 검증은 조기 해제 후 새 SQLi→LLM/MCP→FW/새 카드 경로의 성공이다. 첫 별도 LLM 시험은 임시차단을 첫 도구로 선택했으나 수정 전 세 번째 기록의 대기로 거절됐고, 도구 인자 오류·거절 뒤 재시도와 시간초과도 관측했다. 세 번째 기록 보완 후 별도 r2는 실제 운영이 만든 요청을 중복 반환받았으며 자체 새 카드 생성으로 합산하지 않는다. 별도 r1/r2의 최종 조사는 `outcome_unknown`으로 종료됐다. 추가 r3/r4는 엄격한 최신 WAF 입력 요건을 만족하지 못해 모델 실행 전 종료됐으며 모델 실패로 채점하지 않는다. 이후 Kali SSH 재시험 한 건은 이미 IP 차단된 상태에서 timeout이어서 새 SQLi 실행으로 표시하지 않는다. 별도 시험과 달리 위 새 카드의 실제 발신은 운영 Hermes run `01d36f34…`의 첫 MCP 성공으로 확인했다.
