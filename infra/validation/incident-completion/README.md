## 후보가 바꾸는 것

- 기존 meta 저장소에 사건별 완료 요건을 결속하고 같은 사건의 후속 세션에서 낮추지 않는다. 새 테이블·MCP·쓰기 권한은 만들지 않는다.
- root가 전달한 완료 요건만 Native 실행에 적용한다. 채팅이나 도구 본문의 환경변수 문자열은 요건을 켜거나 끄지 못한다.
- 사건을 resolved로 끝내려면 모델의 판단 줄과 이번 실행의 실제 성공 도구 인용이 필요하다. 단순 조회·진행 중·승인 대기는 종결과 구분한다. 실제 읽기·승인 우선순위와 비공개 원문을 보존하고 거절된 종결 주장은 공개하지 않는다.
- 안내는 기존 `soc-investigate`의 사건 조사 완료 절을 재사용한다. 판단을 benign/remediated로 자동 선택하거나 기존 정정 횟수·도구 범위를 늘리지 않는다.
- SDK의 일반 Wazuh/OS 조사도 판단 형식을 확인한다. 교차 검토의 `text`는 스키마에서 최소1자,실행 시 공백만 있는 문장·개행을 거절한다. 의미 일치 여부는 모델 판단으로 남는다.

## 모델 시험에서 확인한 한계

현재 B→Thor 경로의 `soc-qwen36:35b-balanced-q4km-20261108`을 reasoning=true·num_predict=6144로 두 번 호출했다. [합성 입력·정정 안내·출력](model-probe-results.json)을 보존했다. Native wrapper가 만든 정정 안내를 실제 모델에 전달했으나 Native CLI·MCP 실행이나 Mattermost 왕복은 아니다. reasoning 내용은 저장하지 않았다.

첫 답변은 표본0건을 전체 정상으로 바꾸지 않고 monitor를 골랐지만 필수 basis를 빼 JSON 계약을 통과하지 못했다(88.613초). 둘째는6144토큰이 생각 과정에 쓰여 최종 본문이 비었다(94.382초,done_reason=length). 첫 행의 completion_error=null은 resolved를 요구하지 않는 진행 상태여서 종결 검사 대상이 아니라는 뜻이며 유효한 판단 보고서라는 뜻이 아니다. 두 출력 모두 일반 정확도·실채팅 지연 수치나 운영 개선 성공으로 쓰지 않는다.

다음은 공통 스킬에서 필수 판단 필드·근거 길이/실제 인용·상태 관계를 빠짐없이 안내하는 보완과,기존 판단을 바꾸지 않는 형식 정정에서 생각 토큰을 쓰는 범위의 분리 검토다. 모델 판단이 필요한 단계의 추론을 단순히 끄거나 토큰/재시도를 늘려 해결한 것으로 표시하지 않는다. 이번에는 다음 후보를 만들지 않았으며 모델 시험 중 동결 소스도 바꾸지 않았다.

## 재현·검사와 실패 기록

[후보 patch](candidate.patch)는 Git `fc27843c6ac2cc45df1e4350a1b2f5cb56362eaa` 기준12파일이며,같은 기준의 [대조군 테스트 유지보수 patch](baseline-test-maintenance.patch)는3파일이다. **서로 별도 기준 사본에 적용**한다. `git apply --unidiff-zero`로 복원해 각각12/3파일 SHA 일치를 확인했다. 운영 소스에 바로 적용하는 파일이 아니다.

대조군 fixture 변경은 빠진 가짜 API/정확한 bool 반환과 이미 구현된 literal 정정2회 상한의 기대값을 맞춘 것이다. 세 번째 정정 거절을 계속 검사하며 production 재시도 제한은 바꾸지 않았다. Mac/B 검사에서 두 실패는 격리 파일 대신 설치된 오래된 harness를 읽은 테스트 경로 문제였고,정확한 동결 파일을 직접 import해 재검사했다. 가짜 MCP 전송이 full wire 이름을 넘긴 오류도 bare 이름으로 고쳤으며 권한 검사를 완화하지 않았다. 최초 실패 로그와 최종 결과는 로컬 검증 기록에 보존했다.

배포용 controller를 미리 렌더링할 때 정본과 다른 추가 zlib import도 발견했다. 최초 엄격 비교에서 중단한 뒤 해당 import와 기존 command의 UID/컨테이너/profile을 보존하고 검토한4개 정의만 교체했다. 같은 root측 runner SHA가 내장됨과 평상시/사건 명령의 차이가 완료 플래그 한 항목임을 확인했다. 71,866바이트 gate 인자는 기존98,304바이트 제한 안이다. **렌더링 준비일 뿐 운영 적용·설치 사본 갱신은 아니다.**

## 운영 적용·복구 경계

운영은17개 코드/스킬 사본과2개 영수증을 읽기 대조만 했다. canonical 작업자에 이미 있는 [식별자 제거](../peer-ids/README.md)와 [읽기 감사 보존](../native-read-audit/README.md)도 아직 운영 미적용이다. 이후 전체 파일을 배포한다면 이 변경을 포함한 정확한 묶음으로 승인받고,현재 SHA·큐·실행 여부 재확인,원본 백업·독립 원복 타이머·필요 서비스의 유휴 재시작·새 실제 채팅·확정을 준비해야 한다. 이번에는 모델 정정 실패가 남아 적용 승인을 요청하지 않았다. 배포/원복 실행기도 운영에서 실행하지 않았다.

[과거 근거 종류/수치 후보](../peer-proof-kinds/README.md)는 계속 보류이며 이 patch에 섞지 않았다. 실제 공격·새 학습·새 MCP·채팅 게시·서비스 재시작·운영 파일/DB 변경은0이다. 새 패키지 설치0,기존 실행환경/G_Harness2/데이터/가중치/운영 복구본을 보존한다.
