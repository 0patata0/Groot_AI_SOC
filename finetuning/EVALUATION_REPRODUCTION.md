# 저장 어댑터 평가 재현과 추론 복구

본 학습 재개 전 진단이다. 기존 원본 모델·기준 어댑터·R7 어댑터·자료를 보존하고, optimizer 업데이트·후보 등록·운영 모델 교체는 수행하지 않는다. 최신 실행 결과는 [STATUS](../STATUS.md)와 [실행 원장](V5_EXECUTION_RESULTS.json)을 따른다.

`reproduce_evaluation.py`는 기존 고정 이미지/환경에서 원래 8개 검증 사례를 다시 준비한다. 원시 토큰 행은 `array.array`를 포함하므로 정수 목록으로 정규화해 해시를 계산한다. 모델 입력은 학습과 같은 `train.collate_lists`로 만든다. 원시 행에 attention mask나 labels가 이미 있다는 가정을 하지 않는다.

먼저 GPU를 노출하지 않은 컨테이너에서 `--prepare-only --output <새 경로>`를 실행한다. 토크나이저·원시 입력·실제 모델 입력 해시, 표본 수, CUDA 미초기화를 확인한다. 실패 단계와 원인을 원자적으로 기록하며 기존 결과 경로는 덮어쓰지 않는다. 모델·패키지 다운로드는 하지 않는다.

GPU 진단은 같은 BF16/SDPA 모델에 저장된 두 어댑터를 번갈아 적용한다. 현재 연산 설정과 결정적 연산 설정에서 각각 두 번씩, 총 8회 평가한다. `torch.no_grad()`와 BF16 autocast, 동일 singleton collator를 사용하고 개별 사례 손실을 기록한다. 결정적 모드는 cuBLAS workspace `:4096:8`, `torch.use_deterministic_algorithms(True)`, cuDNN deterministic, TF32 비활성화를 사용한다. 미지원 연산은 실패로 남긴다. 이 시험이 역전파·optimizer 재현성이나 품질 개선을 증명하지는 않는다.

운영자는 별도 root 소유·SHA 고정 제어기, 6분 평가 제한, 8분 독립 복구 타이머와 최대 6분 복구 서비스 제한을 먼저 확인한다. 기존 공유 Ollama 중단 승인 범위와 누적 시간을 확인한 뒤 실행한다. 이 제어기는 봇 MCP 권한으로 제공하지 않는다. 최초 실패와 이후 재시험은 별도 컨테이너·상태·출력 경로를 사용한다.

`training_window.py`의 복구 확인은 원래 모델 digest를 대조하고, 이미 올라온 모델의 context 길이를 유지한 실제 1토큰 생성으로 응답 가능 여부를 확인한다. `stream:false`이며 서비스 active/상주만으로 성공 처리하지 않는다. 최대 3회·총 180초 안에서 대기열/통신 시간 초과를 기록하고 재검사한다. 실패하면 독립 복구 타이머를 성공 처리로 지우지 않는다. 복구 실패 영수증 뒤에 수동으로 응답을 확인한 경우 별도 후속 영수증으로 구분한다.

기존 실행 당시의 root 복사본과 입력 동결 파일은 이력이다. 수정된 복구 소스를 다음 본 학습에 사용할 때에는 새 실행 ID·검토된 root 복사본·새 SHA 및 누적 시간 계산을 준비해야 한다. 과거 손실 기준을 임의로 완화하지 않는다.


`train.py`의 `deterministic_training:true`는 명시적으로 선택하는 별도 수치 연산 프로필이다. CUDA 할당 전에 workspace와 결정적 알고리즘·cuDNN·TF32 설정을 적용하고 실제 값을 manifest에 기록한다. 기존 기본 프로필은 자동으로 바꾸지 않는다. `reproduce_training.py`는 원래 최장 2입력/2-step/seed/학습률/재계산 설정을 그대로 복사해 이 옵션과 새 출력 경로만 바꾸며, 독립 프로세스 2개에서 순차 실행한다. 두 결과의 step2 완료, 유한 가중치, 모든 adapter tensor와 train/eval loss 일치를 검사한다. 8분 실행 제한·10분 독립 복구를 갖는 별도 검토 창에서 시험했다. 이 프로필은 속도가 달라질 수 있으므로 본 학습 시간을 다시 산정해야 한다.

V5 smoke 동등성 검사도 참조/후보의 수치 연산 프로필이 다르면 손실 비교를 거절한다. strict 프로필은 실제 설정 영수증까지 요구한다. 예전 reference loss 허용치를 넓히거나, 새 프로필의 낮은 손실을 운영 관제 정확도 향상으로 간주하지 않는다. 다음 본 학습은 검증된 동일 프로필 참조·새 입력 동결·원래 모델 복구·누적 중단 한도를 모두 충족해야 한다.
