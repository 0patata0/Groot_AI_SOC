# DGX 학습 · Thor 추론 운영 계획

2026-10-31 사용자 결정. 앞으로의 GPU 학습은 새로 SSH 접속을 확인한 DGX Spark에서 수행하고, 검증한 추론용 가중치를 Thor에 반입해 운용한다. 이전의 Thor 학습·추론 겸용 및 DGX 일반 모델 추론 분산안보다 이 방침을 우선한다. **현재는 접속·기초 환경 확인과 계획 반영 단계이며 학습 환경 구축·새 학습·가중치 전송·운영 모델 교체는 미실시**다. [현재 상태](../STATUS.md).

## 역할

| 위치 | 역할 |
| --- | --- |
| 로컬 작업 폴더·Codex | 출처 검수·정제 로직·학습 설정·평가·실행 제어와 결과 검토. GPU 학습 연산은 원격 실행 |
| DGX Spark | 검수 자료와 고정 base 준비, 시험/본 학습, adapter 보존, 병합·추론용 변환 및 산출물 검증 |
| Jetson Thor | 검증한 후보 파일을 별도 모델로 등록·평가한 뒤 선택한 가중치로 추론. 이후 새 학습의 기본 실행 대상에서 제외 |
| B 관제 서버 | Hermes/Ollama 봇·Mattermost·MCP·승인 실행 경로 유지. 학습 장소 변경을 봇 이동·권한 확대로 해석하지 않음 |

현재 두 봇의 Thor 원본 `qwen3.6:35b` 연결은 유지한다. 이번 결정이 학습본의 품질 합격이나 자동 운영 승격을 의미하지 않는다. DGX에서 기존에 제공하던 추론 서비스·다른 사용자 작업도 이번에 변경하지 않았다.

## 실제 접속·환경 확인

2026-10-31 15:54 KST, 자격파일의 새 DGX 구역을 직접 참조해 기존 known_hosts 검증을 유지한 SSH 읽기 전용 조회를 수행했다. 주소·계정·비밀번호는 이 문서와 Git에 복사하지 않는다.

이번에는 sudo 권한 변경, 그룹 추가, 패키지 설치, 이미지 pull, 모델 다운로드, GPU 학습/생성, 서비스 중지·재시작을 하지 않았다. SSH 성공과 GB10 관측을 기존 Thor 학습 환경의 DGX 호환 검증으로 대신하지 않는다.

## 다음 학습의 실행 순서

1. **DGX 환경 준비:** 관리 실행 경로와 공유 자원 사용 범위를 확인하고 기존 환경을 조사한다. 승인된 ARM64/CUDA/PyTorch 조합을 별도 환경으로 준비한 뒤 GPU 인식·필요 연산·짧은 forward/backward를 검증한다. Thor용 컨테이너·드라이버·메모리 제한·추론 중단 실행기를 그대로 실행하지 않는다.
2. **자료·base 고정:** 출처·이용 범위·정답 근거·중복/분할·토큰·마스크 검증을 통과한 자료만 선별한다. base revision·tokenizer·설정·입력 파일 SHA와 코드/환경 버전을 실행 원장에 고정한다. 기존 Thor 자료는 원본을 보존하고 필요한 검증 파일만 서버 간 전송한다. 새 자체 작성 문항은 기관 원자료와 구분한다.
3. **독립 학습 실행:** 새 run ID로 작은 시험 후 본 학습을 수행한다. SSH 연결이 끊겨도 유지되는 실행·시간/자원 상한·중단/완료 기록을 DGX에 둔다. Thor 추론 중단은 학습의 전제조건으로 두지 않는다. DGX 자원 확보를 이유로 기존 다른 서비스나 사용자의 작업을 임의 종료하지 않는다.
4. **가중치 산출·검증:** adapter와 학습 원장을 보존하고 정확히 일치하는 base에 병합한다. 현재 프로젝트의 검증된 HF→GGUF/Q4_K_M 경로를 후보로 삼되 DGX 실행 호환성을 먼저 검사한다. tensor 구조/유한값·필수 구성·tokenizer/템플릿·양자화·파일 SHA를 확인한다. adapter 파일 하나가 곧바로 독립 실행 가능한 전체 모델인 것으로 취급하지 않는다.
5. **Thor 후보 적재:** 모델 파일·필요 구성/템플릿·manifest·검증 기록을 서버 간 전송하고 양쪽 SHA를 대조한다. 별도 후보 이름으로 등록하고 기존 모델과 설정을 보존한다. Mac에 가중치·패키지 사본을 남기지 않는다. `Capstone_Groot_training`의 기존 자료·어댑터를 이동/삭제하지 않는다.
6. **평가·운영 선택:** 동일 하네스·MCP 권한·독립 질문으로 원본/학습본을 비교한다. 짧은 요청, 장비 범위, 전체/커스텀·상관 규칙, 사건 판단, KST, 중요 누락, 승인형 쓰기·사후 확인과 지연을 평가한다. 그 뒤에만 복구 가능한 하네스 축소를 별도로 비교한다. 기존 원본보다 나아진 근거가 있는 구성을 선택하고 정확한 모델명·어댑터 제한·초기 설치 설정을 함께 반영한다.

예정 DGX 작업 루트는 `~/Capstone_Groot_training/`이며 아직 생성하지 않았다. 구체 run 폴더·사용량·실행시간은 환경 준비와 시험 실측 뒤 확정한다. Thor의 기존 학습 산출물은 과거 재현·복구 자료로 보존한다.

## 기존 소스의 적용 범위

- [고정 base 설정](config.qwen36-thor.json), [병합](merge_streaming.py), [변환](convert_soc.py), [기존 Thor 실행 기록](THOR_35B.md)은 재사용 검토 대상이다. 파일명이 Thor인 기존 실행기의 검증 이력은 유지하며 실제 DGX 실행 전 별도 구성·경로·자원/복구 검사를 마련한다.
- 새 서버 학습 환경은 기존 `deploy.sh` 진입점과 연결할 구체 변경을 준비할 때 설치 소스·설정 예제·오프라인 반입 목록을 함께 갱신한다. 현재 계획 확정만으로 미검증 DGX 설치 기능을 추가하거나 기존 초기 설치기로 운영 서버를 덮어쓰지 않는다.
- 실제 서버·서비스·이미지·포트·키·모델 연결은 이번에 변경하지 않았으므로 운영 설치 경로의 변경도 없다. [이전 추론 분산 검토의 현재 위치](../infra/hermes/dual-inference-plan.md)를 함께 확인한다.
