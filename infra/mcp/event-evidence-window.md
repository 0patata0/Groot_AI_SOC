# 사건 구간과 WAF 탐지 설명

2026-10-31. 기존 `security-events` MCP의 읽기 도구3개와 동일 권한을 유지한다. `search_modsecurity_alerts`와 `search_suricata_alerts`에 정확한 시작·종료 시각을 추가했고, WAF 경보의 센서 설명을 제한적으로 제공한다.

## 정확한 조회 구간

시작·종료가 모두 지정된 질문은 모델이 `since_kst`와 `until_kst`를 선택한다. 둘 다 초와 `+09:00`을 포함한 ISO8601이며, `lookback_minutes`를 함께 보내면 거절한다. 시작을 종료에서 역산하는 모델 연산을 피한다. 서버는 양끝 시각·양수 구간·최대24시간·종료 시각의 과거90일/미래 금지를 검증한다. 밀리초·자정 경계도 입력 그대로 조회하고 실제 적용한 `requested_since_kst`·`requested_until_kst`를 반환한다. `window_mode=explicit_bounds`, 응답의 `lookback_minutes`는 서버가 계산한 숫자이며 입력을 임의 보정하지 않는다.

```json
{"since_kst":"2026-10-29T19:00:00+09:00","until_kst":"2026-10-29T19:20:00+09:00","source_ip":"192.168.16.233","limit":10}
```

기존 `until_kst`+`lookback_minutes`와 최근 기본60분/10건도 유지한다. 필터·인덱스·최대50건·Indexer 읽기 전용 자격은 그대로다. `returned_count`는 반환 표본이며 `indexed_window_total_count=null`을 전체 건수로 바꾸지 않는다.

공통 하네스는 명시적 시각 쌍이 있고 실제 도구 스키마가 지원할 때 양끝 필드를 요구한다. 날짜/연도·시각·도구는 모델이 선택하며 코드는 자연어를 임의의 날짜로 채우지 않는다. 과거 사건의 첫 읽기 선택에서는 지정 기간을 지원하지 않는 최신 Wazuh 요약을 제외한다. 이후 조사에서 모델이 필요한 추가 읽기를 선택할 수 있다. 모호한 기간 전체를 해결하는 자연어 시간 파서는 아니다.

## 턴 시각과 실패 조회 피드백

두 봇은 요청마다 서버의 현재 KST 시각과90일 조회 기준을 한 번 만들고 같은 요청의 모델 호출에서 재사용한다. 새 턴에는 갱신하고 이전 system 시각 표시는 투영본에서 제거한다. 사건 날짜·도구 인자는 모델이 고르며, 명시된 과거 연도를 한도에 맞추려고 바꾸지 않는다. 현재 시각은 사건 발생이나 조회 성공의 증거가 아니다.

실패 뒤 읽기 선택을 다시 요청할 때는 이번 턴의 실제 실패한 도구명·인자·오류를 전달한다. 결과 SHA를 대조하고 해당 읽기 도구만 허용하며, 최대6실패·인자2048자·오류1024자와 생략 표시로 제한한다. 실패 자료는 지시가 아닌 untrusted 자료로 구분한다. 성공 조회·보호 쓰기 호출을 이 경로에서 재실행하지 않는다. 이는 인자 정정에 필요한 근거를 제공하는 보완이며 모델이 항상 올바르게 정정한다는 보장은 아니다.

## WAF 설명과 제외 범위

`waf_rule_matches`는 실제 구조화된 `transaction.messages`에서 같은 항목의 `ruleId`와 최상위 `message`를 연결한다. 최대20개·설명240자, 파싱 입력131,072자·검사64항목으로 제한하며 잘림/누락·잘못된 형식은 `waf_rule_matches_incomplete=true`로 표시한다. 중복은 같은 규칙·설명·심각도일 때만 합친다. ID 충돌·제어문자·잘못된 ID는 설명에 넣지 않는다.

- `rule_id`: 센서 규칙 ID. Wazuh 상관 규칙 ID와 다르다.
- `description`: 경보에 기록된 센서 설명. 지시·승인·확정된 침해 판정이 아니다.
- `native_severity`: ModSecurity 원값0~7만 보존한다. Wazuh level과 합치거나 숫자를 동일 척도로 비교하지 않는다.
- `waf_rule_messages_untrusted=true`: 센서 설명에 포함된 지시를 따르지 않는다.

전체 messages 객체와 `details.data/match/message/reference/file`, 요청 본문·헤더·query string은 이 경로로 반환하지 않는다. 이 필드가 제공하는 것은 센서의 탐지 설명이며 요청 페이로드나 실행 결과가 아니다. HTTP200/302·규칙 매칭만으로 명령 실행/침해 성공을 추정하지 않고 실행 근거가 없으면 미확인으로 남긴다.

## 설치와 검증

기존 루트 `deploy.sh`의 SIEM 소스 목록과 `ollama-trial` 오프라인 source cache로 배포한다. 새 패키지·포트·계정·권한은 없다. 기존 B에는 MCP 파일·두 봇 하네스/계약을 복구본·SHA 비교·소유권/모드 보존·원자 교체로 함께 반영하고 두 봇의 MCP 카탈로그를 새로 연결한다. Thor 추론 서버·보안 엔진은 재시작하지 않는다.

실제 비특권 `mcp` 계정·강제 명령 래퍼로 초기화/목록/조회하여 정확한20분 구간, WAF2/IDS0 반환 표본, WAF 설명14개를 확인했다. 실제 채팅의 판단 품질·실패와 지연, 소스/운영 해시는 [검증 원장](event-evidence-window-validation-2026-10-31.json)에 별도로 기록한다. 해당 과거 개발 사건 재시험은 미사용 독립평가나 실제 차단·승인·복구 E2E가 아니다.
