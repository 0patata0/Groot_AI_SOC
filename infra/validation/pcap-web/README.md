## 확인한 문제와 다음 순서

1. SID 1000002는 설명과 달리 404·서로 다른 경로를 확인하지 않고 임의 URI 40회/10초를 센다. 이번 정상 반복 조회도 경보가 됐다. 실제 공격 룰의 정상 대조군을 추가하고 승인 경계 안에서 수정해야 한다. 이번에 룰을 바꾸지는 않았다.
2. 232 재생의 SSH는 결과 없이 255로 끝났고 18:13 KST에는 관리자와 두 Kali 모두 TCP22가 timeout이었다. 접속 복구 후 기존 `expanded-results.jsonl`·`expanded-summary.json` 및 실행 프로세스를 먼저 확인한다. 결과 미회수를 실패 21건이나 성공 21건으로 합산하거나 같은 실행 ID로 중복 실행하지 않는다.
3. FW의 실제 DROP → Wazuh 100128/100129·정규화 자료·LLM 조사까지 연결하고 누락을 구분한다. WAF/IDS 경보 관측으로 이 검증을 대신하지 않는다.
4. 정상 308은 리다이렉트 응답만 확인했다. 후속 Log4Shell 앱 응답이나 정상 요청에 대한 LLM 개별 판정으로 집계하지 않는다. 차단 중 후속 요청 실패와 정상 오분류를 분리한다.

## 보존한 실행 소스

이 폴더의 Python 6개는 이번 Kali233 실험에 사용한 코드 원문이며 SHA를 원장에 고정했다. 새로운 서비스·설치기·MCP 도구가 아니다. 기존 Kali의 Python 표준 라이브러리와 tshark를 사용하며 Mac 설치는 없다.

| 파일 | 실행 역할 |
|---|---|
| `scan_http.py` | 전체 PCAP의 재조립 HTTP 후보 검사, 파일별 SHA·진행/결과 기록 |
| `scan_packets.py` | Ethernet/IPv4/TCP 단일 패킷의 후보 선별 보조. 재조립·전체 프로토콜 분석을 대체하지 않음 |
| `select_cases.py` | 검토 기준으로 21개의 비파괴 GET 변형 선별. 후보가 곧 정답은 아님 |
| `replay_mixed.py` | 정상 97·선정 3 요청 시도·연결/전송/응답 분리 기록 |
| `replay_variants.py` | 별도 21변형 시험 ID·결과 기록 |
| `probe_fw.py` | 고정 A의 제한 포트 24개를 1.1초 간격으로 검사 |

경로와 실행 ID는 이번 증거를 재현하기 위해 고정되어 있으며 이미 존재하는 실행 결과/manifest에는 재생을 거절한다. 재시험은 새 실행 ID/디렉터리와 승인된 출발지·표적을 정하고 소스/manifest SHA를 새로 남긴다. 현재 운용 결과를 초기화하거나 네트워크에서 PCAP의 원래 목적지로 보내지 않는다. 232에서는 전달받은 PCAP의 SHA·프레임·페이로드 SHA를 직접 확인해 별도 manifest를 구성했다.

232는 과거 C의 주소가 아닌 새 Kali다. 16:38 커널 `never_block`의 해당 원소와 영구 FW 파일을 함께 제거하고 16:40 확정했다. [관리 경로·복구](../../groot-a/fw-v2/README.md). 두 Kali SSH는 사용자 지시로 직결하며 A/B/C 설정 변경은 관리자 호스트를 경유한다. 이 예외 제거 자체가 232의 실제 공격→FW 차단 검증 성공은 아니다.
