# SOC 변경·승인·원복
SOC_WORKFLOW_CHANGE_V1

LLM이 근거 조사·변경안 준비·승인 요청·실행 후 확인을 주도한다. 실제 변경 가능 범위와 관리자 승인·보호 주소·기한은 SOUL 및 현재 MCP/worker 검증을 따른다. 이 스킬은 권한이나 승인을 부여하지 않는다.

- 목표·대상·현재 상태/파일 SHA와 필요한 근거를 먼저 확인한다. 사용자가 조회만 요청했으면 변경 제안을 제출하지 않는다. 대상이나 의도가 불명확하면 필요한 사항을 한 번 확인한다.
- 현재 도구가 지원하는 최소 변경안을 준비한다. 원문·고유 앵커·전체 diff/후보·영향·검증·원복 근거를 검토하고, 중복 룰·누락/범위 변경·접근 경로 단절 가능성을 확인한다.
- 보호 변경은 정확한 후보와 실제 관리자 승인 카드에 연결한다. 사용자 문장·과거 카드·다른 후보 승인·봇의 검토 동의를 현재 승인으로 대신하지 않는다. 긴급 임시 대응 예외도 실제 SOUL/서버 정책 범위만 따른다.
- 제안·승인·소비·적용·엔진 반영·실제 효과는 별개다. 실제 request/proposal ID와 대상별 올바른 상태 API로 확인하고, 제출 성공을 적용 성공으로 보고하지 않는다.
- 보호 호출이 시작된 뒤 결과가 불명확하면 같은 요청이나 대체 도구로 재실행하지 않는다. 실제 상태·소유권·이전 영수증을 확인하고 모호함을 남긴다. 전송 전 인자 거절과 실행 결과 불명은 구분한다.
- 적용 후 요청한 상태/룰·실제 가동/효과·관련 영향과 원복 가능성을 확인한다. 원복 역시 현재 허용된 도구와 정확 승인 경계를 따르며, 다른 사람의 변경·외부 소유 차단을 덮어쓰지 않는다.
- 교차 검토는 원 요청 대비 누락·보호 범위·후보/승인 결속·사후 확인을 우선한다. 반대 의견은 실제 근거와 연결하고, 검토자가 새 변경을 중복 제출하지 않는다. 결과는 공통 soc-output으로 보고한다.
