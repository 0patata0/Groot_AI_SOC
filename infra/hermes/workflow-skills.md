## 실제 연결

`workflow_contract.py`는 고정된 네 이름만 허용한다. 각 SKILL의 이름·설명·고유 마커·크기와 파일 경로를 확인하며 누락·중복·심볼릭 링크를 조용히 무시하지 않는다. 원본 정의는 위 네 폴더에 하나씩 둔다. 설치된 세 프로필의 `skill-soc-*.md`는 같은 원본 바이트의 배포 복사본이다. flat 이름으로 기존 파일별 백업/원복과 충돌 없는 초기 반입을 유지한다.

SDK의 기존 요청 해석과 Native의 같은 공유 하네스가 필요한 업무만 선택한다. Native는 이전 업무 블록을 제거하고 현재 블록을 한 번 넣는다. root 자동조사/검토는 실제 사건·변경 문맥의 절차를 사용하고 단순 조회는 기존 읽기 경로를 사용한다. 선택을 위한 추가 LLM/MCP 호출은 없다. 도구 스키마/영수증 검사·렌더링 코드와 API별 도움말은 기능상 필요한 부분을 유지했다. 전체 하네스 문장을 모두 삭제했다는 뜻은 아니다.

권한·강제 역할·정확 후보 승인·보호 주소·TTL/소유권·결과 불명 시 재실행 제한은 SOUL와 서버 코드에서 계속 검증한다. SKILL을 편집해도 도구 권한이나 승인이 생기지 않는다. Native skill_manage의 임의 자기 수정·배포는 이번에 연결하지 않았다. 환경의 변동 상태를 스킬에 외워 두지 않고 실제 MCP 근거로 확인한다.
