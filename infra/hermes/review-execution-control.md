query1.19.76을 B에 반영했다. Native 사건 재검토에서 압축한 모델 입력에도 실제 실행기의 종료 안내와 반복 실패 정보를 전달한다. **정확한 최종 보고30초 달성은 아직 입증하지 못했다.** [수치 원장](review-execution-control.validation.json) · [현재 상태](../../STATUS.md).

## 원인과 변경

앞선 비공개 시험은 프로세스 `active`를 웹 정상·위험 해소로 잘못 판단해 기존 검사가 거부했다. 이후 없는 FW snapshot으로 같은 호출을3번 반복했고214.517초에 시간 초과했다. 해당 시험에서 Native는 실행 예산80% 이후 최신 tool 메시지에 마무리 안내를 붙였다. 그러나 compact 경로는 원래 메시지 대신 실제 영수증과 제어기 요청으로 입력을 다시 구성하므로 이 안내가 빠졌다.

| 보완 | 유지하는 경계 |
|---|---|
| 실제 Native `_run_budget_wrapup_injected`가 boolean true일 때 종료 안내 전달 | 도구 출력·사용자 문구로 이 상태를 만들지 않음. 기존 시간 한도 그대로 |
| 실제 완료 원장의 동일 도구·정확 인자에 대한 반복 실패 행 번호 전달 | 같은 호출이 성공하면 해당 실패 묶음 초기화. 다른 도구·대상·인자는 구분 |
| 오류 검토와 인자/접근 변경, 현재 근거·미확인·다음 조치 보고 안내 | 읽기 도구 제거·강제 종결·정상 판정·승인 생성·미조회 성공 처리 없음 |

기존 필수 근거·사실 일치·인용·위험 해소 검사는 그대로다. 반복 실패 안내는 재시도 정책을 모델이 판단하는 근거이며 도구 호출을 자동 실행하거나 금지하지 않는다. 운영자 명시 ID와 실제 발급된 snapshot ID의 결속 검증은 별도 후속 작업이다.
