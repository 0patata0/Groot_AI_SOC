# 공통 주장 결속·조회 범위 개발 검증

**부정·조건·향후 조사 표현의 검사 오탐과 첫 센서 조회 범위를 보완했다. DNS 답변의 근거 오류가 남아 운영에는 채택하지 않았다.** [검증 원장](validation.json) · [동결 소스와 의존 관계](manifest.json) · [현재 상태](../../../STATUS.md).

## 실제 요청에서 확인한 결과

동일한 세 개발 질문을 격리 기준본·R5 후보·R6 후보로 실행했다. 총9요청/MCP9·기록된 모델 완료19이며 Mattermost 게시·운영 적용·공격 시험은0이다. 기준본은 **미승인 관리 상태19파일+앞선 공통 조회8소스의 격리 조합**이다. 현재 설치본이나 승인된 배포본으로 부르지 않는다.

## 정리한 공통 요소

| 요소 | 후보 동작 | 유지한 경계 |
|---|---|---|
| 주장에 붙은 표현 | 부정·조건·조회 예정·실제 단정을 분리. `입증하지는 않습니다`·`입증하지도 않습니다`도 공통으로 처리 | 다른 문장/앞선 표본 한계로 후속 단정을 면제하지 않음. 이중부정은 불확실성 면제가 아님 |
| 센서와 측정값 결속 | 자기 센서의 건수·없음·과거 탐지 주장만 검사. 다른 센서의 앞선 숫자나 뒤의 조사 계획을 빌려 오지 않음 | 미조회 센서의 실제 건수/탐지 단정은 계속 거절. Wazuh 미호출 실패 주장은 아직 놓침 |
| 관리 상태 형식 | 일반 답변에 선택적으로 나온 MANAGEMENT_STATUS의 enum을 검사. 판단 단계에는 기존 `soc-investigate`의 `incident-disposition` 절 재사용 | 상태·위험·승인을 코드가 대신 선택하지 않음. nonce JSON용 다른 단계 지침을 섞지 않음 |

기존 diagnostic 기간 근거 검사가 `검토해야`라는 계획 표현으로 우회되는 회귀를 확인해, 호환 진입점에서는 계획 표현을 면제하지 않게 수정했다. 보안 경계를 느슨하게 하는 방식으로 오탐을 없애지 않았다.

## 재현 방법

원격 연결·모델·MCP·서비스 제어 없이 소스 조합과 공식 구조 검사를 재현한다. 프로젝트에 이미 보존된 고정 Harness²를 사용하며 새 도구를 설치하지 않는다.

```sh
python3 -B infra/validation/claim-modality/reproduce.py --repo /절대경로/capstone_project --output /새로운/임시/claim-review
SOC_MODALITY_ROOT=/새로운/임시/claim-review/candidate python3 -B infra/validation/claim-modality/test_claims.py
```

`prerequisite.patch`는 Git69f809b에서 **미승인 비교 기준**을 만들기 위한22파일의 재구성 연결이다. 배포 계획이 아니며 정본에 적용하지 않는다. `candidate.patch`는 그 기준에서4파일만 바꾼다. 두 패치·시험·24구성 SHA와 허용 AST 범위를 [manifest](manifest.json)에 고정했다. 재현기는 현재 작업 트리의 다른 변경을 가져오지 않는다. 출력물은 새 임시 경로에만 만들고 종료 후 정리한다.

## 다음 완료 조건

1. 조회 성공/실패 서술을 실제 호출 시도·정확 도구·인자·결과 영수증과 결속한다. 미호출 도구의 가짜 실패를 허용하지 않는다.
2. 짧은 경보 요청에서 목록 조회와 사건 판단 의도를 공통으로 구분하고 실제 읽기·기본 시간 범위를 연결한다. 설명 방법 질문의 기존 오분류도 별도 회귀로 다룬다.
3. 다음 조사 계획에 실제 MCP 필터/기능 제약을 전달해 미지원 목적지IP·포트 검색을 가능하다고 제안하지 않게 한다.
4. 다시 공식 Harness²·동결·반례/회귀·실제 읽기를 확인한다. 이후에도 정확 운영 승인·적용/복구·새 Mattermost 채팅 검증은 별도다.

기존 [관리 상태19파일](../control-status/application/README.md)과 [journal9코드](../journal-adapter/application/README.md)의 승인·계획 SHA는 바꾸지 않았다. 이 개발 후보를 기존 승인에 끼워 넣거나 운영 완료로 표시하지 않는다.
