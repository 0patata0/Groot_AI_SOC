# 기능 장애 부재 주장과 복합 판단 후보 검증

2026-11-08 KST. 실제 모델이 만든 “oneshot의 정상 종료이므로 기능 장애가 아닙니다”라는 문장이 기존 검증기를 통과했다. common1.5.80은 프로세스 종료 관측을 기능 장애 부재로 확대하는 이 경로를 거절한다. [현황](../../STATUS.md) · [재현 원장](functional-health-claims.validation.json).

## 수정 범위

- `기능 장애가 아니다`, `서비스 장애가 없다`, `관제 이상이 없다` 등 명시적인 장애 부재 주장을 기능 정상 주장과 함께 검사한다. 이 검사는 반대로 서비스에 장애가 있다고 판정하지 않는다.
- 같은 주장에 붙은 `단정할 수 없다`, `판정은 미확인` 등은 건강 판정이 아니므로 허용한다. 다른 문장의 주의 문구가 별도의 정상 주장을 면제하지 않는다.
- 실제 종료값0·Type=oneshot/Result=success를 보고하는 것은 유지한다. 웹과 진단 대상의 오류 코드를 구분하며, 새 도구·권한·판정 규칙·자동 조치는 추가하지 않는다.
- 수정 피드백에도 정상 종료가 기능 장애 부재를 증명하지 않는다는 설명을 연결했다. 모든 자연어 우회 표현을 탐지한다고 보장하지 않는다.

## 실제 모델 대조에서 채택하지 않은 후보

기존 원본 qwen3.6:35b·운영 설정을 사용했다. 실제 직전4조회와 같은 전체 원문/등록35읽기 도구·같은 오류 피드백을 주고, 후보만 지표별 필드/값/뜻/출처를 추가했다. 실제 사건1조건과 별도 합성 반례2조건을 각각 대조군/후보로 생성했다. 원문은 줄이지 않았고 도구 실행·운영 정책 변경은 없었다.

6개 출력 모두 JSON 규격은 통과했으나 규격 통과나 기존 guard의 오류0은 의미 정확성 증거가 아니다. 표에 이미 정확한 관측이 있어도 모델의 별도 잘못된 판단을 정당화하지 않는다. 반대로 `needs_review` 또는 사건 미종결 자체만으로 답변이 부정확하다고 판정하지 않는다. 질문 범위의 원인/현재 영향·불확실성을 근거에 맞춰 설명했는지를 별도로 검수한다.

같은 실제 조건에서 추론 기능만 켜고 출력 상한4,096으로 시험한 별도1회는 **75초 응답 제한에 도달해 결과를 확보하지 못했다**. 모델 품질·속도 개선을 입증하지 못했으므로 운영의 reasoning=False를 바꾸지 않았다. 서버 측 연산 취소 완료까지 검증한 것은 아니며, 생성 결과·추론 내용을 확보했다고 표시하지 않는다. 이 실험은 단일 모델 호출 시간이며 Mattermost 왕복 시간이 아니다.

위 자료는 이미 사용한 개발 사례 및 합성 반례다. 학습 편입·미사용 독립 평가·통계적 정확도 비교로 세지 않는다. 후보 안내나 평가 정답을 운영 답변에 고정하지 않았다.
