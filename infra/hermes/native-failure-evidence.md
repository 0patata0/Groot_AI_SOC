# Native 실행 실패 시 조회 근거 보존

2026-11-08 07:16 KST 확인. review 채널에서 Hermes가 MCP 조회 뒤 최종 생성을 끝내지 못하면 실제 받은 조회 자료까지 일반 실패 문구로 사라지던 경로를 수정했다. 조회 표를 남기되 최종 판단·요청 완료·정상·복구 성공으로 표시하지 않는다. [현재 현황](../../STATUS.md) · [소규모 재현 정보](native-failure-evidence.validation.json).

## 구현과 경계

- 현재 run의 CLI trace에서 `tool_use`와 `tool_result`를 ID·이름으로 결속하고, 완료된 도구 이름·오류 여부·횟수를 같은 run의 DB 원장과 대조한다. 도구 원문 SHA를 유지한다.
- 마지막 메시지나 읽기가 미완료여도 앞서 검증한 읽기만 표시한다. 훼손·미결속 기록, 32MiB 초과 trace, 비허용 도구는 사용하지 않는다. 기존 엄격한 trace 판독 호출은 동작을 유지한다.
- 더 늦은 현재 차단 목록 조회가 실패·미완료·누락되면 앞선 차단 목록을 현재 목록으로 재사용하지 않는다. 모든 표는 조회 당시 관측이며 답변 시점의 최신 상태를 보장하지 않는다.
- 쓰기 실행이 섞인 실패는 기존 보호 작업 실패 처리로 유지한다. 새 권한·자동 조치·일반 셸 실행은 추가하지 않는다.
- 실패한 답변은 `partial`, 범위 미완료 및 비재사용 감사 기록으로 남긴다. 모델이 생성한 미검증 문장을 완료 답변으로 게시하지 않는다.

적용 범위는 `review_channel_worker.py`의 Native 실패 답변이다. 후속 수정은 CLI 완료+도구 실패에도 같은 근거 보존을 적용했다. [실제 실패 재생·시간 제한 보완](../mcp/journal-query-budget.md). 자동 SOC controller의 실패 outbox 및 직접 Hermes gateway의 모든 실패 경로를 검증한 것은 아니다. 모델이 최종 보고를 생성했으나 의미 판단이 틀린 문제도 별도다.

## 설치·복구·정리

`deploy.sh`→기존 review 설치 경로가 canonical worker를 복사하므로 새 패키지·포트·설정 키는 없다. 설치 관련63검사가 통과했으며 새 서버 전체 설치는 하지 않았다.

운영 복구본은 `/var/lib/capstone-service-grounding/20261108-failure79`에 보존했다. 관리자231 경유로 review queue 유휴 상태를 확인하고 백업의 worker/receipt만 복원하는 범위이며 DB·승인·trace·기존 다른 파일은 덮지 않는다. 적용 때 독립15분 원복 타이머를 두고 서비스·소스 확인 후 확정했다.
