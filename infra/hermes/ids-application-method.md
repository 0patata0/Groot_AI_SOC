## 수정과 실패 기록

- 적용 방식 질문과 실행 지시를 분리한다. “재시작 없이”를 조회 대상에서 지우지 않고, 재적재/리로드 실행 요청은 기존 보호 변경 경로로 남긴다. 하네스가 변경을 승인하거나 MCP를 고정 호출하지 않는다. 모델이 등록된 도구·인자를 선택한다.
- 최신 조회 실패·잘못된 대상·원문 해시 불일치·빈 허용 작업·미확인 영향을 완료로 세지 않는다. 이전 성공으로 덮지 않는다. `reload`가 허용돼도 실제 적용 성공 증거로 사용하지 않는다.
- 룰 개수와 적용 방식이 함께 요청되면 두 범위를 모두 요구한다. 알 수 없는 시각·경로는 미확인으로 남긴다.
- 최초 로컬 검사3실패를 수정한 뒤 첫 운영 후보에서 Hermes는 성공했으나 Ollama 두 질문은6.720/6.982초·실제조회0·partial이었다. 누락 대상 ID에 설명을 붙여 SDK 스키마 대상 선택이 빈 목록이 된 코드 오류였다. 안정된 ID를 보존하고 등록 스키마→모델 선택 경로 회귀를 추가해 위 최종 결과를 확인했다. 빠른 실패를 성공 지연으로 세지 않는다.
- 이 문제는 하네스/스키마 오류이며 추가 모델 학습으로 해결한 것이 아니다. 시험 질문을 학습 자료로 추가하지 않았다.
