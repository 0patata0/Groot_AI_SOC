# 남은 모델 처리 지연 점검 — 2026-10-24 KST

현재 모델 크기를 유지해도 캐시가 맞으면 모델 단계는 수초에 끝난다. 남은 지연의 주요 비용은 긴 입력 재처리이며, 모델 재적재와 시간대별 출력 속도 변동도 관측했다. **이번 작업은 점검이며 추가 속도 개선을 운영에 배포하지 않았다.** 이전 실제 IDS 채팅43.291/43.063초가 최신 운영 왕복 표본이다. [측정 메타데이터](../inference-latency-inspection-20261024.json) · [전체 현황](../../../STATUS.md).

## 접근·시험 범위

사용자가 DGX에는 SSH 없이 Ollama API만 열려 있다고 확인했다. Groot_B에서 기존 모델 `qwen3.6:35b`·Ollama0.40.4의 공개된 API만 호출했다. GPU 사용률·전력/온도·서버 큐·다른 사용자의 실제 병렬 연산·실행 환경변수는 확인하지 못했다.

운영1.5.1의 native 요청 조립 경로로 과거 시험 질문과 당시 도구 결과를 재현했다. 도구 선택 요청은19개 읽기 스키마/22,808입력 토큰, 읽기 후 요청은 원래35개 스키마/27,886토큰이었다. 이는 당시 대화 재생의 입력 크기이며 모든 새 질문의 크기가 아니다. 정책·변경안 준비 권한·정확 승인 경계는 유지했다.

모델 API 요청16회를 순차 실행했고 실제 MCP 도구 실행·채팅 게시·보호조치·운영 재시작은0회다. 스키마 발견은 수행했다. 출력 상한1,536토큰에 걸려 종료된 표본은 없었고 숨은 추론 본문은 저장하지 않았다. V1 스트림과 native `/api/chat`의 계측을 구분한다. native에서는 같은 메시지/도구·`think=false`·대응하는 생성 옵션을 사용했으나 `tool_choice` 필드가 없어 완전히 같은 전송 계약으로 간주하지 않는다. 사용자에게 스트리밍을 켜거나 검증 전 내용을 게시하지 않았다.

측정 중 같은 서버에 `qwen3.8:27b`도 상주하는 것을 확인했고 일부 구간에서 생성 속도가 낮아졌다. 이 두 관측만으로 다른 모델의 실제 병렬 연산이 원인이라고 확정하지 않는다. GPU 사용률·서버 로그 접근 없이 전력 제한/온도·큐 대기·동시 요청을 분리할 수 없다.

## 캐시와 샘플링 대조

캐시가 항상 무효화되는 것은 아니다. 같은 시스템/도구/대화 앞부분을 유지하고 마지막 안내 문장만 추가한 통제 시험에서는22,818토큰 중20,770토큰을 재사용했고 입력 처리0.899초·전체1.871초였다. 그 요청을 그대로 반복하자22,814토큰을 재사용했다. 부분 접두부 재사용이 실제로 작동한다.

앞선 `fresh_prefix_sampling` 묶음의 `tail_changed` 표본은 직전 요청과 시스템 접두부까지 달랐으므로 “꼬리만 바꿔 전체 캐시가 깨졌다”는 증거로 쓰지 않는다. 이 구분을 위해 별도 통제3요청을 실행했다. 읽기19개에서 조사 후35개로 도구 목록이 달라지는 실제 계약도 입력 앞부분을 바꾸는 요인이지만, 권한 경계를 희생해 목록을 고정하지 않는다.

선택 단계의 `temperature=0`을2회 시험하자 같은2개 읽기와 인자를 선택했다. 호출 수가 줄지 않았고 실채팅 지연 개선/일반 정확도 이득도 입증하지 못해 운영에는 적용하지 않았다. 기존 모델의 temperature1·top_p0.95·draft2 등 파라미터와 Hermes의 요청별 추론 설정을 유지했다.

## 후속 우선순위와 운영 확인

1. 현재 근거·사용자 제약을 보존하면서 API 입력의 중복과 앞부분 변동을 줄이는 후보를 별도로 검증한다. 이미 반영한1.5.1의 과거 읽기 원문 생략은 유지한다.
2. 캐시를 유지하려고 오래된 조회 답변을 현재 사실로 재사용하거나, 신규 증거·시각을 고정하거나, 조사 후 변경안 준비 권한을 없애지 않는다.
3. 모델 상주 시간 연장이나 서버별 전용 자원은 모델 소유 측의 지원·자원 정책을 확인한 뒤 검토한다. 현재 접근만으로 GPU/큐/전력 설정을 튜닝했다고 표시하지 않는다.
4. 전송 스트리밍만으로 모델 계산량이 줄지는 않는다. 검증 전 토큰 노출은 기존 KST/근거 검사와 함께 설계·재검증할 사안이다.

운영 소스/manifest·양 프로필 설정·Memory·공용 gate7개 파일 해시는 직전 배포와 일치한다. gateway 연결·기존 timer/broker active·failed0·서버 시험 임시 디렉터리0을 확인했다. 전체 메시지는1450→1453행으로,23:23 KST의 별도 실제 채팅 user/assistant/session_meta3행 증가를 메타데이터로 구분했다. 이번 진단은 글을 게시하지 않았고 상태 DB는 읽기 전용으로 열었다.

새 모델 설치/교체, `keep_alive`·`num_ctx`·서버 캐시 설정 변경, 강제 unload/cache flush, Mac 설치·패키지 다운로드는 수행하지 않았다. 실제 공격/탐지/승인/차단E2E·새3VM 설치와3번CVE 보류 범위도 유지한다. 문서 게시·Mac 임시 정리 결과는 [STATUS](../../../STATUS.md)를 따른다.
