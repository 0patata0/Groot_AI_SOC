## 순서와 판정

1. 현재 운영 소스·모델 digest·템플릿·컨텍스트·추론 옵션을 고정한다. Thor 가용 메모리/공유 부하와 후보 API 호환성을 읽고 시험 실행의 자원·시간 한도를 정한다. 기존 운영 모델을 그대로 복구할 설정과 종료 절차를 검증한다.
2. 운영 봇 설정을 덮어쓰기 전에 같은 SDK 하네스의 별도 실행에서 후보를 명시적으로 선택한다. 우선 실제 읽기 MCP만 제공한다. 짧은 질문·후속 문맥·장비별 전체 룰·경보/시스템 조사·불확실성 처리로 검증한다. 첫 적재 시간과 재사용 응답 시간을 분리한다. 일반 셸/sudo나 공격 송신은 추가하지 않는다.
3. 같은 최신 하네스와 권한·도구·옵션·문항으로 운영 원본과 비교한다. 학습 효과 분리는 동일HF 미학습 대조군을 포함한다. 시점이 변하는 라이브 관측과 동일한 고정 관측을 분리하고, 모델 실행 순서·자원 부하를 남긴다. 이전 평가 정답을 학습에 넣지 않는다.
4. 실제 도구·인자·원문SHA·페이지/범위·최종 답변·시각·누락·실패·소요 시간을 함께 채점한다. 보안상 치명적 누락·무승인 조치·근거 없는 정상/성공은 우선 탈락 조건이다. 모의 평가 통과를 운영 대응 성공으로 세지 않는다.
5. 읽기/조사 검증을 통과한 후보만 제한된 채팅 시험으로 연결한다. 이후 보호 쓰기는 기존 정확 후보 승인 카드·적용 후 읽기·독립 복구를 거친다. 원본과 동점/우위 미입증이면 운영 원본을 유지하되 후보의 실제 시험 결과는 보존한다.
