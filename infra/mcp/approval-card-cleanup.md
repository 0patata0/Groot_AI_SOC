# 미응답 만료 승인 카드 정리

사용자가 본문·버튼 정리 방식을 승인한 뒤 **2026-10-15 18:52 KST B 브로커에 배포**했고, 실제 응답 형식 보완을19:01:33에 적용한 후 **19:02:18 KST 실제 API 검증을 통과**했다. 신규 설치의 기본값은 비활성이며, 배포 스크립트 실행만으로 자동 활성화하지 않는다. 앞선 선택 대기·미배포 안내는 이 배포 이전의 상태다.

Mattermost에서 루트 게시물을 삭제하면 댓글까지 함께 삭제된다. 따라서 구현은 게시물 삭제 대신 `PUT /api/v4/posts/{post_id}/patch`로 만료된 요청의 본문을 `만료된 승인 요청`으로 바꾸고 `attachments=[]`를 보낸다. Mattermost의 응답·재조회에서 빈 첨부는 JSON `null`·필드 없음·빈 배열만 인정하고 나머지 props는 엄격히 비교한다. 잘못된 자료형이나 남은 버튼은 거부한다. 승인 버튼과 기존 카드 본문은 사라지지만 댓글·게시물 ID·다른 속성은 유지된다. HTTP DELETE는 사용하지 않는다. [Mattermost 11.11.1 공식 API 정의](https://github.com/mattermost/mattermost/blob/v11.11.1/api/v4/source/posts.yaml#L352).

## 적용 범위와 보호

- 활성화 이후 지정된 일반 봇이 REST로 새로 만든 승인 요청 카드만 대상이다. 기존 incoming webhook 카드와 연결 근거가 없는 과거 게시물은 검색하거나 정리하지 않는다.
- IP 대응, 보안 규칙 변경, 서비스 작업·임시 차단 결정의 미응답 만료 요청을 처리한다. 승인·거부·소비·결과가 기록된 요청은 영속 보호하여 이후 상태가 `expired`로 바뀌어도 정리하지 않는다.
- 게시물 ID, 봇 ID, 채널 ID, 요청 ID, nonce의 SHA-256, 제안 digest, 만료 시각과 카드 내용 hash를 확인한다. 콜백도 실제 `post_id`·`channel_id`가 일치해야 결정을 수락한다. 기존 승인자·출처·nonce·정확 후보 검증은 유지된다.
- 승인·거부 수락 전에 SQLite `synchronous=FULL`로 정리 제외 상태를 저장한다. 저장 실패 또는 정리 중 경합이면 결정을 반영하지 않는다. 정리 기록으로 승인을 복원하지 않는다.
- 결과 게시물, 분할 diff 검토 게시물, 기존 감사기록은 수정하지 않는다. 원문 카드·토큰·nonce 원문은 정리 DB에 저장하지 않는다.

## 배포 준비

배포 파일은 같은 버전의 `soc_bot.py`, `operations_approval.py`, `soc_management_events.py`, `approval_card_cleanup.py` 네 개다. 두 배포 스크립트가 이 묶음을 함께 검사·복사하도록 갱신되었다.

`deploy_rule_broker_B.sh`는 `RULE_SOCBOT_SRC` 파일의 인접 디렉터리에서 나머지 모듈을 읽으며, 코드·모듈·환경 파일을 백업하고 실패 시 원복한다. `--check`는 변경하지 않는다. 초기 설치용 `deploy_socbot_B.sh`는 `/tmp/`에 네 파일이 모두 있어야 하며, 이미 보호된 브로커 설정이 있는 환경에서는 재실행을 거부한다. 두 스크립트 모두 만료 카드 정리를 자동으로 활성화하지 않는다.

별도 Python 패키지는 필요 없다. 표준 라이브러리와 기존 Python 3을 사용하며 Mac에 패키지를 설치하지 않는다. 운영 서버의 `/opt/socbot` 파일은 기존 정책대로 root 관리, socbot 읽기 권한을 유지한다.

## 활성화 설정

아래 값은 서버의 보호된 `/etc/socbot/soc_bot.env`에만 설정한다. 실제 토큰은 Git·명령행·로그에 넣지 않는다. [환경 파일 예시](soc_bot.env.example)를 참고한다.

| 변수 | 용도 |
|---|---|
| `SOC_APPROVAL_CARD_CLEANUP=1` | 명시적 활성화. 미설정은 기존 webhook 방식 유지 |
| `SOC_CARD_MM_URL` | Mattermost 서버의 고정 기본 URL |
| `SOC_CARD_MM_TOKEN` | 지정된 일반 봇 토큰. system_admin 토큰은 거부 |
| `SOC_CARD_MM_BOT_ID` | `/users/me`와 일치해야 하는 고정 봇 ID |
| `SOC_CARD_MM_CHANNEL_ID` | 승인 요청을 게시할 고정 채널 ID |
| `SOC_CARD_CLEANUP_DB` | 기본값 `/var/lib/socbot/approval-cards.sqlite3` |

DB 부모는 socbot 소유 0700, DB는 socbot 소유 일반 파일 0600이어야 한다. 심볼릭 링크·다중 하드링크·잘못된 권한을 거부한다. 신규 환경은 해당 디렉터리를 별도로 준비하고 soc-bot systemd의 `ReadWritePaths=/var/lib/socbot` 허용 여부를 확인해야 한다. 기존 디렉터리의 권한을 임의로 바꾸지 않는다. 추가 관리자 역할이나 일반 sudo·Docker 권한은 필요하지 않다.

기능을 끌 때는 활성화 값을 제거하거나 `0`으로 바꾸고 서비스에 반영한다. 감사 DB를 삭제하거나 승인 복원에 사용하지 않는다.

## 검증과 운영 한계

로컬 최초 신규33개·기존51개, 총84개 통과 후 실제 응답 정규화 회귀를 추가하여 **신규39개·기존51개, 총90개 테스트를 통과**했다. 정확한 카드 식별, 승인·거부 보존, 콜백 혼선 거부, 댓글·다른 속성 유지, DELETE 금지, 응답 유실 후 멱등 처리, 재시작·제한 재시도, 응답 용량·시간 제한과 빈 첨부의 허용/거부 경계를 확인했다.

```sh
PYTHONDONTWRITEBYTECODE=1 python3 -B -m unittest discover -s infra/mcp -p 'test_*approval*.py'
```

작업자는 5초마다 만료를 확인한다. 정상 API 응답과 낮은 대기량에서 만료 후 약 10초 내 정리를 목표로 하며 고정 완료 시간은 보장하지 않는다. 후보가 없으면 Mattermost API를 호출하지 않는다. API 요청당 응답 제한은 2MiB·5초이며, 일시적 실패는 지연 재시도하고 최대 5회 이후 보존 상태로 전환한다. 권한·신원·내용 불일치는 자동 범위 확장 없이 보존하고 고정 오류 코드만 기록한다.

POST 성공 여부가 불명확하거나 카드 연결 저장에 실패하면 자동 정리 대상에 넣지 않는다. 이는 승인 오인이나 다른 게시물 정리를 피하기 위한 보수적 잔여 카드다. Mattermost의 편집 제한 때문에 정리가 거부될 수도 있다.

이번 라이브 시험에는 **실제 관리자 승인이나 룰 API 호출이 없었다.** 영속 보호 상태의 카드가 정리되지 않는지 확인한 범위이며, 승인→룰 적용 전체 시험으로 확대하지 않는다. 이후 신규 운영 요청의 정리·보호 상태와 API 오류를 계속 관찰한다. 부분 수정 응답의 바인딩·내용 확인에 실패하면 정리를 확대하지 않고 보호 상태로 남긴다.
