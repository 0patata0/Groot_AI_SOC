# 자동 관제의 지연과 중단 보고 복구

Native 실제 실행에서 첫 조회의 KST 날짜·센서·현재 차단 목록을 공통 계약에 맞췄다. 짧은 문장의 독립한 목록 요청도 두 봇 공통으로 해석한다. 보고에는 공통 추론 설정과 근거에 결속한 최대2회 정정을 적용했다. 최종23사본의 Mac/Linux 회귀240·206·27과 Linux Harness²38·설치37은 통과했다. 격리 Native 최종2질문의 보고 수락은2/2이며 전체 실행은28.745/64.764초다. 이전의 잘린 보고·틀린 주장·목록 누락·반복 조회 거절도 원장에 보존했다. 운영 미적용·기본값0이며 실제 Mattermost 응답 시간과 일반 정확도는 미검증이다. 공격·새 학습 중단을 유지한다. [의미·가용성 검증](capability-grounding.validation.json).

자동 관제의 긴 입력과 중단 시 근거 손실을 분리해 보완했다. 운영 B의 자동 관리 경로에 반영했으며 MCP 도구·스키마·모델·승인 권한은 바꾸지 않았다. 후속 Native·SDK 이관과 새 단순 조회4건을 확인했으며 복합 조사30~60초와 통제 전후 비교는 미완료다. 아래 시각은 KST다.

## 복합 조사 후보와 품질 승격 보류

새 스레드에서 오늘 WAF와 IDS 경보의 공통 출발지·실제 차단 여부를 조사하도록 요청했다. Hermes는 149.666초, Ollama는 116.849초 뒤 검증 미완료 보고를 냈다. 실제 MCP는 각 2읽기였다. Native는 각 10건/scan_capped, SDK는 WAF19건·IDS48건/limit50을 반환했으므로 같은 범위의 속도 비교가 아니다.

| 실제 MCP 격리 시험 | 다른 복합 질문·기존 읽기36개만 노출·2읽기·모델4회·126.027초. 차단 목록을 읽지 않고 현재 차단이 없다고 주장해 거절됨. 운영 파일·쓰기·Mattermost 게시0 |
| 모델/환경 | 같은 학습 모델·65,536컨텍스트·전체 GPU 적재를 관측. 이번 입력은 한도 내이며 모델 교체나 학습은 하지 않음 |

동일 자료 재검사는 새 MCP·독립 사건·실제 채팅이 아니다. 실제 MCP 격리 시험도 Mattermost 왕복이나 Native 검증을 대신하지 않는다. 모델 실험은 앞선 후보이며 최신 fingerprint/문자열 경계 보완은 회귀 근거로만 기록한다. 모든 guard 통과가 사실 정확도를 보장하지 않는다는 반례도 남긴다.

**운영 승격은 보류했다.** 설치본의 명시 동반 조회 범위와 정정 단계에서 부족한 실제 읽기를 선택하는 경로가 다음 보완 대상이다. 403·당시 엔진 모드와 실제 요청/IP 차단·침해 영향을 분리하고 주소·시간 연관을 동일 flow 증명으로 바꾸지 않아야 한다. 판정 enum을 억지로 정상/해결로 채우거나 가드레일을 낮춰 통과시키지 않는다. 공개 정본은 후보 코드이며 B의 현 운영 13파일 확정 상태를 덮어쓰지 않았다. 초기 설치기는 기존 공통 파일 복사 경로를 유지하고 37검사를 통과했으나 새 OS 전체 설치와 후보의 새 실제 채팅은 미수행이다. [기계 판독 원장](complex.validation.json).


## 동반 조회와 센서별 주장 검증

기존 도구가 없어서 실패한 것이 아니었다. 복합 질문에서 현재 IP 차단을 명시해도 필수 읽기로 잡지 못했고 한 센서 조회만으로 다른 센서의 조회까지 끝난 것으로 처리할 수 있었다. 현재 차단 목록·과거 이력·웹 요청 차단을 구분하고 장비별 최신 성공 영수증을 각각 요구하도록 보완했다. 최신 실패·SHA 불일치·잘못된 반환은 이전 성공으로 대신하지 않는다.

모델이 기존 등록 도구와 인자를 선택한다. 요청한 읽기의 전체 묶음을 검증한 뒤 실행하며 보호 도구·중복으로 채운 누락 묶음은 부분 실행하지 않는다. 예산이 적으면 후속 묶음과 미완료 범위를 유지한다. 다른 서비스·과거 시각·부정·조건·인용·정의 설명을 현재 FW 목록으로 바꾸지 않는다. 교차 검토의 초기 도구 범위에도 명시한 동반 목록을 남긴다.

| 실제 SDK 격리 시험 | 시간·실제 읽기 | 결과·한계 |
|---|---|---|
| 1차 · IP 대조 표현 | 95.355초·2건 | ‘대조’를 놓쳐 목록을 읽지 않았고 미실행 목록 주장을 가드가 거절 |
| 2차 · 표현/필수 범위 보완 | 101.095초·3건 | 목록 누락은 해소. HTTP403을 WAF 차단·백엔드 보호로 단정해 최종 partial |
| 3차 · 다른 비교 질문 | 77.578초·3건 | 자동 completed였으나 원문 대조에서 WAF에 없는 출발지·403만의 차단 입증을 확인. 품질 통과로 채택하지 않음 |

위 중간 세 시험은 서버의 현재 MCP를 실제 읽었으나 Mattermost 왕복은 아니다. 같은 질문의 통제 비교나 평균/p95도 아니다. 실제 로그 표본과 조회 한도가 달라 소요시간을 향상률로 환산하지 않는다. 최종 후보의 다른 조사 질문도 147.322초·실제 3읽기·모델 4회 뒤 같은 403 단정이 반복되어 partial로 종료했다. 세 번째는 비교 질문을 사건 조사로 분류하지 않아 판단 감사가 없었다. 실제 경보 필드 검사는 이런 분류와 관계없이 적용하도록 보완했다. 잘못 통과한 원문을 새 검사에 넣으면 `http_status_used_as_security_outcome`·`source_address_attributed_to_wrong_sensor` 두 사유로 거절된다. 모든 의미 오류를 검출하는 검증기는 아니다.

최종 후보는 운영 설치본 13파일에서 선언한 함수·스킬 절만 바꾼다. 기존 MCP 45·같은 학습 모델·B→Thor·보호 주소·승인·TTL은 유지한다. Mac/Linux 설치본 Native 169·SDK 118·Harness² 38·설치 37은 모두 통과했고 생략 0이다. 정본 Native 430은 통과했지만 SDK 422에는 기존 8실패항목/1오류가 남는다. 로컬 전체 서비스 계약 검사에는 openai 모듈 공백이 있다. 필요한 동반 읽기 7검사 통과와는 구분한다. Mac에는 패키지를 설치하지 않았다. [해시·시험·최종 상태](companion.validation.json).

초기 설치는 기존 deploy.sh가 같은 정본을 복사하는 경로를 유지한다. 신규 MCP·이미지·포트·패키지가 없어 설치 진입점이나 오프라인 목록은 바꾸지 않았다. 설치 회귀는 새 OS 전체 설치를 대신하지 않는다. 새 후보의 운영 적용·서비스 재시작·새 실제 채팅·공격·학습은 0이며 직전 운영과 복구본을 보존한다.


## 현재 근거에 결속된 구조화 판단

조사 이력을 매번 길게 다시 설명하는 대신 현재 요청과 실제 읽기의 인자/원문·SHA·성공/실패 순서를 한 사본으로 묶어 전달하는 후보를 만들었다. 기존 읽기 전용 필터에 판단 단계를 따로 두고 공통 역할·출력·조사 스킬을 재사용한다. 읽기 선택만 하라는 안내를 판단 단계에 그대로 넣지 않는다. 보고 형식은 기존 서비스 보고의 구조를 재사용하며 원문 표는 기존 렌더러가 표시한다. 위험 판단과 추가 조회의 선택은 모델이 맡는다.

| 검증 단계 | 시간·호출 | 실제 결과와 한계 |
| --- | --- | --- |
| 보존 근거의 모델 단독 시험 | 17.307초·새 MCP 0건 | Wazuh 추가 읽기 이름을 선택했으나 실행하지 않았다. 최종 조사 시간·현재 라이브 상태의 판정이 아니다 |
| 실제 SDK 1차 | 47.493초·3읽기·2모델 | 서로 다른 출발지 집합을 같다고 표현하고 도구명을 혼동했다. 미확인 판단과 resolved 상태도 모순됐다. 자동 검사 통과를 수동 품질 통과로 인정하지 않았다 |
| 실제 SDK 2차 | 67.984초·3읽기·4모델 | 모순된 상태가 스키마에서 거절됐으나 모델이 반복했다. 정정 2회 뒤 미완료 보고로 종료했다 |

최종 시험의 실제 MCP 시간 합은 0.210초, 모델 호출 합은 38.944초, 연결 준비는 7.417초였다. 같은 모델·질문을 사용했으나 조회 시점과 후보가 다르고 Mattermost 전송은 포함하지 않았다. 통제된 전후 향상률·평균·p95나 조사 완료 SLA로 사용하지 않는다. 마지막 응답의 Wazuh 추가 읽기는 미실행 제안이다. 실제 추가 읽기 분기는 SDK 경계를 대체한 회귀에서 확인했고 이 세 번의 라이브 시험에서는 선택되지 않았다.

| 보완 | 범위·경계 |
| --- | --- |
| 근거 결속 | 현재 요청의 원문·인자·SHA·순서, 같은 인자의 최신 실패와 센서 이름공간을 보존한다. 표본의 교집합/차집합은 양쪽 영수증에 결속하며 같은 흐름·사건으로 판정하지 않는다 |
| 추가 읽기 | 모델이 현재 등록 읽기/인자를 선택하면 전체 스키마·시간·반복·남은 예산을 검사한 뒤 실행한다. 쓰기 혼입은 전체 묶음을 실행 전에 거절하며 미실행 제안을 실행으로 바꾸지 않는다 |

| 역할·권한 | 기존 MCP 45개·읽기 범위·학습 모델·B→Thor·승인·보호 주소·TTL을 유지한다. 기존 조사 스킬 문장을 다듬었고 새 스킬이나 MCP 도구는 만들지 않았다 |

최종 16사본 후보는 설치본의 Mac/Linux Native 183·SDK 141 검사와 공식 Harness² 38·설치기 37 검사를 생략 없이 통과했다. 정본 Native 430은 통과했고 정본 SDK 445에는 이전과 같은 8실패항목/1오류가 남아 있다. 전체 SDK 통과로 표시하지 않는다. 초기 설치본에 없던 스키마 정정 설명과 사건 완료 검사도 기존 정본 함수만 범위를 지정해 이관했다. 최초 누락 절 2오류·설치본 정정 함수 누락 1오류·세 번의 실제 판단 실패/미완료 원문은 로컬에 보존했다.

실험용 `CAPSTONE_EVIDENCE_REPORT_COMPACT`의 기본값은 0이며 격리 SDK에서만 1로 설정했다. Native에는 순수 공통 계약을 검사했으며 새 실행 연결·자동 관제 경로 연결·운영 적용·새 양봇 채팅은 미완료다. 초기 설치는 기존 `deploy.sh`의 복사 경로를 유지하고 실험 기능을 자동 활성화하지 않는다. 새 OS 전체 설치·공격 E2E·전원 단절 복구는 시험하지 않았다. [작은 검증 원장](evidence-judgment.validation.json)에 소스 SHA·후보·실측·미수행을 구분했다.

기존 설치된 ChatOllama의 `json_schema`·`include_raw=True`를 사용했다. dict 스키마 출력은 별도 검증이 필요하므로 기존 JSON Schema 검사를 유지한다. [LangChain 공식 API](https://reference.langchain.com/python/langchain-ollama/chat_models/ChatOllama/with_structured_output). Malvex의 단계별 근거 보존·가설/판정 분리만 참고했으며 프레임워크나 도구 서버 구조를 교체하지 않았다.


## 실제 추가 읽기와 짧은 조사 질문

Malvex를 참고한 단계별 근거 보존·가설과 판정의 분리를 기존 하네스에서 보완했다. 새 MCP 서버나 도구는 추가하지 않았다. 모델이 필요한 등록 읽기를 선택하면 현재 스키마·시간·성공 조회의 반복 여부·예산을 검사하고 실제 결과를 다음 판단에 제공한다. 읽기 예산이 남아 있을 때는 미실행 제안으로 조사를 끝내지 않도록 구조화 보고의 선택지를 좁혔다. 읽기만 하는 이 단계는 승인 요청을 제출하지 않으므로 awaiting_approval 상태를 허용하지 않는다.

| 실제 SDK 시험 | 시간·호출 | 관측과 판정 |

빈 차단 목록은 현재 항목 0개의 근거일 뿐 기능 비활성의 근거가 아니다. 등록된 접근 로그 조회를 미지원 기능으로 보고하는 것도 해결해야 한다. 이 두 문제 때문에 마지막 응답을 품질 통과로 인정하지 않았고 후보를 운영에 적용하지 않았다. 실험 기본값은 `CAPSTONE_EVIDENCE_REPORT_COMPACT=0`이다. 기존 MCP 45·학습 모델·B→Thor·승인·보호 주소·TTL을 유지한다. Native 실행 연결·양봇 새 실제 채팅·자동 관제 연결·새 OS 전체 설치·공격 E2E·전원 단절 복구는 미수행이다. [소스와 검증 원장](evidence-followup.validation.json)에 실패 후보와 남은 범위를 함께 보존한다.

현재 차단 목록·WAF·IDS의 사실 표는 단일 요청의 실제 인자·원문 SHA에 결속된다. 사용자 표시에서 숨긴 판정 메타데이터는 실제 수락된 모델 JSON으로 대조했다. 동일 근거로 다시 렌더한 본문이 표시용 본문과 정확히 같고 정본 검사도 통과했다. 새 판단이나 조회를 만든 것은 아니다.

확장 질문은 ‘실제로 차단됐는지 근거로 구분’하라는 요청이었다. WAF 표본의 request_path에는 두 서비스의 경로 단서가 있었지만 모델은 현재 등록된 search_web_access·get_web_service_target을 읽지 않았다. 경로 단서는 실제 라우팅·백엔드 도달의 독립 검증이 아니며 HTTP 403도 차단 주체의 증거가 아니다. 다음 작업은 이 요청의 대상별 실제 읽기 완료 조건을 보완하는 것이다. 안전한 미확인 응답을 조사 완료의 대용으로 삼지 않는다.

후보는 운영 미적용이며 `CAPSTONE_EVIDENCE_REPORT_COMPACT=0`을 유지한다. Native에는 공통 계약·순수 검사를 수행했으며 새 판단·추가 조회 실행 연결과 새 양봇 채팅은 미완료다. MCP 45개·학습 모델·B→Thor·권한·승인·보호 주소·TTL은 바꾸지 않았다. 초기 설치는 deploy.sh의 기존 소스 복사 경로를 유지하고 실험 기능을 자동으로 켜지 않는다. 새 OS 전체 설치·공격 E2E·전원 단절 복구는 미수행이다. [검증 원장](capability-grounding.validation.json)에 구현·실제 응답·미완료를 구분했다.


## 웹 근거 조회 범위와 남은 표현 문제

웹 요청의 실제 처리 결과를 물었는데 경보·현재 차단 목록만 읽고 끝내던 누락을 기존 하네스에서 보완했다. 유효한 WAF 반환의 출발지·실제 조회 구간·경로 단서로 기존 collect_incident_evidence의 선택 범위를 좁힌다. 모델이 선택한 호출만 기존 스키마·예산·권한 검사 후 실행한다. 출발지와 시간을 서로 조합해 새 범위를 만들거나 경로 문자열로 target을 추정하지 않는다. 백엔드 조회에는 공격자 IP 필터를 복사하지 않는다. 프록시의 주소 보존이 검증되지 않았기 때문이다.

현재 웹 수집 대상은 c:dvwa, c:lab-console, c:lab-java, c:lab-httpd49, c:lab-httpd50이다. /log4shell/은 이 다섯 경로와 대응하지 않는다. 실제 수집이 성공해도 두 경로 단서는 미확인으로 남으며 c:log4shell을 만들지 않는다. 조회 시도·설정 파일의 대응은 WAF 중재·프런트 적재·백엔드 도달·침해 부재의 증명이 아니다. 읽지 않은 범위나 경로 공백을 표에 남기고 그런 공백을 정상·해결 판단으로 종결하지 못하도록 검사한다. 여러 대상의 새 읽기 묶음은 답변 정정 실패와 분리하되 기존 모델 6회·부모 도구 8회 한도는 유지한다.

첫 시험의 올바른 부정 설명을 정정 실패로 처리한 원인과 두 번째 시험의 미증명 단정을 각각 보완했다. 다른 부모 묶음 안의 같은 내부 조회라도 나중에 실패했으면 이전 성공을 현재 근거로 승계하지 않는다. 실제 HTTP 응답값과 차단 주체·영향의 구분은 유지한다. 최종 확장 보고의 WAF 차단(403)이라는 축약 표현은 인접한 응답값 전용 한계와 함께 읽어야 하므로 완전한 의미 검증이나 무할루시네이션으로 표시하지 않는다.

Mac/Linux 설치 사본은 Native 228·SDK 192·Harness² 38·설치 경로 37 검사를 통과했고 생략은 0이다. 정본 Native 430은 통과했으며 SDK 493에는 기존 8실패 항목·1오류가 그대로 남아 있다. 공식 구조 검사는 고정 140파일의 출처·SHA를 확인했다. 상시 지시의 문자 증가 0은 조사 절의 크기 불변이나 정확도·속도 향상을 뜻하지 않는다. 설치 사본의 조사 스킬 증가는 5679바이트다.

## Native 요청·선택 처리 연결 후보

기존 Native의 요청·선택 처리에 공통 보고 경로를 연결했다. 이 경로로 현재 원장과 실제 MCP 원문을 전달한다. `CAPSTONE_EVIDENCE_REPORT_COMPACT=1`인 읽기 전용 사건 조사에만 사용하며 기본값은 `0`이다. 일반 서비스 보고 분기는 그대로 둔다. 새 MCP나 직접 모델 호출 경로는 추가하지 않았다. 모델은 기존 B→Thor 전송을 통해 판단과 추가 조회를 선택하고 실제 호출은 Native 실행기가 담당한다.
