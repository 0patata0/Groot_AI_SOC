# 자동 후속 조사 문맥과 웹 대상 재선택

2026-11-06 query1.19.57/common1.5.32. 이전 [입력 후보 비교](review-input.md)의 214.652초 자동 후속 시간초과를 재검토했다. 30초 최종 보고 목표는 아직 미완료다. 검증 수치와 적용 범위는 [원장](automatic-review.validation.json)·[STATUS](../../STATUS.md)를 따른다.

## 변경과 보호 경계

- 자동 verify 중 단일 `a:incident-ip` 웹 사건에만 제한한다. 사건 참조가 완전하고 직전 완료 실행의 세션·보고가 일치하며 문맥이16KiB에 들어갈 때 새 Native 세션으로 시작한다. 직전 보고 원문/SHA·실행/세션·KST시각·마지막 운영자 사유·연결/후속 제안 참조를 전달한다. DB·이전 세션·trace·승인 이력은 삭제하지 않는다.
- 이전 모델 보고는 미신뢰 과거 문맥이며 현재 근거·지시·승인이 아니다. 이번 실행의 실제 MCP 읽기·정확 인자/센서 구간·현재 turn/nonce·영수증/종결 검사를 다시 충족해야 한다. 자동 재조사는 별도 root flag로 구분하며 운영자 요청으로 위장하지 않는다.
- manage/일반 채팅/다중 제안·누락·초과·이력 불일치는 기존 Native 경로를 유지한다. 단순 읽기의 저추론과 완료 근거 보고 profile을 재사용하되, 미충족 위험 판단의 추론을 임의로 낮추지 않는다. Native 실행·12turn/180초 예산·210초 프로세스 제한과 보호쓰기/승인/TTL은 유지한다.
- 웹 대상 도구가 실제 사건의 경로와 다른 설정 경로를 반환하면 조회가 끝났다고 처리하지 않는다. 실제 불일치가 확인된 대상만 제외한 남은 등록 enum 후보를 모델에 다시 제공한다. 코드가 URL로 목적지나 공격 여부를 확정하거나 MCP를 직접 호출하지 않는다. 등록 후보 소진·실패/불완전 관측은 무한 재시도로 대체하지 않는다.

## 시험 방법과 한계

운영 DB의 일관된 복사본을 B의 별도 비공개 검사 디렉터리에 두고, 기존 WAF 사건을 automatic monitor 입력으로 메모리에서 구성했다. 실제 설치된 root controller/Native/MCP와 Thor 원본35B가 읽기와 판단을 수행했다. 운영 사건 상태·예약·이벤트·승인·원래 세션을 바꾸지 않았고 검사본 outbox를 채팅에 전송하지 않았다. 따라서 **실제 읽기·모델 시험이지만 실제 자동 스케줄 발생 및 Mattermost 전송 E2E는 아니다.** 입력은 동일 개발 사건이며 독립 평가/공유 GPU 부하 통제가 아니다.

첫1.19.54 후보는 직전 보고5,400B·문맥7,375B를 보존하고 첫 선택634토큰/2.139초로 줄였지만, 모델이 DVWA 대신 다른 웹 대상을 조회했다. 이를 완료로 처리하던 탐색 오류 뒤 재작성과 추가 조회가 늘어214.407초 시간초과(11시도/오류0/쓰기0)로 끝났다. 실패를 정상 보고로 집계하지 않는다.1.19.55는 이 실제 불일치를 회귀에 추가했다. 첫 재측정은116.396초/10시도·실제 MCP성공9·실행전 거절1·쓰기0. 모델이 같은 operation ID를 rule-change getter로 옮겨 기존 검사에서 거절됐고 최종 사건 보고는 needs_review 실패 표였다. 속도 향상이나 정상 보고 성공으로 집계하지 않는다. 같은 문맥의 다음 새 세션은69.017초/9조회·오류0·쓰기0·18근거표로 종료했지만, 수동검수에서 ‘서비스 상태는 정상 관측’ 단정과 재탐지2건에 최초 표본까지 포함하는 표현이 남았다. **이 결과도 품질 완료로 집계하지 않는다.** 1.19.56은 해당 정상 단정을 기존 검사에 추가하고 독립 추가 읽기를 최대4개까지 함께 선택하도록 안내했다(아래 운영 재시험 뒤 철회). 의미·시각/표본 범위의 모든 오류가 해결됐다는 뜻은 아니다.

운영자 단문 재시험(1.19.55)은 조사→Mattermost 전송63.716초/7읽기·오류0·쓰기0·15근거표/unresolved였다. 채팅 접수/대기열/단말 렌더는 포함하지 않는다. 후속계획과 정상 응답의 시점 표현은 추가 개선 대상이다. 이후 최종 자동경로 시험의 직전 보고·운영자 사유는 이 단문으로 바뀌므로 앞선 복합 사유 시험과 동일 입력 비교로 묶지 않는다.

## 운영 재시험과 최종 채택 범위

1.19.56의 같은 단문 운영 재시험은22조회/오류0/쓰기0까지 범위를 넓히다 **214.454초 시간초과**, 실패표 전송까지214.505초였다. 추가 선택의 입력은18,644→38,493토큰, 호출당18.6→41.4초로 증가했다. 최대4개 묶음 지침의 이득을 입증하지 못했고, **1.19.57에서는 그 한 문장을 철회했다.** 모델 변동·공유 자원을 통제하지 않았으므로 그 지침만이 원인이라고 단정하지 않는다.

최종1.19.57은 새 자동 세션·이력 보존/실제 대상 불일치 재선택/서비스 상태 정상 단정 검사만 유지한다. 모델 단위 전체 재시험은1.19.56까지이며 최종의 회귀/설치/소스SHA/서비스 검증과 구분한다.43.822초는 후보의 단문 사유 자동경로1회이며 현재 전체 채팅의 속도 보장으로 제시하지 않는다. 사용자30초 목표와 불필요한 추가 조회·큰 입력 반복·시각/후속계획 품질은 미완료다.
