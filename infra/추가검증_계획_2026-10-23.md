# 추가 검증 계획 — 2026-10-23

이 문서는 기존 A/B/C와 승인된 Kali 실습 환경의 후속 검증 목록이다. **새 VM 3대 전체 초기 설치 시험은 제외**한다. 실행 결과 보고서가 아니며, 아래 성공 조건을 충족한 증거를 확보한 뒤 개별 항목을 완료로 바꾼다. 실제 공격 입력·악용 코드·외부 콜백 주소·자격 값은 포함하지 않는다.

| 설치 시험 | 소스·구문·격리 회귀와 기존 서버 변경 검증 | 새 VM 3대 전체 `--apply` 시험은 이번 범위에서 제외 |

sudo 운영 근거는 [sudo 웹 검증 JSON](groot-c/nonweb-labs/sudo-web-validation-20261023.json), 앞선 Redis/Samba 근거는 [기존 통합 검증](groot-c/nonweb-labs/validation-20261023.json)과 [TTY 검증](groot-c/nonweb-labs/terminal-tty-validation-20261023.json)을 따른다. 새 진단 경로는 [진단 계약](mcp/system-diagnostics.md), [초기 설치 격리 검증](../deployment/diagnostics-bootstrap-validation-20261023.json), [실제 SDK·운영 검증](mcp/system-diagnostics-validation-20261023.json)을 참고한다. 과거 JSON의 SHA·검증 수를 후속 변경의 결과로 덮어쓰지 않는다.

Kali의 처음 영문 검색에 잡힌 Wazuh 접속 설명은 기존 A를 가리켰으며 Kali 성공 근거에서 제외했다. 이후 한글 전용 항목의 원래 주소는 접속 타임아웃이었고, 사용자가 쉼표로 추가한 새 주소에서 관리 접속을 확인했다. 구체 IP·사용자명·비밀번호는 이 문서에 기록하지 않는다. **정상 root 암호를 이용한 `su` 성공은 CVE-2021-3156 악용 성공이 아니다.**

## 실행·판정 원칙

- 시험 전 대상 실습 ID·전체 CID·이미지 ID·출발지·기간·정리 방법을 기록한다. 관리용 IP/CIDR과 시험용 출발지를 구분하고, 다른 시스템·다른 포트·다른 주소로 자동 확대하지 않는다.
- 기존 서비스 상태와 사용자가 실행한 실습을 먼저 기록한다. 시험이 만든 세션·fixture만 정리하고, 다른 사용자의 실습·DVWA·DB·원본 로그를 초기화하지 않는다.
- `환경 준비`, `CVE 재현`, `장비 탐지`, `로그 수집`, `LLM 판단`, `승인·대응`을 각각 판정한다. 버전 확인·HTTP403·경보 하나만으로 나머지 단계의 성공을 추정하지 않는다.
- 정상/차단 비교는 같은 시험 ID와 대응되는 조건으로 수행한다. 사전에 최대 관찰 시간을 정하고 지연을 측정한다. 기준이 정해지지 않은 지연값을 성능 합격으로 표시하지 않는다.
- 예상하지 못한 대상 변경·격리 이상·관리 연결 영향·비밀 노출·증거 불일치가 생기면 해당 시험을 중단하고 고정 읽기 진단으로 원인을 확인한다. 실패 입력을 무제한 반복하지 않는다.
- 키·암호·쿠키·challenge proof·터미널 capability·원문 자격 파일·PTY 전사는 증적에 넣지 않는다. 필요하면 합성 표식과 고정 오류 코드로 검증한다.

원래 C 호스트의 취약 sudo·auditd 권한 상승 시나리오는 현재 rootless 실습과 별도다. 이를 검증하려고 운영 호스트 sudo를 구버전으로 바꾸지 않는다. 별도 대상·복구 범위를 확정하기 전에는 호스트 시나리오를 미검증으로 남긴다.

각 CVE의 재현 결과와 WAF/IDS/Wazuh 탐지 결과는 별도 열에 기록한다. HTTP3의 WAF 경로와 웹 터미널 안에서 사용하는 Redis/SMB/로컬 sudo 프로토콜은 관측 경로가 다르다. 터미널 안의 동작이 WAF를 통과했다고 가정하지 않는다.

| P1-SOC-04 보호 주소 | 서버·관리/VPN·LLM·설정된 보호 CIDR을 차단 후보로 제출한다. | 실제 규칙 변경 전에 거절. 보호 주소를 탐지·원본 로그 제외 대상으로 삼지 않음 | 실제 차단이 생성되지 않았음을 확인 |
| P1-SOC-05 WAF 키와 L4 | 전용 시험 출발지의 IP 차단과 유효 WAF 예외를 조합한다. 공유 NAT/관리 출발지면 실행하지 않는다. | HTTP 예외 키가 기존 IP 차단을 해제하지 못함. Suricata·승인·보호 주소 정책 유지 | 예외 해제, 시험 차단 해제, 정상 연결 복구 확인 |
| P1-DIAG-01 실제 조회 | 구현된 읽기 MCP로 A/B/C의 고정 대상25개를 조회하고 정상·실패·oneshot 표본을 대조한다. | 실제 Hermes UID의 호출 성공, target/host/unit 일치, `Type=oneshot`의 inactive/dead를 그 자체로 장애 처리하지 않음 | 조회만 수행. 장애를 만들기 위해 운영 unit을 중지하지 않음 |
| P1-DIAG-02 입력·전송 경계 | 허용 범위를 벗어난 target·기간·개수·추가 command/path/unit 필드를 합성 요청으로 제출한다. 전용 reader의 TTY/forwarding/임의 명령 거부도 확인한다. | 고정 읽기 기능만 실행. 일반 SSH·sudo·Docker·임의 journal 권한이 생기지 않음. pinned host key 불일치는 거절 | 시험 연결 종료. 운영 키·host key 검증을 완화하지 않음 |
| P1-DIAG-03 신선도·수집 장애 | 격리 fixture로 TTL180초 만료·미래 시각·수집 실패·요청 구간 미포함을 확인한다. | `unavailable`/`null`/`coverage.not_available`로 구분. 오류0건·정상으로 대체하지 않음. 수집60초 지연과 최신 구간 한계 표시 | 합성 snapshot 제거. 운영 snapshot/collector는 변경하지 않음 |
| P1-DIAG-04 민감정보·주입 | 합성 비밀 표식·경로·명령·지시 문장이 있는 fixture를 수집/조회한다. | 원문 MESSAGE·토큰·쿠키·명령 인수는 snapshot/MCP/LLM 문맥에 없음. 고정 오류 분류·허용 basename/행·시각·coverage만 전달 | 합성 fixture 제거. 실제 비밀로 시험하지 않음 |
| P1-SOC-06 모델/도구 실패 | 합성 fixture나 격리 검증에서 모델 불가·읽기 MCP timeout·게시 실패를 각각 확인한다. | 실패/미확정/검토 필요를 구분. 정상 판정·승인 없는 쓰기·무제한 차단으로 대신하지 않음 | fixture/시험 제안 종료, 운영 모델/채팅 서비스를 강제로 중지하지 않음 |

진단 snapshot은 상태와 제한된 오류 표본이다. 최신 최대60초의 미반영, 4시간 표본 count, query/retention truncation을 표시해야 한다. 진단 결과를 승인된 변경 직전의 별도 대상 재조회나 변경 후 효과 검증으로 대체하지 않는다.

## P2 — 시간 제한·재시작·오프라인 유지·반복 평가

| ID·대상 | 절차 | 성공 조건 | 정리 |

| P2-01 입력 유휴5분 | 입력 없이 poll만 유지한다. | poll이 유휴 시간을 연장하지 않고 설정된 유휴 한도와 reaper 주기에 맞춰 종료. sudo는 전체 컨테이너 중지 | 시험 세션·직접 시작한 환경 정리 |

| P2-03 terminal daemon 재시작 | 별도 점검 시간에 sudo 연결 중 daemon 재시작을 시험하고 startup cleanup 결과를 본다. 정리 실패 경계는 격리 회귀로 확인한다. | sudo 전체 정리 또는 새 sudo 연결 차단 유지. 재시작으로 실패 차단이 풀리지 않음. Redis/Samba 컨테이너 상태 유지 | 시험 세션 정리, unit active와 고정 상태 재확인 |

새 VM 3대 전체 초기 설치, 전체 백업 체계·장기 장애 무손실 회수·과거 로그의 A→B 자동 이관은 이 계획의 합격 조건에 포함하지 않는다. 필요 시 독립 과제로 범위를 정한다.
