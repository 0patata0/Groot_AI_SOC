# 짧은 조회·실제 근거·FW 페이지 처리

2026-11-03 공통 `soc-chat-contract:1.5.15`를 Hermes·Ollama 운영 경로에 반영했다. 원본35B를 유지하며 새 학습이나 권한 확대는 하지 않았다. [현황](../../STATUS.md) · [검증 원장](short-read-validation-20261103.json) · [보완 전 현황](../../archive/STATUS-20261103-before-short-read.md).

| 요청·문제 | 동작 |
|---|---|
| 규칙 볼래/볼 수 있나/봐줘 | 대상 없는 새 대화는 장비를 한 번 확인한다. 같은 사용자·같은 스레드의 명확한 대상은 이어받되 이전 상태·승인은 재사용하지 않는다 |
| IP들/주소들·어느 IP가 막혔니 | 현재 임시차단 조회 범위를 유지한다. 전체 FW 정책은 별도 전체 조회다. 해제·변경·과거·복합 질문을 이 경로로 바꾸지 않는다 |
| 기본·커스텀 범위 | 장비별 전체 정의가 기본값이다. 사용자가 명시한 기본/커스텀·ID·상관 조건은 보존한다 |
| 미조회인데 차단0/규칙수 단정 | 도구·반환 SHA·최신 영수증을 확인한다. 최신 실패·손상은 이전 성공을 무효화한다. 실제 완전한 FW 영수증도 근거로 인정한다 |
| FW 가상 snapshot·불필요 추가 호출 | 최초에는 snapshot을 선택할 수 없고 offset0만 허용한다. 다음 호출은 실제 snapshot/next_offset에 결속한다. 한 선택 묶음에서 FW 한 페이지만 허용하고 완료 후 도구를 제거한다 |

분류·검증 코드는 도구를 직접 선택하거나 실행하지 않는다. LLM이 허용된 스키마에서 실제 도구와 인자를 선택하고 기존 MCP가 권한을 검증한다. 정확한 중복 선택은 제거하지만 서로 다른 미래 페이지를 미리 실행하지 않는다. 모호한 대상을 추측해 여러 장비를 조회하거나 조회 실패를0건으로 표시하지 않는다.

보호 주소의 차단 금지는 허용된 사건 조사까지 중단할 이유가 아니라는 지침도 명시했다. 최근 고정 진단 스냅샷을 과거 journal 조회처럼 제안하지 않으며, 성공 종료한 oneshot의 inactive/dead만으로 재시작을 권하지 않는다. yellow 상태의 복제 한계도 보존한다. 이 지침 추가를 독립 사건 판단·쓰기 품질 개선의 실측으로 표시하지 않는다.

실채팅 합계12요청·실읽기14회·확인2회며, 읽기를 수행한10요청 모두 진행 표시를 관측했다. 기본 조회는 Ollama3.30~9.77초/Hermes16.10~28.96초, 다중 페이지는9.77/33.02초였다. 약1초 폴링·순차/공유 추론·API게시~응답관측 값으로 전체 지연이나 모델 우위로 일반화하지 않는다. 브라우저의 표 렌더링은 시각 확인하지 않았다.

스테이징 참조 파일 누락, SDK 로그와 JSON이 섞인 검사기 오류, 추가 근거 검사가 완전한 FW 결과를 거절한 오검출을 모두 보존했다. 마지막 오검출은 완전한 FW 영수증 인정과 양성 회귀로 수정하고 최종 소스의 실제5요청·채팅12요청을 검증했다. 이전 모델3군의1.5.14 계획·점수는 변경하지 않았고 이 질문을 학습자료에 편입하지 않는다.

## 설치·운영 반영·복구

진입점은 기존 루트 `deploy.sh` 하나다. 기존 source bundle이 `harness.py`·`chat_contract.py`·`read_contract.py`를 복사하고 Hermes 플러그인에도 같은 바이트를 배치한다. 서비스·MCP 도구·권한·키·공개 포트·패키지·이미지를 추가하지 않아 오프라인 패키지 목록은 불변이다. 초기 설치기로 운영 서버를 덮어쓰지 않았다.

13:46 큐 유휴를 확인하고 공통 소스6사본과 trial receipt1개만 SHA/CAS로 증분 교체했다. 기존 소유권·모드를 유지하고 Hermes 컨테이너1회, Ollama/review 소비자 각1회 재시작했다. management timer를 재개했고 모델/설정·SOUL5개 SHA를 보존했다. stale했던 receipt의 source SHA2항목도 이전 바이트를 보존한 뒤 동기화했다. 13:54 실제 채팅·인증 heartbeat·소스/receipt SHA·큐를 확인해 확정하고15분 독립 복구 타이머를 해제했다.

root 복구본과 manifest는 `/var/lib/capstone-short-read/20261103-r1/deployment`에 있다. 승인된 운영자의 수동 복구 명령은 다음과 같다.

```sh
python3 -B /var/lib/capstone-short-read/20261103-r1/deployment/rollback.py --manual
```

현재 파일이 이번 배포 SHA일 때만 이전 바이트를 복구하며 동시 수정은 덮지 않는다. 진행 중인 durable/management 작업이 있으면60초 뒤로 미룬다. 복구 시 소비자를 재시작한다. 실제 운영 원복은 실행하지 않았고 root 복구본·검증 원문·가중치를 보존한다.

native 관리 CLI의 조회 생략과 미배포 review 교차검토 후보는 이번 일반 채팅 검증의 완료 범위에 포함하지 않는다. 보호 쓰기/승인·실제 공격 대응·장기 무손실·새 서버 전체 설치도 별도 검증이 남는다.
