## 원인과 동작

기존 수집기는 고정 Apache 로그를 읽고 최신10,000행만 남긴 다음 MCP 요청의 시간·서비스를 검색했다. 실제 정제 대상14,143행 가운데 과거 DVWA6행이 그 최근 목록에서 빠졌다. 원본에 기록이 존재해도 조회에서0행이 될 수 있었다.

root publisher가 같은 원본 읽기 범위에서 만든 **정제 이력 파일**을 함께 게시하도록 보완했다. reader는 게시된 manifest가 가리키는 SHA 기반 고정 이름만 열고, 전체 이력의 무결성을 확인하며 시간·서비스·선택 출발지에 맞는 행을 검색한다. 결과 상한은 필터 뒤 적용한다. 실제 원본 파일 경로·셸 명령·호스트·SQL 같은 새 입력은 받지 않는다.

최근10,000행·4MiB 스냅샷은 유지한다. 실제 `search_web_access`는 `record_scope=query_filtered_sanitized_history`와 이력 SHA·보관 행 수를 반환한다. `recent_snapshot_rows_truncated`는 최근 목록의 한계이고, `coverage.rows_truncated`는 이번에 검색한 이력의 한계다. 둘을 혼동하지 않는다. API 이름·인자·반환 schema1과 MCP1.2.2는 유지하며 내부 게시 형식만 schema2다. 구 게시물/메모를 새 근거로 사용하지 않는다.

## 설치·복구

루트 `deploy.sh`의 기존 service diag-apply→`web_access_deploy.py`와 SIEM 복사 경로가 같은 canonical 소스를 사용한다. 추가 패키지·이미지·키·포트·도구/일반 권한·서비스는 없다. 새 OS 실제 설치는 실행하지 않았다. 기존 설치기의 source SHA·영수증은 운영 증분 변경과 함께 맞췄다.
