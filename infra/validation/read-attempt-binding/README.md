# 실제 읽기 시도·실패 서술 결속 개발 검증

**명시한 도구의 가짜 성공·실패 서술을 실제 호출 기록과 대조하는 공통 검사를 연결했다. 대상명만 쓴 OS 답변·짧은 조회 범위·표본 부재 표현에 오류가 남아 운영에는 채택하지 않았다.** [검증 원장](validation.json) · [동결 소스](manifest.json) · [현재 상태](../../../STATUS.md).

## 실제 비교 결과

같은 세 질문을 앞선 R6 격리 기준과 새 R2 후보에 요청했다. 첫 DNS 질문은 개발 회귀, 나머지 두 질문은 새 자연어 표현이다. 총6요청·실제MCP6·모델 완료15이며 운영 적용·실제 Mattermost 게시·공격/새 학습은0이다.

| 요청 | 앞선 R6 기준 | R2 후보 | 수동 근거 검토 |
|---|---|---|---|
| 출발지·목적지·최근15분 DNS 조사 | 95.744초·MCP1/모델4·partial | 60.186초·MCP1/모델2·completed | 가짜 Wazuh 실패는 새 응답에 없었지만, 반환 표본0을 구간 색인 경보 부재·추가 위험 징후 부재로 넓힌 표현은 미검출 |
| `DNS 경보 좀 봐줘` | 30.660초·MCP0/모델1·completed | 91.116초·MCP2/모델4·completed | 기준은 조회중 표와 미래 약속만 반환. 후보는 불필요한 룰 조회가 섞였고 개별 SID의 활성화를 과장 |
| B systemd 오류 로그·실패 조회 확인 | 36.078초·MCP1/모델2·completed | 40.286초·MCP1/모델2·completed | 둘 다 현재 `b:systemd` 스냅샷만 조회. 기준은 이를30일 이력으로, 후보는 미실행 과거 조회를 실패로 서술 |

비교 기준은 **미승인 관리 상태19파일+공통 조회8소스+주장 결속4소스 R6 조합**이며 현재 설치본이 아니다. 모델 태그는 `soc-qwen36:35b-balanced-q4km-20261108`, 시작·수집 종료 digest는 모두 `7ac2a1dc6aa17746f522e81804ba2a76b25fc01e69d2460a083a0ec5cfa207c3`였다. 캐시·로그 구간·공유 부하를 통제하지 않았고 첫 기준 요청은 격리 CPU 검사와 겹쳤다. 각1회·개발 사례이며 독립 정확도·속도 개선율·채팅 왕복/p95를 입증하지 않는다. `completed`는 의미 검토 통과를 뜻하지 않는다.

초기 R1의 시도 구분을 R2에서 보완했다. 인자 거절 뒤 성공한 조회를 원장 병합 순서 때문에 실패로 읽지 않도록 순서를 기록하고, 도구 오류의 조건문·서비스 실패 결과와 조회 자체 실패를 분리했다. 격리 버전은 contract1.5.86/query1.19.143이며 설치137과 별도 준비141은 유지했다.

`b:systemd`의 실제 반환은 `latest_snapshot_only_not_requested_history`, failed_units_total=0·returned_units=0였다. 원문 과거 journal은 `since_kst` 사용 시25개 등록 서비스 target으로 제한되며 aggregate `b:systemd`는 그 enum에 없다. 실제 스키마의 로컬 검증으로 이를 확인했고 불필요한 서버 오류 호출은 하지 않았다. **미지원 범위와 실제 조회 실패는 다르며, 이번 답변은 과거 조회를 시도하지 않았다.** 코드에 lookback_minutes를 제공했다는 설명도 실제 인자와 다르다.

짧은 DNS 답변의 룰 자료는 반환20/일치52,500이며 current-file·per-SID 적재 검증이 false다. 이를 현재 활성화된 SID 목록으로 표시하면 안 된다. 이 결함과 표본0의 과장·조회 약속만으로 completed 처리를 남은 과제로 기록했다. `review-agent` 스킬은 찾지 못해 수동 결함 우선 검토를 했고 Semgrep은 미수행이다.

## 재현

```sh
python3 -B infra/validation/read-attempt-binding/reproduce.py --repo /절대경로/capstone_project --output /새로운/임시/read-attempt-review
SOC_ATTEMPT_ROOT=/새로운/임시/read-attempt-review/candidate python3 -B infra/validation/read-attempt-binding/test_attempts.py
```

재현기는 새 프로젝트 밖 경로에서만 부모 소스를 복원하고6파일 패치를 적용한다. 현재 작업 트리의 다른 변경이나 운영 자격을 사용하지 않는다. 공식 Harness²는 이미 보관된 고정 사본을 사용한다. 출력 경로는 작업 후 정리한다. 이 패치를 정본·운영에 바로 적용하지 않는다. 실제 Native controller는 gate를 내장하므로 향후 채택 시 같은 SHA로 재렌더하고 정확 적용/복구 계획을 검증해야 한다.

## 다음 조건

1. **도구명뿐 아니라 실제 target·view·조회 목적과 인자까지** 서술에 결속한다. 미실행·미지원·실패와 전송 결과 미확인을 구분한다.
2. 짧은 경보/로그 요청을 공통으로 해석해 경보를 실제 읽고, 룰 파일·현재 스냅샷으로 바꾸지 않게 한다. 조회중/미래 약속으로 최종 완료하지 않는다.
3. 표본0·단정/조건/면책 표현의 범위를 같은 명제에 한정하고 전체/위험 부재·개별 룰 활성화를 근거 없이 통과시키지 않는다.
4. 실제 스키마의 조건부 target/view 제약과 지원 필터를 조사 계획에 반영한다. 이후 공식H2·동결·회귀·새 실제 읽기와 별도 정확 승인/적용·복구·양봇 새 채팅을 검증한다.
