## 비교 조건

11월7일 Hermes66/Ollama66의 실제 조회 원문4개/3개를 SHA256으로 확인해 동결했다. 원문·시각·숫자를 변경하지 않은 입력과, 처리 대기가 실제 존재하도록 값을 명시적으로 바꾼 별도 반례1개를 구분했다. 반례는 전송3·실행2·기한초과1·검토17과 각 경과 시간·상태 코드를 일관되게 설정한 개발 fixture다. 실제 사건이나 학습자료로 사용하지 않는다.

각 실행에서 현재 등록 읽기 도구35개의 설명을 확인했지만 새 MCP 결과 조회·보호 호출·채팅 게시·공격 실행은0이다. 합성은 B에서 Thor의 원본 모델을 호출했다. DGX 학습 현황은 조회하지 않았다. 모델 응답 본문을 스키마 검사 전에 보존했고, 내부 추론 내용은 저장하지 않았다.

## 실제 생성 설정 확인

Thor `/api/show`와 `/api/ps`에서 `qwen3.6:35b`는35.5B·Q4_K_M, family=qwen35moe, 등록·적재 context_length=262144로 확인됐다. 등록 기본값에는 presence_penalty1.5가 있고, 봇은 temperature0/top_p0.95 등을 지정하지만 이 옵션을 명시하지 않았다. 사용자 정의 system 본문은0바이트였다. 이것만으로 오류의 원인을 특정하지 않으며, 0 대조도 품질을 해결하지 못했으므로 기본값을 바꾸지 않았다.

설치된 ChatOllama에는 `presence_penalty` 생성자 필드가 없고, 설치된 Ollama Options에는 있다. `_chat_params`는 호출별 `options`를 전달하면 기본 옵션 사전 전체를 대체한다. 추후 이 옵션을 시험·반영할 때 생성자에 임의 인자를 넣거나 temperature·출력 상한을 빠뜨린 옵션 사전으로 덮지 않아야 한다. 이번 비교에서는 native 요청의 temperature0/top_p0.95/출력2048을 유지한 채 presence_penalty만0으로 지정했다. 마지막 추론 후보는 별도 조건으로 출력4096이며3,422토큰을 생성했다.

## 다음 작업과 보존

단순히 설명·정규식·추론량을 더하는 방법을 해결책으로 채택하지 않는다. 다음은 **실행할 수 있는 후속 조회와 제공되지 않는 기능의 요청을 분리하고, 제안한 호출을 실제 입력 스키마에 결속하는 것**이다. 일반적인 원인·영향 추론 품질은 별도이며, 이 구조 변경만으로 해결됐다고 표시하지 않는다. 새 학습본은 사용자의 학습 현황 조회 재개 이후 결과·독립 평가·실제 MCP/채팅 비교를 거쳐 판단한다.

운영 소스·설정·권한·FW·승인·가중치 변경과 서비스 재시작은0이다. 서버 시험 코드는 기존 Python에서 메모리로 실행했고 별도 설치·임시 반입 파일을 만들지 않았다. Mac 신규 패키지·다운로드·작업용 임시환경도 없다. 재현 소스·원문·응답은 로컬 전용 대화기록에 보존하며, Git에는 이 문서와 작은 설정·SHA·결과 원장만 남긴다.
