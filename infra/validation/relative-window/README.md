|---|---|---|

| (코드) | Ollama 봇 | '오늘'이 아니면 무조건 60분으로 고정했고, "최근 30분" 같은 질문은 단순 목록 조회에서 아예 제외돼 모델이 계산했다 |

'오늘'만 요청 시각 기준으로 고정하고, 다른 상대 구간은 모델이 시각을 계산한 것이 공통 원인이다.

## 수정 (공통 요소 먼저, 봇별 적용)

| 위치 | 내용 |
|---|---|
| 공통 계약 `chat_contract.py` | `relative_lookback_minutes(질문)`: 질문에 명시된 **한 개**의 최근 구간만 분 단위로 읽는다("최근 30분", "지난 2시간", "직전 10분", "한 시간 동안", "30분간", "최근 반시간"). 다음은 해석하지 않고 기존 경로에 둔다: 시계 시각, 날짜, 시작/끝 표현("부터·까지·이후·이전·사이"), 시점("1시간 전"), 복합 길이("1시간 30분"), 여러 구간, 주기("간격·마다"), 24시간 초과. `without_relative_window`는 받아들인 구간 문구만 지운다 |
| Hermes 관리 실행기 `initial_event_filter_schema` | 첫 경보 조회에서 상대 구간이 있으면 '오늘' 처리와 같은 자리에서 절대 시작/끝 인자를 없애고 `lookback_minutes`를 N으로 고정한다. 컨트롤러가 정한 구간은 덮어쓰지 않고, 카탈로그 범위를 벗어나면 고정하지 않는다 |
| Ollama 하네스 | 단순 목록 판정에서 받아들인 구간 문구를 지워 "최근 30분 Wazuh 경보 보여줘"도 결정적 목록 조회로 처리한다. 길이를 명시하면 N분, 아니면 기존 60분이다. 영수증 검증은 실제 조회 구간이 N분과 같아야 완료로 본다 |

시각 계산은 모델이 아니라 MCP 서버가 조회 시점에 한다(`lookback_minutes`). 그래서 미래 끝 시각이 생기지 않는다. 기존 시험 1건(`'오늘 최근 1시간'`은 고정하지 않음)은 의도한 변경이라 기대값을 "60분 고정"으로 바꿨다.
