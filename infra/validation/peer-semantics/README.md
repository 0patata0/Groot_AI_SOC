# 교차 검토 조건과 표본 범위의 의미 검증

**개발 비교 완료·품질 미완료·운영 미적용**이다. [R2 후보](candidate-soc-investigate.md)를 유지하고 더 나쁜 R3는 기각했다. canonical과 운영3사본은 기준 SHA `50825f27…`이며 신규 설치 경로에도 후보를 승격하지 않았다. [최초 R2 원장](validation.json) · [후속 비교·출력·판정](validation-r3.json) · [현재 상태](../../../STATUS.md).

작성자 Codex의 수동 의미 판정이며 독립 전문가 평가·일반 정확도·모델 학습 결과가 아니다. 같은9사례의 최초 R2 결과는 별도 원장에 보존했다. 추가6사례와 판정 기준은 추론 전에 작성했고, [기존 입력](../../hermes/peer-semantics.cases.json)·[추가 입력](../../hermes/peer-semantics-generalization.cases.json)은 학습에 사용하지 않는다.

설치된 B 작업자와 기존 비특권 `soc-ollama` 런타임에서 B→Thor의 `soc-qwen36:35b-balanced-q4km-20261108`을 호출했다. 운영 SHA와 같은 작업자에 합성 영수증을 넣고 스킬 절만 격리 교체했다. 세 군 순서를 사례마다 순환했고 temperature0·추론 비활성·출력 예산1536으로 각1회 비교했다. 실제 MCP·대기열·채팅 왕복 시험은 아니며 공유 자원·캐시가 통제되지 않아 속도 개선률을 주장하지 않는다.

추가 FW 사례의 첫 입력은 요청과 결과의 `request_id`가 달랐다. 잘못 만든 입력의3출력을 점수에서 제외하고 ID를 일치시킨 동일 사례를 세 군에 다시 실행해 모두 통과했다. 원래 입력 SHA·제외 출력·수정 SHA·대체 출력의 계보는 후속 원장에 남겼다. 오류를 숨기거나 두 번 합산하지 않았다.

## 남아 있는 의미 오류

| 유형 | 실제로 확인한 문제 | 다음 검토 방향 |
|---|---|---|
| 조건과 권고 | 조건부 추가 조회 계획을 상대의 실제 관측·완료 주장으로 바꿈 | 새 근거를 보기 전에 원문의 주장 종류와 범위를 해석 |
| 실행 주체·계층 | Suricata `action=allowed`를 봇/FW 차단 미실행의 근거로 확대 | 센서 판정과 봇·FW 작업 영수증을 구분 |
| 이미 밝힌 한계 | 상대의 표본·전체 미확인을 자기 조회 한도로 검증하다 거절 반복 | 한계의 반복과 실제 반대 관측을 구분 |
| 표본0 | 전체 부재 확정은 피했으나 일부 범위 표현이 모호 | 반환 범위·전체 미확인 보존 |
| 출력 | 장황함·내부 식별자 노출이 일부 남음 | 식별자 후보 `dfc3e2a`는 별도 승인 대기 |

원문 해석과 근거 대조를 분리하는 방식은 **다음 가설이며 아직 구현·검증하지 않았다.** 같은 질문의 답을 저장하거나 특정 서비스 예외를 추가한 것은 아니다.

첫 회귀는 승인 대기 식별자 변경을 포함한 HEAD 테스트를 그 이전 운영 작업자에 붙여 양쪽에서 실패했다. 운영 작업자와 같은 커밋의 테스트를 사용해 다시 검사했고, 바뀐 R3 문구에서 빠뜨린 기존 공통 요구도 복원했다. 검사를 약화하지 않았으며 실패 로그·소스 SHA는 로컬에 보존했다. 최초 R2의104개 검사와 이번105개, HEAD106개는 서로 다른 범위로 기록한다.

## 재현·보존과 배포 경계

기각한 R3의 [복원 패치](attempt-r3.patch)는 승인·적용용 패치가 아니다. `4a9318e`의 R2 후보 파일에 `git apply --unidiff-zero`하면 원장의 R3 SHA `f8bd6131…`가 재현됨을 임시 경로에서 확인했다. 현재 후보 파일은 R2 SHA `83ea52e2…`로 되돌렸다. 도구·승인·보호 정책·검증기·운영 사본은 바꾸지 않았다.

Hermes 도구 확인은 관리자231 경유·컨테이너 고정 MCP 연결이며 보호 호출0·모델 호출0·채팅 게시0이다. 의미 비교 자체의 실제 MCP는0이다. Ollama 도구 통합은 권한 후보와 정확한 승인 검토가 별도로 필요하다. 실제 자연어 요청·카드 승인·실행 검증 전에는 연결 완료로 쓰지 않는다.

원격 시험3개는 종료 증거와 Linux 로그를 확보한 뒤 제거했고 운영8경로 SHA 유지를 확인했다. 새 패키지·학습·공격·운영 배포는 없다. 다음 후보도 공식 Harness²→동결→회귀→실제 모델 반례→정확 승인·관리자 경유 적용→새 실제 채팅 순서로 검증한다.

## 후속 시도와 별도 전달 누락

[원문 해석 분리·허용 근거 조합·별도 의미 검증기](../peer-source-first/README.md)를 추가 개발 비교했으나 조건·실행 주체·표본 범위 오류가 남아 모두 미채택이다. 위 R1/R2/R3 수치와 새 비교의 분모를 합치지 않는다. 이후 실제 Hermes 추적10건의 완료 읽기20개가 비공개 감사/교차 검토 전달에 남지 않는 것을 확인했다. [읽기 감사 보존 후보](../native-read-audit/README.md)는 이 IO 누락을 격리 재처리에서 수정한 것이며 의미 오류 해결·운영 배포의 증거는 아니다.
