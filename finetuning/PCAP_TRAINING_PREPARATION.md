351,160흐름을 같은 수의 학습 문답·독립 사건으로 세지 않는다. 한국어 질문·답변은 **제공자 관측에 근거한 프로젝트 작성물**이며 제공자가 작성하거나 전문가가 독립 검증한 정답이 아니다. 기존 기관 자료 중심 혼합은 유지한다. 2011년 통제 망의 세 캡처는 전체 SOC 업무와 최신 기업 침해사고를 대표하지 않는다.

## 발견한 문제와 수정

- 최초 실제 토큰 검사에서 새 후속 질문3건만 `conversation_prefix_mismatch`. Qwen template이 마지막 사용자 질문 이전 assistant의 빈 thinking wrapper를 제거하면서 앞선 정답 토큰 배열과 달라졌다. 해당3건에만 명시적 `preserve_empty_thinking_history=true`를 적용한다. 비어 있지 않은 reasoning·think 본문·문자열 true는 거절한다. 기본 문답 동작은 유지한다. 이후 전수 토큰/마스크 통과.
- 예전에 도구선택 전용으로 편입된6건의 ID가 `-initial-call`로 끝나면 새 fallback 분할로 오인하는 admission 오류를 수정했다. 실제 선택한 train/fallback 레코드의 토큰을 사용한다. 자료를 버리거나 이름을 바꿔 통과시키지 않는다.
- 현행 시스템 진단 schema의 기간 배타/쌍 조건을 옛 감사기가 처리하지 못했다. 알려진 조건의 정확한 형태와 실제 인자를 먼저 확인한 뒤 기존 구조 검사를 적용한다. 알 수 없는 조건·시간 조합·미등록 역사 조회는 거절한다. 운영 MCP 권한은 바꾸지 않는다.
- 로컬 실행 묶음 첫 run ID 규격 오류 및 최종 반입의 임시 경로 변수 재사용 오류는 실패로 남겼다. 올바른 고정 ID로 새 묶음을 만들고95파일을 다시 대조했다. 실패 도중 학습/서비스 변경은 없다.

관련 회귀62검사 통과. 보호 변경 예제3건은 격리 모의 실행임을 명시하고 **제안·승인 대기, 미적용**을 답한다. 전체 신규24답변과 변경된 도구 선언을 검수했다. 정확 입력 중복/평가 겹침0은 확인했지만 모든 파생자료의 의미 중복이 수학적으로 없다는 주장은 하지 않는다.

## 다음 실행 조건

기존 Qwen3.6-35B-A3B revision `995ad96eacd98c81ed38be0c5b274b04031597b0`와 고정 DGX 환경을 재사용한다. 새 LoRA r16, 학습률5e-7, 최대4,096토큰·전체 assistant 답변 학습·1epoch 계획은4,360 optimizer step이다. 학습시간/품질 향상을 이번 준비만으로 보장하지 않는다.

GPU 사전 시험은 최장4,067토큰 문답·실제 복수 도구 대화2,920토큰·새 후속 질문914토큰의3개를2-step/누적2로 확인하도록 준비했다. 현재 묶음은 **preflight_only**이고 학습 daemon/타이머는 설치하지 않았다. 종료 시각은11/7 17:00KST 준비값이므로 이후 시작할 때 실행 시각·자원·공유 추론 충돌을 다시 확인하고 새 묶음을 생성한다. 현재 묶음을 그대로 본학습으로 승격하지 않는다.

GPU 사전 시험이 통과해야 정확 데이터SHA와 모든 실행 소스SHA를 묶은 release를 발급할 수 있다. 기존 실행의 GPU 성공 영수증을 새 코드에 재사용하지 않는다. 초기 진입점은 계속 `deploy.sh --training-dgx`이며, 사용자가 본학습을 지시하면 그 시점의 종료 기한과 공유 서비스 상태를 확인해 실행한다.
