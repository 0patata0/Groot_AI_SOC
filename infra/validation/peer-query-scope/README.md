## 문제 (11/13 21:55 공동 채널, B 기록)

| 근거 | 내용 |
|---|---|
| Hermes 실제 조회(B 관리 대화 DB) | `search_modsecurity_alerts {"lookback_minutes": 30, "limit": 50}` |
| Hermes 답변 | "`search_modsecurity_alerts` lookback 30분, limit 50 → 반환 0건" (사실과 일치) |
| Ollama 교차 검토 이견 | "상대 답변은 ModSecurity 조회의 limit를 50으로 기재했으나, 실제 호출 결과는 limit 10입니다. … 핵심 파라미터 오류" |
| 실제 | 10은 검토자 **자신의** 독립 조회가 기본값으로 보낸 한도다. 경보 조회 결과는 요청 조건(`limit`·`lookback_minutes`·`window_mode`·`requested_since_kst`/`requested_until_kst`·`applied_filters`·`scan_capped`)을 그대로 돌려준다. 검토자는 그 값을 상대 조회의 영수증처럼 썼다 |

검토자에게는 상대의 실제 조회 영수증도 없었다(`other_read_context: []`). Hermes 조사형 답변은 범위가 완결된 결정적 조회가 아니어서 근거(`evidence`)를 넘기지 않는다. 지시문에는 이미 "같은 범위의 근거로 반대 명제가 확인될 때만 이견"이라고 적혀 있었지만, 모델이 따르지 않았고 이를 막는 결정적 검사도 없었다.

## 수정 (공통 원칙: 검토자 요청 조건은 상대 주장의 근거가 아니다)

[`infra/hermes/review_channel_worker.py`](../../hermes/review_channel_worker.py)

- 모든 교차 검토 주장은 `bind_peer_references`에서 근거 경로를 검사한다. 기존에는 새 스냅샷의 관측 시각(`peer_snapshot_scope_mismatch`)과 다른 구성요소의 클러스터 상태(`peer_component_scope_mismatch`)만 막았다. 같은 자리에 규칙을 하나 추가했다. 근거가 검토자 조회 결과의 **요청 조건 필드**(위 7종, `applied_filters` 하위 포함)이면 일치·이견 판정을 `peer_query_scope_mismatch`로 거절한다. 도구·장비별 예외 없이 모든 조회 결과에 적용된다.
- 이 코드는 기존 정정 경로(`PEER_OUTPUT_ERRORS`)에 들어간다. 모델은 같은 근거로 한 번만 고칠 수 있고, 새 조회·쓰기·승인은 없다. 두 번째도 같으면 이견을 게시하지 않고 `synthesis_failed`(`partial`)로 끝난다.
- 미확인(`unverified`)으로는 같은 근거를 계속 쓸 수 있다(예: "검토자 조회는 limit 10 표본이라 상대의 limit 50 조회는 미확인"). 반환 건수·경보 내용 같은 **관측값**은 지금처럼 일치·이견 근거로 쓸 수 있다.
- 지시문과 정정 요청에 같은 원칙을 한 줄씩 추가했다. 상대 조회 조건은 상대 영수증으로만 확인되며, 영수증이 없으면 미확인이다.

**한계(의도한 것)**: "상대가 질문(30분)과 다른 구간(60분)으로 조회했다"는 지적도, 검토자 자신의 `lookback_minutes`를 근거로 쓰면 미확인으로 바뀐다. 거짓 이견이 운영자를 오도하는 비용이 더 크다고 판단했다. 구간 불일치는 상대 시각 구간 고정(21:30 적용)으로 줄었다. 상대 영수증의 조회 조건을 교차 검토 입력에 넘겨 검토자가 실제로 확인할 수 있게 하는 일은 다음 개선 후보다(작업자 출력·디스패처·입력 구성 변경 필요).

## 적용 방법(승인 후, 미실행)

`apply_b.py <review_channel_worker.py>`를 B root로 1회 실행한다. 공동 채널 대기열이 비어 있을 때만 작업자와 영수증 항목을 바꾸고, 백업과 45분 원복 타이머를 건다. 작업자는 작업마다 새 프로세스로 실행되므로 서비스는 재시작하지 않는다. 적용 뒤에는 설치기 점검과 같은 방식으로 영수증 대조를 하고, 공동 채널 조사 질문의 교차 검토가 요청 조건으로 거짓 이견을 게시하지 않는지 확인한 다음 확정한다. 모델 출력은 매번 달라 같은 거짓 이견이 재현되지 않을 수 있으며, 그 경우 결정적 검사는 회귀 시험으로만 확인된 것으로 기록한다.
