# 서비스 조사: 자연어 시간 구간

common1.5.70은 명시된 날짜·시각 구간을 기존 서비스 이력 조회 인자에 연결한다. 서비스는 실제 등록된 target→systemd unit 메타데이터로 식별한다. 시간 해석 코드가 도구를 직접 실행하거나 사건을 판정하지 않는다. 기존 모델의 필수 읽기 선택·인자 검증·실제 영수증 확인을 유지한다.

이전 common68에서 `2026-11-06 16:20~16:40 KST`라는 질문은 필수 조사 계획으로 연결되지 않았다. 실제 Ollama 채팅은78.365초/조회0으로 실패했다. 같은 문장의 시간만 ISO로 바꾸면 필수3읽기 계획이 복원되는 것을 재현했다. `B의`라는 표현이나 MCP 권한 문제로 단정하지 않는다.

| 입력 | 처리 |
|---|---|
| `2026-11-06 16:20~16:40 KST` | 같은 날짜의16:20~16:40 KST |
| `2026년 11월 6일 오후 4시 20분부터 4시 40분까지` | 같은 구간, 생략된 끝 시각의 오후를 이어받음 |
| `어제 16시 20분~16시 40분` | 요청 시작 시각의 KST 날짜를 기준으로 전날 계산 |
| 명시 날짜와24시간제, 시간대 생략 | 프로젝트의 기본 시간대 KST 사용 |
| `2026-11-06 23:50~2026-11-07 00:10` | 명시한 두 날짜 유지 |
| 날짜 없는 시간, 연도 없는 날짜, `쯤`, 여러 구간/선택지 | 이 제한된 계획 생성 경로가 범위를 추측하지 않음 |
| `23:50~00:10`처럼 날짜 변경이 생략된 역순 구간 | 다음 날로 임의 보정하지 않음 |
| 다른 명시 시간대, 잘못된 날짜·시각, 미래·30일 밖·24시간 초과 | KST로 이름만 바꾸거나 조회 범위를 축소하지 않음 |

지원하지 않는 표현은 기존 일반 조사 경로에 남으며, 정상·0건·조회 완료의 근거가 아니다. 모든 자연어·모든 시간대 해석을 완성한 것은 아니다. ISO `+09:00` 및 기존 오늘/어제 비교도 유지한다.

## 검증·배포 범위

Mac의 새 시간 검사5개와 기존 Linux 서버의7프로필1,449고유검사/skip0을 확인했다. 일반 Mac 전체 서비스 검사에서는 jsonschema/openai가 없어21개 오류가 발생했으며 패키지를 설치하지 않았다. 같은 검사들은 기존 서버 환경에서 통과했다. 시간 구간·자정/연말·오전/오후·초·잘못된 날짜·명시 시간대·복수 범위·서비스 등록·조회 금지 조건을 검증한다.

common69의 첫 반영 뒤 명시된 PST 등 다른 시간대를 기본 KST로 잘못 읽을 여지를 확인해 common70으로 보완했다. 이 단위에서는 대기열 유휴 상태에서 계획된 Hermes 재시작이2회 있었다. 일반 장애 재시작이나 모델/GPU 서비스 변경과 구분한다. 공통 모듈2복사본과 SDK SHA 영수증을 갱신하며 query1.19.121·이전 SDK 추가조회 실행·원본35B·승인·FW 정책은 유지한다. 독립 원복과 실제 채팅 결과는 [검증 원장](service-periods.validation.json) 및 [현재 상태](../../STATUS.md)에 기록한다.

초기 설치는 기존 단일 `deploy.sh`의 공통 모듈 복사·소스 영수증 경로를 그대로 사용한다. 패키지·포트·키·MCP 권한 추가는 없다. 설치 프로필62검사와 실제 새 OS 전체 설치는 구분한다.

## 원문 로그의 별도 공백

11/8 02:32 KST, B의 해당 unit·11/6 16:20~16:40 구간에서 지정 오류 문자열에 일치하는 journal8행을 실제 확인했다. 원문은 원격 프로세스 안에서만 분류·SHA 처리했고 외부로 반환하지 않았다. 이는 해당 조건으로 반환된 자료이며 전체 로그 보존을 증명하지 않는다.

현재 MCP는 root 수집기가 발행한 정제 스냅샷·이력 SQLite를 읽고, 이 저장소에는 journal 본문이 없다. 모델에 일반 SSH/journal 권한을 주는 것으로 해결할 문제가 아니다. 후속 기능은 등록된 unit·기간·결과 크기·호출 한도, 비밀 마스킹, 원문 해시·수집 범위·미반환/잘림 표시와 감사 기록을 갖춘 제한된 로그 읽기로 설계한다. **이번 시간 수정이 원문 읽기를 구현한 것은 아니다.**
