# 전체 보안장비의 관리 IP·대역 정책

**고정 조회·장비별 파일 후보를 작성하고 A/B/C 실제8설정에서 검증했다. 전역 변경 MCP와 운영 적용은 아직 연결하지 않았다.** 관리대상의 추가·수정·삭제를 전체 보안장비의 후보·승인·검증으로 묶는다. [현재 상태](../../STATUS.md) · [계획](../../PLAN.md).

## 현재 확인한 공백

관리자231을 경유한 읽기에서 A FW의 `mgmt_src`에는 현재 관리자 주소가 있고 `never_block`은 별도 목록이었다. Suricata가 선택한 threshold에는 관리자 주소의 SID2001219 경보 예외가 있다. 이 관측으로 엔진 메모리에 로드됐다고 단정하지 않는다. B Wazuh `white_list`에는 loopback 항목만 있었고 B/C 호스트 보안 프로필의 관리 CIDR 목록은 비어 있었다. 이 파일 조회만으로 실제 접근이 차단되거나 모든 경로에 예외가 없다고 단정하지 않는다.

초기 설치 입력도 `ADMIN_PROTECTED_CIDRS`·`MANAGEMENT_ALLOWED_CIDRS`·`DASHBOARD_ALLOWED_CIDRS`·`LOG_PROTECTED_IPS`로 나뉘어 있다. 기존 `deployment/management_access.py`는 A의 특정 파일을 이관하는 용도이며 전체 장비 변경 기능이 아니다. 실제 룰 제안 도구의 범위도 WAF/Suricata/Wazuh 커스텀 파일이다. 관리 CIDR을 임의로 변경하는 도구가 있다고 안내하면 안 된다.

## 공통 목록과 장비별 효과

관리자 신원·주소·역할·정책 버전을 한 목록으로 관리하고 각 장비가 실제로 보는 출발지/중계 경로를 연결한다. 관리자와 MCP·내부 인프라 주소를 다른 역할로 구분한다. NAT/프록시 뒤에서 보이는 주소를 확인하지 않은 채 같은 주소만 복사해서 전체 반영으로 처리하지 않는다.

| 대상 | 공통 변경안에 포함할 항목 | 완료 근거 |
|---|---|---|
| FW | 관리 접속 출발지·자동 차단 보호 목록·등록된 관리 포트 | 영구 설정·커널 집합·체인 참조·허용/비허용 경로 대조 |
| WAF·웹 관리 | 관리 API/화면의 허용 출발지·실제 프록시 주소와 인증 | 전체 설정 구문·로드·관리 요청/비관리 요청 결과 |
| Suricata | 승인된 관리 트래픽 경보/차단 예외의 범위와 방향 | 선택 설정·엔진 로드·해당 관리 경로와 일반 공격 탐지 회귀 |
| Wazuh | active-response 보호 목록·관리 경보 분류·대시보드 경로 | 실제 설정/프로세스·규칙 시험·원래 로그 보존·자동 대응 결과 |
| 호스트 SSH/MCP | A/B/C의 실제 관리 중계 출발지·포트·고정 계정 경계 | 각 호스트의 유효 접속 정책·새 관리 연결·MCP 경로 조회 |

관리 접속 허용·자동 차단 예외·경보 예외는 각각 기록하고 관리자 접속은 정상 관리로 구분해 감사 로그를 보존한다. 특정 SSH 경보 억제를 모든 공격 검사 면제라고 표시하지 않는다. 기존 관리 주소 외에 새 주소를 이번 요구만으로 임의 등록하지 않는다.

## 작성한 공통 검증 계약

`deployment/management_policy.py`는 관리자 목록의 버전과 전후 SHA, 고정된 14적용면의 준비/확인 기록을 검사한다. 목록과 후보, 장비가 보는 출발지/중계 경로를 하나의 계획 SHA로 묶는다. FW 접속/차단 보호, WAF 관리, Suricata 관리 경보, Wazuh 대응/관리/경보, A/B/C SSH와 MCP, C 실습 관리가 대상이다.

검사 함수는 파일·네트워크·서비스에 접근하지 않는다. 실제 어댑터가 수집한 근거의 형식을 검사하며 자체 관측을 수행하지 않는다. 아직 MCP에 등록하지 않았고 승인 카드를 만들거나 룰을 적용하지도 않는다. 모델 인자로 받은 준비/로드 성공 값을 운영 증거로 삼는 인터페이스로 연결해서는 안 된다.

| 검사 | 통과 조건 |
|---|---|
| 전체 후보 |14적용면 전부·같은 기준/새 정책·현재 근거·구문/경로/원복·감사/공개 검사/차단 TTL 보존 |
| 정확 승인 결속 | 전체 후보와 전후 소스·어댑터·출발지 매핑의 SHA가 같은 계획에 포함 |
| 적용 뒤 확인 | 실제 소스가 승인 후보 SHA와 일치·로드 검증·동일 어댑터/출발지·모든 대상 확인 |
| 누락·실패 | 단1개 누락/중복·다른 버전·오래된 근거·미로드·경로 변경이면 전체 완료 불허 |
| 미확인·로컬 경로 | 알 수 없는 SHA는 미확인으로 유지. MCP stdio/unix에는 IP를 만들어 넣지 않음 |

Mac의34검사·생략0은 합성 어댑터 기록으로 위 조건을 시험한 결과다. 장비별 실제 로드/접속·탐지 효과나 전체 whitelist의 운영 완료를 증명하지 않는다. [작은 검증 원장](../../deployment/management-policy.validation.json).

```sh
python3 -B -m unittest discover -s deployment/tests -p test_management_policy.py
```

## A Native NAT·영구 로더 후보

실제 A는 기본 `ip nat` 테이블과 `capstone-basic-nat-` 주석이 붙은 고정 룰을 사용한다. 로컬의 미커밋 `deployment/firewall_nat.py`는 다른 테이블 통합 대안이므로 수정하거나 이번 작업에 포함하지 않았다. 실제 설치 소스 SHA를 보존해 `deployment/firewall_native_nat.py`의 기준으로 삼았다.

| 구성 | 작성한 기능 | 남은 조건 |
|---|---|---|
| Native NAT | 복수 CIDR·기존 DNAT 그룹만 원자 교체·Docker 룰 순서/기존 masquerade/차단 TTL 보존 | 전체 승인과 독립 원복을 담당하는 상위 작업자 연결 |
| 영구 로더 | `management_policy_render.py`가 관리 출발지·FORWARD 반복·NAT 인자 배열·표시를 함께 바꾸는 후보 생성 | 구문·전체 차이 검토 뒤 정확 승인·실제 설치 |
| 로컬 검사 | Native18·로더7, 합25검사·생략0 | 일부 OS 동작은 모의이며 실제 장비 인수와 구분 |
| Linux 격리 | 실제 iptables/nft 파서·두 대역 적용/원복·잘못된 기준/외부 룰 개입 거절 등9조건 통과 | 운영 경로의 SSH/웹·센서 효과·MCP/두 봇 검증 아님 |

Linux 시험은 별도 네트워크·mount 공간에서만 실행했다. 패킷 송신0·운영 FW 구조 불변·자체 서버 폴더 제거를 확인했으며 임시 차단의 핸들과 남은 시간119→119초를 유지했다. 첫 시험용 nft 줄바꿈 오류는 고쳐 재실행했으며 실패 원문도 보존했다. [작은 검증 원장](../../deployment/management-native.validation.json).

이번 후보는 운영에 설치하지 않았고 새 MCP를 등록하거나 관리자 주소를 추가하지 않았다. 전역 제안·승인·독립 복구·다른 장비 어댑터·`deploy.sh` 초기 설치 연결까지 완료한 것으로 표현하지 않는다. 기존 읽기/쓰기·관리자231 경유·공격/학습 중단 경계도 유지한다.

## 고정 조회와 장비별 파일 후보

`management_policy_observer.py`는 root 운영 담당자가 고정된 역할만 선택해 설정을 읽는 코드로, 모델이 경로·명령·성공 값을 입력하지 않는다. 비밀 환경값·전체 설정·알 수 없는 whitelist 문자열은 출력하지 않으며 실제 계정만 sshd 유효 설정을 확인한다. Docker는 설치된 두 고정 경로 중 하나와 로컬 소켓만 사용한다. 파일 선언·유효 sshd 설정을 엔진 로드나 새 접속 성공으로 표시하지 않는다.

| 호스트 | 실제 원본으로 생성한 후보 | 확인 범위 |
|---|---|---|
| A | FW 관리/보호 집합·NAT 영구 로더·Wazuh 관리 프록시·Suricata threshold,4파일 | 별도 네트워크 공간 nft 검사·Bash 구문·기존 컨테이너 nginx 검사 통과. reload 없음 |
| B | 호스트 보안 프로필·실행 중 Wazuh 관리자 설정,2파일 | SSH 중계 주소는 A 내부 주소. 실제2개 global 중 whitelist 구간만 변경. 커널/엔진 미적용 |
| C | 호스트 보안 프로필·실습 관리 환경,2파일 | SSH 중계와 원래 관리자 신원을 구분. 명시적 CIDR 변수만 추가하고 서비스 재시작 없음 |

관리 접속과 자동 차단 보호·경보 예외를 분리했다. FW의 기존 인프라·동적 차단 TTL, 공개 실습 경로/WAF, 다른 Suricata 룰, Wazuh의 기존 보호 목록을 보존한다. 기존 인프라/비관리 whitelist와 주소가 겹치면 관리자 역할 삭제만으로 모든 보호가 사라졌다고 표시하지 않는다.

같은11소스·입력으로 Mac87·Linux87/생략0을 확인했다. 이87에는 기존 공통 계약34와 로더7이 포함되며 독립 보안 사건 수나 정확도 점수가 아니다. 원본8설정 SHA 불변·자체 서버 폴더와 nginx 후보 제거를 확인했다. Wazuh/Suricata 엔진 검사는 수행하지 않았다. A 프록시/threshold의 상위 경로는 이 관찰기의 root 신뢰 조건을 충족하지 않아 승인 준비로 취급하지 않는다. [검증 원장](../../deployment/management-devices.validation.json).

이 코드는 운영에 설치하거나 MCP에 등록하지 않았다. 전체14면의 신뢰된 출처·실제 로드/경로 근거와 정확 승인·다중호스트 작업자/독립 원복·단일 초기 설치·양봇 새 채팅이 남았다. 이번에는 프롬프트/스킬/하네스를 바꾸지 않아 새 Harness² 실행을 주장하지 않는다. 후속 하네스 연결에는 기존 공식 점검 절차를 적용한다.

## LLM과 승인·복구 계약

| 단계 | 필수 조건 |
|---|---|
| 조회 | 전체 장비 목록·정책 버전·현재 파일 SHA·실제 로드 상태·커버리지 조회. 읽기는 승인 없이 |
| 제안 | LLM이 필요성과 대상/역할/추가·수정·삭제를 판단하고 장비별 전체 차이·구문/경로/누락 검사를 준비 |
| 승인 | 관리자 카드 하나에 전체 후보 SHA·대상·기한·중단 영향·복구 계획을 결속. 카드 밖 변경 금지 |
| 적용 | 관리자231 경유·독립 복구 장치·전후 상태 대조. 기존 차단 TTL/소유권을 보존하는 변경만 |
| 검증 | FW/WAF/Suricata/Wazuh·호스트 경로 모두 확인. 일부 미접속·미지원·실패는 전체 완료 금지 |
| 실패·교체 | 일부 반영을 정확히 표시하고 원복/보류. 새 관리 경로 확인 전 기존 유효 경로를 제거하지 않음 |

LLM이 관리대상 목록을 임의로 넓히거나 상시 root/sudo/Docker 권한을 얻지 않는다. 같은 공통 정책을 `deploy.sh`의 초기 설치 경로와 기존 서버 변경에 사용해야 한다. 초기 설치기로 운영 서버 전체를 덮어쓰지 않는다.

## 구현·검증 상태

| 항목 | 상태 |
|---|---|
| 실제 설정 읽기·분산된 목록 확인 | 완료. 설정 선언 범위의 관측 |
| 공통 registry·전체 후보/읽기 검증 계약 | 구현·Mac34검사/생략0. 파일/장비를 바꾸는 실행기 아님 |
| 고정 장비 어댑터·실제 근거 수집 | 고정 조회와 A4/B2/C2 파일 후보·Mac87/Linux87/생략0 확인. 실제14면의 출처/경로/로드와 상위 작업자는 미연결 |
| 전역 조회/제안 MCP·기존 카드 연결 | 미구현 |
| 전체 적용·장비별 로드/효과·부분 실패/원복 | 미구현·운영 시험 전 |
| 초기 설치기의 단일 공통 정책 연결 | 미연결. 기존 독립 입력은 아직 유지 |
| 새 관리자 주소나 보안장비 설정 변경 | 수행하지 않음 |

예정한 도구 이름과 설계 문구를 등록된 MCP 기능으로 표현하지 않는다. 실제 도구 목록·운영 설치 사본·정확 승인·새 채팅과 장비별 결과를 확인한 뒤 상태를 갱신한다.
