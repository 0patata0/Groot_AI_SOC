# 저장소 정리와 복원 — 2026-11-01

사용자 승인 범위: 현황·계획의 현재/과거 분리, 상세 검증 출력·벤치 반복 생성물·재생성 이미지 정리. 코드·시험 입력/정답·집계·출처·라이선스는 보존했다. 서버 작업과 Git 이력 재작성은 하지 않았다.

정리 전 **1,567파일을 무손실 압축하고 전부 실제 복원해 SHA256 일치**를 확인했다. 로컬 복구본은 `대화기록/검증/2026-11-01-git-cleanup-review/repository-before-cleanup.tar.gz`, 원장은 같은 폴더의 `backup-manifest.json`이다. 압축 SHA256은 `7cacc0ec6823a33e3ca7923c8ee19969183f6246f90024a6e4438938dad613c6`이다. 이 복구본은 학습 데이터셋 압축파일이 아닌 저장소 정리 복구 자료다.

[파일별 변경·원본 해시](REPOSITORY_CLEANUP_20261101.json)에 12개 추적 제거 파일과 검증 결과2개의 원래 크기·해시를 남겼다. 상세 원본이 필요하면 로컬 복구본에서 임시 경로에 해당 파일만 해제해 SHA를 대조하거나, 삭제 전 기준 커밋 `f9291ac6625fc5dc2a6535f17e124f9ffb604a13`에서 해당 경로를 읽는다. 최신 파일 위에 전체 복원하거나 전체 작업 트리를 reset하지 않는다.

예를 들어 기존 커밋의 한 원본을 읽는 명령은 다음과 같다. 출력을 저장하려면 별도의 로컬 임시 경로를 사용하고 원장 SHA를 확인한다.

```bash
git show f9291ac6625fc5dc2a6535f17e124f9ffb604a13:infra/hermes/benchmarks/results/2026-10-13-1609/results.jsonl
```

이전 manifest의 SHA는 **당시 원본**을 가리킨다. `_storage`가 추가된 공개 요약 JSON의 현재 SHA와 혼동하지 않는다. 원시 표본을 다시 채점하거나 이전 manifest 전체를 검증하려면 원본을 복원해야 한다. 요약을 완전한 원시 결과로 표시하지 않는다.

변경 전 Git 추적 파일은 약25.29MB였다. 상세 표본 축소와 생성물12개 제거로 약3.16MB를 줄였으며, 이력 문서 이동은 증거를 보존하기 위한 구성 변경이다. 기존 Git 커밋은 보존하므로 과거 blob을 포함한 Git 저장공간이 즉시 줄어들지는 않는다.

가중치·자격·포스터·대화/로컬 검증·업무분담·데이터 압축파일은 계속 Git 제외다. 의존성 lock 파일, 오프라인 vendor 소스와 라이선스, 학습 출처·재현 원장, 안전 검증 코드는 삭제하지 않았다.
