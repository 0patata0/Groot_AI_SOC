# 자동 관제의 지연과 중단 보고 복구

자동 관제의 긴 입력과 중단 시 근거 손실을 분리해 보완했다. 운영 B의 자동 관리 경로에 반영했으며 MCP 도구·스키마·모델·승인 권한은 바꾸지 않았다. 응답 30~60초 목표와 두 봇의 실제 채팅 검증은 아직 완료하지 않았다. 아래 시각은 KST다.

## 확인한 병목

| 관측 | 직접 확인한 범위 | 해석 |
|---|---|---|
| 관리 실행 | 최근25개 중7개가 약284초 subprocess timeout | 당시 실행 표본이며 전체 실패율이 아님 |
| 수집·채팅 큐 | 14:30의 A/B/C Wazuh 버퍼0·채팅 미완료 큐0 | 과거 포화나 누락이 없었다는 증거가 아님 |
| 모델 입력 | 같은 사건의 기본 자동 조사 프롬프트를 재구성하면67,469→54,102바이트 | 기본 정책 중복 제거 효과이며 실측 속도 향상률이 아님 |
| 추론 | Thor의 단일 슬롯과 긴 입력 평가·생성·대기 관측 | 단순 큐 확대만으로 해결할 근거가 없음 |
| 실제 읽기 전용 재검토 | 도구9건은 성공했지만 실패 보고 생성 중 예외 | MCP 응답 성공과 조사·보고 완료를 구분해야 함 |

실제 실패 기록을 격리 상태 저장소에서 재처리해 `FileNotFoundError`를 재현했다. 호스트의 `soc_management_run.py`가 서비스 근거를 표로 만들면서 같은 폴더의 `chat_contract.py`를 찾았으나 파일이 없었고 대체 경로는 컨테이너 전용 `/opt/data/plugins/groot-query-completion/chat_contract.py`였다. 운영 unit의 `TimeoutStartSec`는6분이었다. 이 실패를 systemd의300초 강제 종료라고 판단하지 않는다. 상태 DB의 약300초는 다음 복구까지 포함한 실행 기록이다.

## 반영한 내용

| 항목 | 처리 |
|---|---|
| 기본 정책 중복 | 자동 사건의 기본 요청에 정책 전체를 다시 넣지 않고 작업 목적만 넣음. 명시한 사용자 요청·근거·제어 조건은 보존 |
| 필수 읽기 선택 | 검증된 모델·경로에서 제공 도구가 모두 등록 읽기이고 선택이 필수인 단계만 reasoning을 낮춤. 위험·쓰기 판단의 기존 설정 유지 |
| 표의 밀집 셀 | 개별 사건 시각·출발지·목적지를 행으로 나누고 조회 구간·조치 타임라인·룰 목록을 구분 |
| 완료 전 근거 저장 | 성공한 실제 읽기에서 추출한 구조화 근거를 기존 SQLite meta에 실행 ID·사건 ID·완료 ordinal·SHA와 함께 저장 |
| 프로세스 중단 복구 | 현재 도구 원장과 저장 근거로 미완료 보고를 재구성. 실패·미수신·쓰기 응답을 구분하고 조치나 조사를 자동 재실행하지 않음 |
| 손상·다른 실행의 근거 | 버전·필드·실행/사건 결속·완료 읽기·SHA 검증에 실패하면 근거 표를 복원하지 않고 그 한계를 표시 |
| 호스트 의존성 | 기존 공통 `chat_contract.py`·`read_contract.py`를 관리 경로에도 배치. 단일 `deploy.sh`가 호출하는 소스 묶음과 설치 경로에도 포함 |

근거 저장과 보고에는128KiB 상한을 두고 초과 사실을 알린다. 저장된 관측은 현재 상태·위험 해소·승인의 증거가 아니다. 새 상태나 늦게 수집된 경보를 확인해야 하면 새 조회를 한다. 이 저장소는 모델 메모리나 승인 재사용 경로가 아니다.

## Malvex에서 참고한 부분

[Malvex](https://github.com/JoasASantos/Malvex/tree/75d86748c185aea0171b38682ab6a2bf15a5240c)는 악성코드·역공학 분석용 프레임워크다. 확인한 커밋은 `75d86748c185aea0171b38682ab6a2bf15a5240c`이며 원문9파일의 경로·크기·SHA를 로컬 검증 원장에 보존했다. 프레임워크를 설치하거나 상위 설치 스크립트를 실행하지 않았다. 기존 관제 기능과 겹치는 도구를 새로 등록하지 않았다.

| 확인한 설계 | 이 프로젝트의 적용·제한 |
|---|---|
| 단계별 결과 보존·완료 단계 재사용 | 이번 실행의 검증된 조회 근거를 이어 쓰고 중단 보고를 복원한다. 상태가 변하는 라이브 서버에는 정적 샘플의 재사용 조건을 그대로 적용하지 않는다. [실행 소스](https://github.com/JoasASantos/Malvex/blob/75d86748c185aea0171b38682ab6a2bf15a5240c/crates/malvex-orchestrator/src/exec.rs) |

조사 원칙은 기존 `soc-investigate`의 두 문단을 고쳐 관리한다. 조회마다 해소할 질문·필드를 정하고 근거 없이 전체 룰·다른 장비 조회로 확장하지 않으며 실패·시간 초과를0건으로 바꾸지 않는다. 별도 스킬은 복제하지 않았다. 운영 설치본의 문단 변경량은96바이트다. 입력 중복 제거·표 분리·정상 종료 시 부분 보고는 Malvex를 참고하기 전에 작성했으며 위 반영 목록에도 포함되어 있다.

후속 배포의 준비 검증은 후보 폴더의 gate 참조가 빠져 실패했다. 이 결과 확인 전에 적용한 절차상 실수는 로컬 원장에 남겼다. 이후 후보 참조를 복구하고 운영·후보의 embedded gate 결속, 원본 백업, 적용 SHA, 실제 기록 재처리와 강제 종료 복구를 확인한 뒤15:52:29에 확정했다. 첫 백업 검증의 파일 순서 오류도 고쳐 다시 검사했다. 실패한 영수증은 보존한다.

현재45도구의 실제 스키마 카탈로그 SHA는 `7b8f53a7834d3fc072ad0bafc838d7870eaaafed11b8a4de8a46bb9143e26140`이며 학습 모델은 `soc-qwen36:35b-balanced-q4km-20261108`이다. 자동 관리 경로의 gate·controller·스킬은 정본 전체 덮어쓰기 대신 관측한 설치본에 이번 변경만 옮겼다. 앞서 남아 있던 다른 후보를 함께 운영에 적용하지 않았다.

Native·SDK의 출력 스킬·gate·핀·영수증은 후속 이관 대상이다. 서버 Harness²는 각 구조 검사는 통과했지만1차 변경 뒤 출력 스킬 사본 차이를 `findings`로 보고했다. 이 결과를 전체 점검 통과로 표시하지 않는다. 새 실제 채팅의 서식·정확도·왕복 속도, 반복 조회·긴 판단 출력, 새 서버 전체 설치와 실제 공격 대응 E2E는 별도 미완료다. 공격 시험과 새 학습은 중단을 유지한다.

정상 종료 보고·SQLite 기록·강제 종료 복구의 확인은 서비스 재부팅이나 전원 단절 복구를 대신하지 않는다. 전체 목표와 다음 순서는 [STATUS](../../../STATUS.md)·[PLAN](../../../PLAN.md)을 따른다.

최종 검토에서 보관 상한에 걸린 새 차단 조회가 이전 목록을 남기는 경계 조건을 보완했다. 최신 목록을 저장하지 못하면 이전 차단 값도 무효화하고 보관 한계를 표시한다. Mac209개·Linux20개를 통과했고 운영 설치본의 해당 반례1개와 gate 결속·원본 백업을 확인한 뒤 2026-11-17T19:21:47.020414+09:00에 확정했다. 최종 운영 controller SHA는 `91201647a1102f8c8132b038b2ee8e310032f920f0bd0e9c60420fea4f6326fa`다. 새 모델·MCP·채팅 호출과 운영 서비스 재시작은0이다.
