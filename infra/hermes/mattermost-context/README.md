## 문맥 처리와 제한

`__init__.py`는 native `pre_gateway_dispatch` hook에 등록된다. 이 hook은 native 인증 이전에 실행될 수 있으므로, HTTP 조회 전에 기존 gateway의 사용자 권한 판정을 명시적으로 다시 호출한다. 봇·내부 사건·허용되지 않은 사용자·명령 메시지는 조회하지 않는다.

| 항목 | 처리 |
|---|---|
| 스레드 댓글 | API로 원글·현재 요청의 채널/사용자/스레드를 대조한 뒤 원글과 요청보다 앞선 댓글 최대 25개를 사용 |
| 채널의 새 글 | 앞선 최상위 글 최대 20개 사용. 다른 스레드의 댓글은 제외 |
| 카드 | 본문, 제목, 설명, 표시용 필드만 추출. 버튼의 action/integration/callback 메타데이터는 제외 |
| 길이 | 전체 문맥 12,000자, 원글 6,000자, 개별 댓글 1,500자 상한. 기존 인용 문맥은 최대 1,000자 |
| 시간·응답 크기 | 전체 조회 9초, 개별 HTTP 4초. 현재 글 256KiB·이력 512KiB 상한, redirect 불허 |
| 실패·생략 | `unavailable`·고정 실패 사유 또는 생략 표지를 모델에 전달. 읽지 못한 원문을 추정하지 않도록 명시 |

읽은 내용은 **신뢰하지 않는 참고 인용**이며 현재 지시나 관리자 승인이 아니다. `reply_to_text`로 전달하여 native `@file` 등의 확장 처리가 끝난 뒤 인용을 붙인다. `event.text`나 `channel_context`에 대화 이력을 넣지 않는다. 원글이 길거나 댓글이 많으면 일부를 생략하므로 “원 보고 전체를 항상 읽었다”고 설명하면 안 된다. 조회 실패 시에도 현재 요청 처리는 이어지지만, 모델은 읽지 못한 범위를 밝혀야 한다.

native 세션 키는 채널과 스레드를 구분한다. 이번 plugin은 그 키와 라우팅을 변경하지 않는다. 서로 다른 비공개·공개 채널의 이력을 합치는 기능은 제공하지 않는다. 문맥에 포함된 과거의 승인 문구나 카드 표시는 승인 브로커의 실제 상태·일회 소비 검증을 대신하지 않는다.

## 공개 채널 가입

`channel_sync.py`는 명시한 팀의 삭제되지 않은 공개 채널에 **해당 봇 자신만** 가입시킨다. 시작 hook이 별도 제한된 aiohttp 세션으로 첫 동기화를 수행하고 300초 간격으로 반복한다. 따라서 새 공개 채널 생성 직후에는 다음 동기화까지 멘션 수신이 늦을 수 있다. 한 번의 동기화는 30초, 가입 시도 20개까지이며 초과분은 다음 실행에서 처리한다.

팀·봇 ID와 home 채널의 소속을 대조한다. 비공개 채널 가입, 다른 사용자 초대, 권한 변경, 메시지 게시, 기존 채널 탈퇴는 수행하지 않는다. 고정 채널 허용 목록을 비우는 것만으로 봇이 미가입 채널의 메시지를 받는 것은 아니므로 이 가입 절차가 필요하다. 시작 hook의 task는 중복 생성을 막고 gateway 이벤트 루프 종료 시 취소되면서 HTTP 세션을 닫는다.

| `__init__.py`, `plugin.yaml`, `channel_sync.py` | `/opt/data/plugins/groot-mattermost-context/` |
| `startup/HOOK.yaml`, `startup/handler.py` | `/opt/data/hooks/groot-mattermost-channel-sync/` |

`config.yaml`의 기존 `plugins.enabled` 목록에 `groot-mattermost-context`를 추가한다. `.env`에서는 기존 `MATTERMOST_URL`, `MATTERMOST_TOKEN`, `MATTERMOST_HOME_CHANNEL`을 사용하며 명시적 `CAPSTONE_MM_TEAM_ID`, `CAPSTONE_MM_BOT_ID`를 설정한다. 토큰 값은 문서·로그·Git에 기록하지 않는다. `MATTERMOST_ALLOWED_USERS`의 기존 관리자 제한과 `MATTERMOST_REQUIRE_MENTION=true`, `MATTERMOST_REPLY_MODE=thread`를 유지한다. `MATTERMOST_ALLOWED_CHANNELS`는 비워 두고 home/free-response 설정은 운영 의도에 맞게 보존한다.

신규 환경의 [SIEM 설치기](../../../deployment/roles/siem.sh)는 위 운영 파일 5개와 설정을 반영하고 native hook·인용 순서 호환성을 사전 검사한다. 패키지는 기존 수동 준비 절차를 따르며 이 기능 때문에 Mac 패키지를 설치하지 않는다. 이 추가만으로 신규 환경에 현재 라이브의 모든 승인 MCP·SOC 운영 구성이 복제되는 것은 아니다.

## 검증과 복구

로컬 문맥·가입 회귀는 다음처럼 실행한다. native 검사는 실제 Hermes 소스가 있는 환경에서 해당 경로를 지정하며, 소스가 없으면 건너뛴다.

```sh
python3 -B infra/hermes/mattermost-context/test_context.py
python3 -B infra/hermes/mattermost-context/test_channel_sync.py
python3 -B infra/hermes/mattermost-context/test_native_contract.py --hermes-root /opt/hermes -v
```

native 검사는 실제 소스에서 세션 분리, hook API, `@file` 확장 이후 인용 순서를 확인한다. 시험용 인용의 파일 참조를 열거나 메시지를 보내지 않는다. 배포 후에는 gateway 연결, 공개 채널 가입, 원 보고/카드/채널 각각의 읽기 결과를 확인한다. 실제 사용자 요청 2건의 문맥 연결은 확인했으며, 다른 채널·긴 보고·조회 실패에서 답변 위치와 내용·생략 고지가 올바른지는 추가 평가한다.

이번 라이브 변경 전 설정 백업은 `/var/backups/capstone-mattermost-context/20261015/config.yaml`과 같은 디렉터리의 `.env`다. 복구할 때는 이후 변경 유무를 먼저 대조하고 이 기능의 plugin 활성화·hook·추가 설정만 되돌린다. 진행 중인 채팅·관리 작업을 확인한 뒤 기존 컨테이너를 제어된 방식으로 stop/start하고 연결을 다시 확인한다. 백업을 무조건 덮어써 이후 설정을 없애지 않는다. 이미 가입한 공개 채널의 멤버십과 기존 메시지는 자동 원복하지 않는다.

만료된 미결 요청 카드만 정리하는 기능은 별도 후속 작업이며 이 문맥 기능의 완료 범위에 포함하지 않는다. 현재 기능은 승인·거부 결과나 서버 감사 기록을 삭제하지 않는다.
