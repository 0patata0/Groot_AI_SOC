## 확인한 원인과 남은 검증

- 현재 operation의 `live_block_state`는 해당 IP의 실제 `agent_block` 관측인데, 기존 안내가 같은 집합의 `list_blocks`를 항상 함께 요구한다. 범위 안내를 바로잡는 것만으로 재조회가 안정적으로 없어지지는 않았다. 전체 목록·다른 IP·실패·관측 후 변경 확인은 필요한 추가 조회와 구분해야 한다.
- 실제 wire 원장은 묶음1회를 기록한다. 내부 웹 읽기를 같은 인자로 재선택한 출력도 확인했다. 검증된 내부 완료 목록을 제공해도 이 두 사례의 반복을 모두 없애지는 못했다. wire 기록을 실제로 없었던 개별 호출로 바꾸지 않는다.
- 현재 웹 건강 검사기가 명시된 Vector 서비스 표현도 웹 정상 주장으로 검사한다. 동시에 모델은 Apache 프로세스 상태를 전체 서비스 건강으로 확대하고, 연속성 미검증을 장애·복구 필요로 오인한다. 검사 대상 혼동과 실제 근거 없는 주장을 따로 고쳐야 하며 통과율을 위해 검사를 단순 해제하지 않는다.
- 정정 요청의 오답 초안이 그대로 반복됐다. 초안을 제외한 사실 중심 정정은 한 사례에서만 교정됐으며, 두 사례 모두에서 안정적이지 않았다. 실제 관제 후속 계획도 관측 대상·구간·현재 권한과 연결되어야 한다.
- 캐시는 답변 정답 저장이나 모델 학습이 아니라 입력 계산의 재사용이다. 같은 과거 자료의 빠른 재생을 새 사건 성능으로 일반화할 수 없다. 공통 지침·도구 규격의 재사용은 확인했지만 사건 자료/시각은 새 조회해야 한다.

공유 추론 부하를 통제하지 않았고, 캐시 적중·모델 선택·출력 길이가 다르다. 독립 평가176건, 새 사건 전체 조사, Mattermost 큐·전달/UI 시간, 평균·백분위/SLA, 실제 공격 E2E를 대신하지 않는다. 초기43초 사건과 다른69초 실패 결과도 [이전 단위](incident-bundle.md)에 그대로 보존한다.
