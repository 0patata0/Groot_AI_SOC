# 추가 조사 선택을 실제 MCP 실행으로 연결

2026-11-06 이전 검증: query1.19.44 / common1.5.32. 현재는 [후속 비교](review-scope.md)를 따른다. [현황](../../STATUS.md) · [이전 지연 실측](case-latency.md) · [검증 원장](additional-inquiry.validation.json).

## 해결한 경로

읽기 전용 웹 사건 재검토에서 모델이 추가 근거를 요청해도, 다음 API 요청이 기존 일반 도구 선택 경로로 빠져 새 MCP 없이 장문 답변을 생성했다. 후속 검증에서는 추가 조회 선택에 남은 medium 추론과 토큰 한도 초과도 확인했다. 기존 검사는 중간 tool_choice만 확인했으므로 최종 API 요청·실제 Native 응답 해석까지 회귀 범위를 늘렸다.

| 변경 | 동작과 경계 |
|---|---|
| 추가 조사 선택 | 현재 요청에 결속된 more_evidence 선택 뒤 모델이 등록 읽기1~4개와 정확 인자를 반환. report만 반환할 수 없음 |
| 실제 실행 | 응답을 Native tool_calls로 전달. 어댑터는 MCP를 직접 실행하거나 성공 영수증을 만들지 않음 |
| 보고 복귀 | 현재 실행에 새 완료 영수증이 생겨야 복귀. 조회 오류도 숨기지 않고 전달 |
| 실제 API 추론 강도 | 외부 재시도 wrapper가 none을 medium으로 되돌리던 경로를 확인. 최종 추가 읽기 선택 요청만 none, 별도 간결 JSON 지시로 구성. 판단/승인 경계는 그대로 |
| 반복 제한 | 동일 영수증 수로 재시도 예산을 늘리지 않음. 기존3회 일반 연속 처리·12turn/180·210초 상한 유지 |
| 조회 누락 보완 | 보고 시에도 허용된 등록 도구 목록을 제공. 운영자가 요청했거나 지금 보완 가능한 조회를 한계·다음 조치로만 미루지 않도록 공통 지침 보완 |

단일IP·verify·operator_review·web_impact_review와 현재 Thor 원본35B의 기존 경로에만 적용한다. 일반 관리·보호쓰기·종결/승인 정책으로 확대하지 않았다. 특정 사건의 정답·추가 진단 target을 코드에 넣지 않았으며 조사 대상·인자·판단은 모델이 선택한다.

현재는 추가 읽기3묶음 모두 모델이 선택해 Native MCP가 실행했다. 선택 응답은96/62/169토큰으로, 기존796토큰 및 length거절을 재현하지 않았다. 그러나 프로세스 목록 등 누적 입력이17,599→37,323토큰으로 늘었고, 추가 선택에18.2/36.6/39.6초가 소요됐다. provider시간은 GPU연산·대기/전송을 별도로 분해한 값이 아니다. **전체 보고 속도가 개선됐다고 결론 내리지 않는다.**

현재 남은 오류는 같은 Apache 진단 반복, 차단 요청ID를 룰변경 상태 도구에 전달,24시간 범위를 넘긴 웹 조회, 예산이 끝나도 추가조사 발화만 남는 보고다. active/running은 침해 부재가 아니며 진단 표의 상태·수집 신선도 표기도 보완 대상이다. 실패/미확인을 정상·종결로 바꾸지 않았다. 원문/실행/실패는 로컬 감사에 보존한다.

[앞선 기본 보고35.5~41.3초](case-latency.md)는1.19.40의 별도 요구/표본이며 현재 추가진단 요청과 동등 비교하지 않는다. 다음 우선 작업은 요청별 조사 범위·중복 조회, 손실 없이 줄일 수 있는 큰 입력, 예산 종료 시 확보 근거 보고를 보완하고 새 요청으로 확인하는 것이다.
