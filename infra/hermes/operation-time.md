# 차단 상태의 KST 표시와 실제 영수증 해석

2026-11-03 시험에서 실제 차단 기한은21:20:18 KST였는데, WAF 조사 보고는21:18로 적었다. IDS 조사에는1970년으로 잘못 만든 계산 입력과 원래 epoch 숫자 출력도 있었다. 이 문제를 모델 학습이나 방화벽 TTL 변경으로 해결했다고 표시하지 않는다.

## 변경

| 경로 | 처리 |
|---|---|
| A/B 룰 MCP | KST 보기를 get/service-get 외에 status/operation-status/contain-ip에도 붙인다. 원래 POSIX 초·서명 payload·계획/증거 해시·상태는 그대로 보존한다 |
| 관측 기준 | 실제 소유 블록의 live_owned_deadline/live_observed_at에서 남은 시간을 산출한다. 커널의 live_remaining_seconds 반올림 값도 보존한다. foreign/absent/unavailable에는 현재 소유 기한이나 남은 시간을 추정하지 않는다 |
| 모델 입력 | 두 봇과 자동 관리가 같은 순수 변환을 사용한다. 검증한 containment 영수증의 top-level 시각만 *_kst로 보여주고 remaining_seconds_at_observation을 제공한다. 감사 원문·중첩 승인 payload·MCP 인자는 바꾸지 않는다 |
| native 연결 | 유일하게 연결된 실제 tool_call_id와 룰 상태/임시차단 도구의 응답만 투영한다. 중복/미연결/다른 도구 이름·오류·알 수 없는 포장은 그대로 둔다. 저장 메시지를 수정하지 않는다 |
| result 이름 충돌 | 실제 차단 상태에도 결과 문장인 result가 있다. 이것을 MCP 포장으로 오인해 JSON으로 풀던 오류를 수정했다. result/isError만 있는 포장만 벗기고 도메인 결과 문장은 보존한다. 시간뿐 아니라 실제 상태 영수증의 근거 수집도 회복한다 |
| 보고 확인 | 실제 영수증과 다른 명시적 만료시각이나 epoch 출력을 정정 대상으로 삼는다. 복수 요청의 모호한 시각·인용·원문 블록·정정 문장은 강제 재작성하지 않는다 |
| 완료 검증 | get_operation_status는 실제 커널 소유/부재를 포함한다. a:incident-ip에 존재하지 않는 별도 target 조회를 요구하던 조건을 수정했다. kept는 같은 대상/상태·실제 소유·유한 양의 잔여시간, released/expired는 현재 부재를 확인한다. 룰/서비스 별도 검증은 유지한다 |
| 역할 | 표시·근거와 절차 완료만 검증한다. 공격 판단/변경안은 LLM이 주도하고 관리자 승인·보호 주소·600초/60분/재차단60초·일반 sudo 위임 금지를 유지한다. 시간 산술이 실제 필요한 요청의 calculate_time 권한은 유지한다 |

이미 제공한 KST/관측 기준 남은 시간을 보여주기 위해 다시 계산하지 않도록 공통 계약1.5.16·query-completion1.19.12를 사용한다. 조회 당시 값은 현재 남은 시간이나 사건 위험 해소의 증거가 아니다. 원 기한과 만료 처리 기록 시각을 구분한다.

최종 실제 모델 응답·도구 수·산술 호출·반영 확정은 [기계 원장](operation-time-validation-20261103.json)과 [현재 상태](../../STATUS.md)를 따른다. 전체 사건 판단/종결 품질이나 모든 자연어 표현의 완전 검증을 뜻하지 않는다.

## 설치·복구

기존 루트 deploy.sh가 같은 canonical MCP·controller 내장 gate·양봇 source bundle을 생성한다. 오프라인 소스 묶음을 갱신하며 추가 패키지·이미지·서비스·포트·키·도구/권한·모델은 없다. 일반 시간 계산 MCP 자체는 변경하지 않는다.

운영 서버에는 관리자231→A→B로 증분 반영했다. A의 stdio MCP1파일은 엔진 재시작 없이 적용하고 B14파일은 유휴/기존 SHA·uid/gid/mode를 확인해 교체한다. 프로세스가 로드한 사본을 바꾸기 위해 두 봇/공동 채널 소비자를 재시작하며, 새 요청의 영속 대기열·DB/WAL·대화를 과거 복제본으로 복구하지 않는다. SOUL·비밀 설정과 모델은 그대로다.

A/B 각 root `/var/lib/capstone-operation-time/20261103-r1`에 원본/후보·중간 SHA와 복구 메타데이터를 보존한다. 독립 원복 timer는 이번 소스의 예상 SHA만 복구하고 다른 변경은 덮지 않는다. B의 작업이 진행 중이면 유휴까지 미룬다. 실제 수동 원복/새 서버 전체 설치는 미실시이며 실제 확정/타이머 해제 상태는 원장을 따른다.
