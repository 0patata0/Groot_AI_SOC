# 데이터셋 통합 압축 보관 규칙

2026-11-01 KST 사용자 확정. 전체 자료를 **원본 1개 + 정제본 1개**의 무손실 압축파일로 보관한다. 데이터셋별·날짜별 압축본을 따로 누적하지 않는다.

| 구분 | 상시 보관 경로 | 내용 |
|---|---|---|
| 원본 | `datasets/archives/original.tar.gz` | 실제 확보한 원문 바이트, 원배포 파일, 출처·이용 조건·취득 기록 |
| 정제본 | `datasets/archives/cleaned.tar.gz` | 정제 결과, 학습/검증/시험 구분, 정제 코드·설정 해시, 검수·제외 근거 |
| 원장 | `datasets/archives/catalog.json` | 압축별 SHA256·크기·KST 갱신 시각, 내부 manifest 위치와 검수 상태. 압축파일 수에 포함하지 않는 작은 메타데이터 |

이 보관소 전체는 Git에서 제외한다. 공개 저장소에는 코드·이 규칙·출처·라이선스·작은 검증 요약만 남긴다. 원자료의 이용 조건에 따라 원문을 공개 저장소에 재배포하지 않는다. gzip은 기존 도구로 사용할 수 있어 Mac에 추가 패키지를 설치하지 않는다.

## 내부 구조와 재현

- `datasets/<source-id>/<revision>/...`로 기관/데이터셋/버전을 구분한다. 실제 사용한 이전 버전과 분할은 같은 통합 압축 내부에 보존한다. 별도 과거 압축본을 늘리지 않는다.
- 원본 텍스트의 인코딩·개행·시각·수치를 압축 때문에 변환하지 않는다. 원배포 ZIP 등의 바이트 보존이 필요하면 원본 압축의 내부 멤버로 포함한다. 외부에 동일 다운로드 복사본을 장기 보관하지 않는다.
- manifest에는 각 멤버의 상대경로·바이트 크기·SHA256·출처/버전/라이선스, 원문 좌표, 정제 코드/설정, 분할·제외/보류 사유를 남긴다. 새 정답이나 라벨을 압축 단계에서 만들지 않는다.
- 부분 다운로드나 원격 참조만 한 자료는 해당 범위와 URL·revision·제공 해시/실측 해시를 구분한다. 받지 않은 전체 원본을 보관했다고 표시하지 않는다. 파일 수를 맞추기 위해 대형 원본을 새로 내려받지 않는다.
- 정제본은 `candidate`, `training_eligible`, `evaluation_only`를 구분한다. 압축에 들어 있다는 사실만으로 학습 적격이 되지 않는다. 실행별 승인된 입력 목록과 분할을 사용하고, 평가/보류 자료를 학습에 섞지 않는다.
- 모델·LoRA·optimizer·체크포인트, 설치 패키지·캐시, 자격 파일은 두 데이터 압축파일의 대상이 아니다.

## 갱신·복구 절차

1. 기존 보관본의 SHA256을 확인하고, 이번에 합칠 원문/정제 결과와 재현에 필요한 기존 버전을 명시적으로 선택한다.
2. 작업별 임시 공간에 새 압축본과 manifest를 만든다. 보관 중인 검증본에 직접 쓰지 않는다.
3. 압축을 끝까지 읽어 모든 멤버의 크기·SHA256을 대조하고 새 임시 경로에서 복원을 확인한다. 단순 파일 존재나 `tar` 목록 확인만으로 무손실 검증을 완료하지 않는다.
4. 검증된 파일을 고정 이름으로 교체하고 catalog를 갱신한다. 교체 중단이나 압축·원장 불일치 시 사용을 중지하고 기존 검증본으로 복구한다. 원본과 정제본을 함께 갱신할 때에는 두 파일과 원장의 일치까지 확인한다.
5. 교체·복원 확인 후 이번 작업의 이전 압축 복사본·임시 해제본·다운로드 중복본을 정리한다. 완료 시 상시 압축파일은 정확히 2개다. 갱신·복구 도중에만 임시 복사본이 추가로 존재할 수 있다.

유일한 검증본이나 현재 실행이 사용하는 파일을 먼저 삭제하지 않는다. 아직 원본/정제본 분류가 끝나지 않은 기존 자료를 이름만 보고 대량 삭제하지 않는다.

## 서버 반입과 사용

1. 로컬에서 출처·권리·개인정보·정답·분할 검수를 마친 정제본을 준비하고 압축 SHA256·허용 멤버 목록을 확정한다. 반입 불가 자료는 제외한다.
2. `cleaned.tar.gz`를 그대로 전달한다. 원본은 로컬에 남긴다. 서버 측 동일 이름의 임시 반입 파일은 해제·입력 검증 뒤 정리하며 별도 세대별 보관본을 쌓지 않는다.
3. 서버에서 압축 SHA256과 manifest를 먼저 대조한다. 새 실행 디렉터리에 필요한 멤버만 해제하고 절대경로, `..`, 링크, 장치 파일, 중복·예상 밖 멤버를 거절한다. 기존 실행 경로 위에 덮어쓰지 않는다.
4. 해제된 파일의 크기·SHA256을 다시 검사하고 모델/tokenizer·도구 계약·학습/평가 입력을 확인한다. 그 뒤에만 해당 실행이 사용한다.
5. 학습 중 입력은 고정한다. 사용이 끝난 해제 작업본은 참조 중인 실행·재현/복구 조건을 확인한 뒤 정리한다. 체크포인트와 가중치의 별도 보존 규칙을 유지한다.

수집·정제·검수는 로컬, 학습과 필요한 실행 검증은 DGX, 검증한 가중치의 적재·추론은 Thor에서 한다. 이 규칙은 GPU 서버에서 원자료를 정제하라는 지시가 아니다.

## 현재 적용 범위

이번 작업은 지속 적용할 저장·반입 규칙, 제외 설정과 문서 연결을 확정한다. 기존 로컬 `datasets/raw`, `datasets/processed`, `finetuning/data-*`의 일괄 압축 전환이나 실행 중인 DGX 자료 변경은 수행하지 않았다. 기존 자료의 분류·해시 검증 및 통합 압축본 생성·복원 검증을 완료하기 전에는 이전 완료로 표시하지 않는다. [현재 상태](../STATUS.md) · [학습자료 검수](../finetuning/SOURCE_REVIEW_WORKFLOW.md).
