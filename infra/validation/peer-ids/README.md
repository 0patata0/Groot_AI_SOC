## 문제

교차 검토 게시문에 내부 근거 식별자(`a0`, `e9` 같은 카탈로그 번호)가 반복해서 노출됐다. 모델 안내는 "text에 a0/e0 같은 내부 식별자를 노출하지 말라"고 하고, 작업자는 게시 전에 식별자를 지운다. 그런데 지우는 정규식에 두 가지 빈틈이 있었다.

| 빈틈 | 내용 | 실제 노출 |
|---|---|---|
| 한국어 조사 앞 경계 | `(근거|증거|evidence)\s+e9\b`의 `\b`를 Python은 "e9"와 한글 조사 사이에서 경계로 보지 않는다(한글도 단어 문자) | 04:17 "증거 e9에 따라" |
| 앞에 "증거"가 없는 식별자 | 괄호 안("(e9)")과 "근거 e9"만 처리하고, 맨 식별자와 범위·목록은 처리하지 않았다 | 00:01 "e70으로 확인됩니다", 23:50 "(e3~e4: 23:21~23:51)" |

오늘 센서 약어(`IDS`·`SID`·`TLS`)에서 고친 것과 같은 경계 계열이다.

## 수정 (공동 채널 작업자만)

`strip_reference_ids(text, answer_ids, evidence_ids)` 하나로 바꿨다.

| 형태 | 처리 |
|---|---|
| 괄호 안 "(e9)", "(근거 e9)", "(e9, e32)" | 괄호째 지운다 |
| "증거 e9에 따라", "근거 e9, e32" | 식별자만 지운다 → "증거에 따라" |
| 맨 식별자 "e70으로", "e28을", "e3~e4: …" | e-식별자는 "조회 근거", a-식별자는 "상대 답변"으로 바꾸고 바로 뒤 조사를 받침에 맞춘다 → "조회 근거로", "조회 근거를", "(조회 근거: …)" |
| 경계 | 식별자 앞에 영문·숫자·`_ : . - /`가 없어야 하고, 뒤에는 영문·숫자·`_ . - /`가 없고 콜론이면 공백이 와야 한다. 한국어 조사는 붙어도 된다. 해시(`e3b0c442`), MAC(`a0:1b:2c`), IPv6(`fe80::a0`), 카탈로그 밖 값(`e100`), 규칙 번호는 건드리지 않는다 |

모델 안내 문구와 검사 기준은 바꾸지 않았다. 지우는 대상은 이번 대조에서 실제로 만든 카탈로그 식별자뿐이다.
