# 현재 에이전트 배치와 역할

2026-11-03 사용자가 채택한 역할 배치를 유지한다. 에이전트·채팅·분배기는 B에서 실행하며,모델은 후속11/8 전환한 Thor 학습본 `soc-qwen36:35b-balanced-q4km-20261108`이다.11/15 SDK실행/모델 manifest GET에서 같은 별칭을 확인했다. DGX는 학습/필요 비교 역할이며 새 학습은 중단 상태다. 아래 역할 배포 검사·복구 수치는11/3 당시 이력이며 최신 모델 품질을 입증하지 않는다. [현재 읽기 검증](../validation/live-reads/README.md) · [실제 현황](../../STATUS.md).

전문 역할은 기존 SOUL과 `SOC_ACTIVE_ROLE`의 강제 지침에 이미 들어 있다. 이번에는 지침과 실제 공동 채널 분배가 맞도록 `soc-review-routing:1.1.0`을 반영했다. 역할은 우선 담당이며 상대 사건의 검토 금지나 공통 관제 의무 축소를 뜻하지 않는다.

## 공동 채널 배정

- `soc-review-agent`의 일반 대화·서비스 상태·룰·차단 목록은 Ollama가 우선 답한다. 차단 목록의 ‘차단’이라는 명사만으로 변경/추가 검토로 보내지 않는다.
- 사건 조사·상관분석·변경과 중요한 위험 검토는 Hermes가 기본 담당이다. 모델의 보안 판단을 코드 분기로 대신하지 않으며 분배기는 실행 경로만 정한다.
- 명시적 단일 봇 태그가 우선한다. 정상적으로 끝난 단일 조회는 추가 봇을 호출하지 않고, 중요한 변경·명시적 검증 요청·미확인 결과에만 한 차례 읽기 전용 검토를 붙인다. 장비가 없는 질문의 확인 요청은 불확실 사건으로 오인하지 않는다.
- 변경은 한 봇만 담당한다. 두 봇을 함께 지정하거나 서로 검증을 요청한 변경의 기본 담당은 Hermes다. Ollama만 명시하면 Ollama가 담당할 수 있고 상대는 읽기 전용 검토를 한다. 같은 변경안을 두 lead가 중복 제출하지 않는다.
- 일반 읽기 lead와 모든 peer는 읽기 전용으로 실행한다. 변경 lead만 기존 승인형 도구 범위를 사용하며 카드 승인·보호 주소·증거·TTL·중복 실행 방지는 그대로 적용한다. 봇 합의는 승인이 아니다.
- 기존 후속 문맥·담당 유지·질문 원문 보존·중단 시 보호 작업 재실행 금지를 유지한다. review 답변은 계속 채널 본문으로 이어지며 전용 채널은 지정 봇과 대화한다.

두 봇이 같은 Thor를 쓰므로 별도 GPU 처리 용량이 생기는 배치는 아니다. 이번 변경의 목적은 불필요한 두 번째 답변과 중복 실행 담당을 줄이고 관제 역할을 명확하게 하는 것이다. 현재 모델 정확도나 동시 처리 여력을 새로 입증한 것으로 표시하지 않는다.

## 설치·반영·복구

루트 `deploy.sh`가 기존 `deployment/review_chat.py`의 고정 source 목록으로 분배기·정책을 설치한다. Ollama 설치기의 봇 소개/채널 안내와 공동 채널 안내도 같은 역할로 맞췄다. 추가 설정 키·MCP·패키지·이미지·포트·권한은 없다. 모델·endpoint·공통 SOUL은 이번에 교체하지 않았다.

운영은 B의 2소스와 영수증을 SHA/CAS 대조 후 증분 교체했다. 낡은 기존 worker 영수증 핀은 현재 canonical/실제 파일 SHA를 확인해 정정하고 이전 바이트를 보존했다. idle 확인 뒤 review 분배기만 한 번 stop/start했으며 일반 Hermes/Ollama 봇은 재시작하지 않았다.

B root 전용 `/var/lib/capstone-role-routing/20261103-r1`에 이전/현재 소스·영수증·재현 입력과 원복기를 보존한다. 독립 원복 타이머는 배정·연결 검증 확정 후 해제했다. root 운영자의 수동 복구는 다음과 같다.

```sh
python3 -B /var/lib/capstone-role-routing/20261103-r1/rollback.py --manual
```

진행 중 작업이 있으면 원복은 지연되고, 이번 배포 SHA와 다른 동시 변경은 덮어쓰지 않는다. 실제 운영 원복은 별도 시험하지 않았다. 이번 검사와 한계·게시 상태는 STATUS와 작은 검증 원장을 따른다. 새 서버 전체 설치·실제 보호 변경/승인·공격 시험은 이번 범위가 아니다.
