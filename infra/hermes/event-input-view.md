등록된3종 검색의 실제 성공 결과만 대상으로 하며 `source`, `source_scope`, `untrusted_evidence`, 반환 행 수를 검사한다. 4KiB~128KiB·최대50행이고 10% 이상 작아지는 경우만 사용한다. 동일 스키마 행은 `shared/columns/values`로 표시하며 원문 SHA와 복원 규칙을 포함한다. 중복 JSON 키·NaN·오류·타입/건수 불일치·잘못된 출처·모호한 호출 결속·이종 행의 필드는 제거하지 않고 원래 입력을 유지한다. 외부 데이터의 지시문은 계속 미신뢰 데이터다.

Native는 같은 실행의 유일한 tool call/result를 결속하고 기존 미신뢰 포장을 유지한다. SDK와 compact 자동 사건 보고는 같은 구현을 호출한다. Native의 기존 incident bundle 적용 범위는 확대하지 않았다. 감사 원문·사실 추출·도구 인자·호출 수·읽기 실패 처리·모델/추론 프로필·보호 승인/TTL·FW는 바꾸지 않았다.

초기 설치는 기존 `deploy.sh`의 canonical source 복사와 원문 SHA 고정·관리 게이트 내장 경로를 그대로 사용한다. 게이트는65,266B이며 기존65,536B 인자 상한을 유지한다. 새 패키지·포트·키·오프라인 바이너리는 없다. 실제 새 OS 전체 설치, 모든 질문의 의미 정확성, 실제 UI 재검수·평균/p95는 미검증이다. 운영 백업과 독립 원복 코드·원문/DB/trace를 보존했다.

단순 이력·현재 상태 비교의 추가 보고 생략과 일반 복합 조사 비용 개선은 다음 작업이다. 단순 비교 표로 원인·위험 판단을 대신하지 않는다. 원문 입력 감소만으로 정확성·60초 목표 달성을 주장하지 않는다.

직전143.304초도 판단 실패이며 표본50행, 이번은10행이다. 질문은 같고 새 대화이지만 공유GPU/표본 차이가 있어 시간 차이를 입력 축소의 순수 효과로 계산하지 않는다. 이번 실제10행 영수증은6,271→2,589B다. 각1회 측정이며 평균/p95가 아니다. 원문·미확인 표기·정상 판정 차단을 보존했고 근거가 부족한 판단을 성공으로 처리하지 않았다.
