# 경보 표본 조회와 Native 실행 경로

2026-11-08 하네스 정리 뒤 IDS·Wazuh·Vector 복합 질문을 양 봇에 각각 새 대화로 보냈다.
단순 조회의 공통 렌더러만 같아도 모든 실행 경로의 입력 제한이 같아지는 것은 아니었다.

| 확인한 문제 | 수정한 동작 |
|---|---|
| Hermes 공동 채널의 Native 관리 실행기가 요청하지 않은 `program_name=ossec`를 붙여 Wazuh 표본0건 반환 | 이 경로도 공통 이벤트 조회 스키마를 사용. 사용자가 지정하지 않은 프로그램·agent·IP·룰 필터를 선택할 수 없도록 제한 |
| 최근10건을 반환했지만 `scan_capped=true`여서 무조건 미완료 | 필터 없는 조회에서 정확한 요청 한도·반환수·스캔수·기간·SHA가 일치하면 **표본 조회** 완료. 한도 도달과 추가 경보/구간 전체 건수 미확인은 표에 명시 |
| Native 관리 경로가 단순 경보 조회를 사건 판단으로 계속 처리 | 실제 영수증과 요청 범위가 검증된 경우 같은 `lookup_report`로 종료. 원인·위험·교차 검토·쓰기·모호한 요구는 이 종료 조건에 넣지 않음 |
| IDS/Wazuh 탐지 이벤트만으로 차단 로그 요청까지 완료 가능 | 해당 차단 요청은 일반 조사로 유지. 단순 탐지 목록을 실제 Suricata drop·FW IP차단·Wazuh 대응 집행 증거로 사용하지 않음 |
| 출발지 없는 이벤트의 표 셀이 빈칸 | 사용자 후속 지시로 `IP 정보 없음`으로 표시. 설명을 한 번 붙여 로컬 접속으로 오인하지 않게 하고 수집 자산·프록시 주소로 채우지 않음 |
| 장비명 없는 “최근 올라온 경보 10개 보여줄래”는 공통 경로를 벗어나 자유 생성에서 옛 미기록 표현 재사용 | 통합 수집 경보는 Wazuh 범위를 명시해 조회. 단일 장비의 지정 개수는 실제 schema limit과 반환 영수증에 결속. 범위 밖 개수·모호한 로그·전체·복합 조건은 단순 완료로 바꾸지 않음 |
| 수정 후 Ollama가 ‘최근’ 요청을 현재~미래1시간으로 계산해 조회 거절 | 기간 없는 단순 경보는 실제 등록 스키마 내 최근60분 rolling window만 선택. 절대시각을 선택할 수 없으며 오늘/명시기간 조회와 구분 |

기존 [soc-query](skills/soc-query/SKILL.md)를 범위·실제 읽기·근거 확인·표 보고/종료 순서로 보완했다. 경보 조회의 중복 하네스 문장을 스킬로 통합하고, 기존 SDK/Native 공통 선택기로 필요한 업무 스킬만 넣는다. SKILL은 가이드이며 실제 도구·SHA·필터·기간·승인 검사는 실행기가 담당한다. 추가 모델 호출로 스킬을 고르거나 새 조회 전용 에이전트를 만들지 않았다.

Malformed 행·반환/인자 limit 불일치·실패·SHA 불일치·미확인 필터는 완료되지 않는다.
‘표본 조회 완료’는 사건 종결, 전체 경보 조회, 무공격·무장애 판단이 아니다.

검증했다. 실행 권한이나 승인 경계를 확대한 변경이 아니다. 실제 배포된 controller는
기존 설정을 보존하고 해당 함수와 정확히 일치하는 내장 소스만 갱신했다.

## 별도 미완료

`Vector 오류가 있었는데 지금도 수집에 영향이 있어? 원인과 현재 상태를 구분해서 알려줘`는
Ollama63.445초/실조회0, Hermes221.599초/실조회8로 모두 판단 미완료였다. Hermes의 실패
근거표에서 실제 현재 Vector 읽기가 빠지고 무관한 날짜가 나열된 문제, 일부 미래 시각
표시도 확인했다. 위 단문 조회 수정으로 이 복합 판단 문제까지 해결했다고 표시하지 않는다.
다음은 기간이 생략된 서비스 원인 질문의 실제 읽기 선택, 현재·과거 근거 보존, 시각 출처
및 모델 보고 한도/종료 사유를 대조하는 작업이다.

같은 Vector 질문의 자동 교차검토 화면에서도 수집 지연 한 관측만으로 ‘수집 영향 없음’을 단정하고 정제 이력의 `journal_status`를 원문 접근 가능성과 혼동하는 문구를 확인했다. 단순 조회 개선으로 이 교차검토의 의미 오류가 해결된 것은 아니다.

원문·인자·SHA·실행 로그·복구 후보는 로컬 전용 검증 기록과 B의
`/var/lib/capstone-service-grounding/20261108-harness92`, `harness94`, `harness95`, `harness96`에 보존한다.
