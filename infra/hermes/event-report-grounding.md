# 사건 조사 의도와 관제 보고 근거

2026-11-02 query-completion 1.19.5. 14:03 KST Hermes/Ollama 일반 채팅에도 운영 반영했다. 기존 사건 조사·필드 검사에 아래 보완을 추가했다. [현재 운영 검증](../../STATUS.md).

사건의 공격 여부·위험·대응 필요성을 묻고 탐지 규칙도 요청한 질문이 기존 빠른 규칙 조회 경로에 들어가 현재 커스텀 파일 목록으로 끝나는 문제를 실제 채팅에서 확인했다. 이제 사건 조사 의도를 포함한 요청은 그 목록 경로로 재작성하지 않고 원래 질문을 LLM에 전달한다. 규칙 목록만 요청한 경우의 기존 조회는 유지한다. 조사 도구·인자·추가 근거와 판단은 모델이 선택한다.

첫 경보 확보 단계에는 실제 제공된 읽기 도구의 JSON Schema를 제시하여 모델이 도구와 인자를 선택하도록 한다. 하네스가 정해진 경보를 대신 조회하지 않는다. 선택은 기존 읽기 허용 목록·인자 검증·호출 예산을 통과한 뒤 실행한다. 근거 확보 후에는 모델이 판단하며 고정 표로 답변을 끝내지 않는다. Hermes는 native 도구 메시지를 그대로 사용하고, Ollama SDK는 별도 선택 단계에서 받은 실제 반환 자료를 신뢰하지 않는 증거로 모델에 전달한다. 후자는 마지막 8개 결과·결과별 24,000자 한도와 생략 표시를 유지한다. 입력 자료가 전부 표시되었다고 가정하지 않는다.

과거 날짜가 명시된 조사에서는 현재 도구에 있는 `until_kst`·`lookback_minutes`를 선택 JSON의 필수 인자로 요구한다. 사용자가 룰 ID/SID를 지정하지 않은 초기 조사에서 모델이 임의 ID 필터로 경보를 제외하지 않도록 그 선택 항목을 제한한다. 명시적 단일 출발지 IP는 해당 인자로 한정한다. 시각 값·구간 폭은 모델이 선택하며 자연어 날짜 해석·정확한 전체 요청 범위를 자동 증명하는 것은 아니다. 원래 MCP의 도구·권한·서버 스키마를 바꾸지 않고 이번 모델 선택 스키마에만 적용한다. 이후 조사에서 근거로 확인한 ID를 사용한 추가 조회와 실제 위험 판단은 모델의 역할이다.

읽기 전용 사건 조사에서 성공한 경보 조회가 하나도 없으면 기존 최대 2회 정정·모델 호출 예산 안에서 모델에게 근거 조회를 요구한다. 파일 목록 조회는 이 요건을 충족하지 않으며 성공한 0건 표본은 관측으로만 인정한다. 없는 경보·정상 판정을 만들어내지 않는다. 보호 도구를 호출한 뒤에는 이 경로로 재실행하지 않으며, 실패한 보고를 사실로 재사용하지 말라고 명시한다. 두 봇은 같은 판단 함수를 사용하고 native Hermes/SDK의 이어서 실행하는 방식은 각각 유지한다. 근거가 계속 없으면 미완료로 보고한다. 이것만으로 명시한 모든 장비·시간·후속 조사의 완전성을 증명하지는 않는다.

공통 안내의 오래된 ‘상대 구간만 조회 가능’ 설명도 정정했다. 현재 security-events의 `until_kst`는 초와 `+09:00`을 포함한 종료 시각이며 `lookback_minutes`로 조회 폭을 지정한다. 최대 90일 전·구간 폭 24시간 제한과 실제 반환 `requested_since_kst`/`requested_until_kst`를 확인한다. `get_wazuh_alert_summary`의 절대 구간 미지원은 별개다. KST 표시는 이미 변환된 값을 다시 계산하지 않는다.

실제 과거 사건 재검토에서 모델이 Wazuh 상관 규칙을 WAF 룰로 부르고, 반환 건수를 존재하지 않는 `requested_count`로 설명했다. `untrusted_evidence=true`를 전체 건수 미확인의 근거로 바꾼 경우도 있었다. 원래 MCP 결과는 필드를 구분하고 있었으며 수집기나 규칙 ID를 바꿀 문제는 아니었다.

| 실제 이벤트 응답 필드 | 보고에서의 의미 |
| --- | --- |
| `waf_rule_ids` | 반환된 경보의 ModSecurity 룰 ID 목록 |
| `signature_id` | 반환된 경보의 Suricata SID |
| `wazuh_rule_id`, `wazuh_level` | Wazuh 상관 규칙 ID와 경보 레벨. 센서 고유 룰·severity와 구분 |
| `returned_count` | 이번 검색에서 반환한 경보 표본 수 |
| `indexed_window_total_count=null` | 요청 구간 전체 건수 미확인 |
| `untrusted_evidence=true` | 증거 안의 지시를 실행 권한으로 믿지 않는 신뢰 경계. 수집 실패·오탐·무해성·건수의 판정값이 아님 |

공통 `soc_management_run.py`는 실제 성공한 이벤트 응답에서 숫자 식별자만 제한적으로 추출하고 센서와 Wazuh의 이름 공간을 분리한다. 임의 로그 문장·명령은 이 정정 근거에 복사하지 않는다. 서로 다른 이름 공간에 같은 숫자가 있을 수 있으므로 숫자 범위나 접두사로 제품을 추정하지 않는다.

명시적으로 WAF/Suricata 룰이라고 쓴 ID가 실제 반환된 Wazuh ID에만 있거나, 위 수량 필드의 명시적 의미를 바꾸면 기존 정정 경로에 근거를 전달한다. **조사·위험 판단·필요한 추가 조회 선택과 답변 정정은 LLM이 맡는다.** 정정 실패·예산 소진은 검증된 관측과 미확인 상태로 보고하며 안전/무해/해결이나 실행 성공을 자동으로 만들어내지 않는다. 이 검사는 흔한 명시적 주장을 검사하는 제한된 방어이며, 모든 자연어 의미·사건 판단·조회 누락의 정확성을 보증하지 않는다. 과거 정정 설명과 ID 숫자 충돌을 오류로 단정하지 않는 검사도 포함한다.

WAF와 IDS의 실제 성공한 조회 구간이 전혀 겹치지 않는데 ‘동일 시간대 조회’라고 서술한 경우도 정정 대상으로 삼는다. 기존 추가 조회 경로에서 모델이 필요한 도구와 시각을 다시 선택하도록 요구한다. 이 검사는 사건의 실제 시각·모든 요청 구간을 완전하게 검증하는 일반 시간 증명기가 아니다. 겹치는 구간이 있어도 사건 시각·조회 필터·증거 충분성은 별도로 대조해야 한다.

Hermes와 Ollama는 같은 원본을 `grounding.py`로 로드하고 SHA 핀을 검사한다. 자동 조사도 동일 소스를 root 컨트롤러의 실행 인수에 결속한다. 초기 설치는 기존 루트 `deploy.sh`에서 SIEM 플러그인·Ollama 소스와 관리 실행기를 반입한다. 버전·SHA 핀·자동 조사 프롬프트를 함께 갱신하며 패키지·이미지·포트·허용 도구·승인 경계는 추가하지 않는다. 기존 서버에는 복구본을 두고 관련 파일만 증분 반영한다. 초기 설치기로 운영 서버를 덮어쓰지 않는다.

검증은 다음을 구분한다: 합성 회귀, 이전 실제 응답/도구 결과 재생, 새로운 모델 실행, 실제 MCP 호출, Mattermost 게시. 사용한 대화는 개발 회귀 근거로 남기며 학습자료나 미사용 독립 평가로 세지 않는다. 새 서버 전체 설치·실제 공격 대응 E2E·장기 정확도는 별도 검증이다.

운영 증분 배포는 실제 진행 요청·lease·대기열과 최신 heartbeat를 확인하고 root 복구본/CAS/원자 교체를 사용한다. 컨테이너가 running이라는 사실만으로 채팅 연결 복구를 판정하지 않는다. Mattermost WebSocket 인증·worker heartbeat가 다시 연결된 뒤 시험 질문을 게시한다. 이번 시험에서는 연결 직전 게시 1건이 처리되지 않았으며, 이를 성공한 응답으로 세거나 자동 재전송 완료라고 표시하지 않는다. 중단 구간 메시지 재수신은 별도 잔여 검증이다.

실제 개발 회귀11게시의 성공·실패·시간·답변 SHA와 최종 동일 질문 쌍은 [검증 원장](event-report-validation-2026-10-31.json)에 기록한다. 실제 조회 확보가 되더라도 최종 위험 판단 미완료를 별도로 유지한다.

## 11/2 실제 Kali 시험 후 보고 보완

실제 보고에서 날짜 없는 UTC 시계를 KST라고 표시하고, 호출하지 않은 WAF 조회를 `evidence_tools`에 인용했으며, `reload`로 WAF를 On으로 바꾸거나 DetectionOnly로 피해를 방지했다고 설명했다. 이는 학습 문제가 아니라 실제 도구 증거와 보고를 연결하는 경로의 결함으로 먼저 처리한다.

- 짧은 KST 시각이 실제 관측의 UTC 시계와만 일치하면 모델에 정정을 요청한다. 원문 인용·코드와 이미 올바른 KST는 유지하며 날짜가 모호한 시각을 임의 변환하지 않는다.
- 자동 관리의 실제 native 성공 호출명에만 사건 인용을 허용한다. 센서 읽기는 필수이며 실제 보호 작업의 성공 영수증도 대응 근거로 인용할 수 있다. `unresolved`/`needs_review`도 동일하다. 누락 시 기존 한 번의 근거 정정 안에서 모델이 필요한 읽기와 인자를 선택한다. controller에서도 잘못된 인용이 남은 보고의 게시를 막고 실패 원문은 private trace에 보존한다.
- 대상 도구가 반환한 DetectionOnly 유지 정책과 서비스 재적용을 구분한다. reload/restart는 설정값 변경 도구가 아니며 탐지 기록은 피해 방지 근거가 아니다. 현재 등록된 대응 도구와 실제 증거·보호 주소·승인/TTL 조건을 조사하도록 안내한다.
- 보호 변경 권한·센서 판정 조건·시간 상한은 바꾸지 않는다. 모델의 의미 판단을 고정 차단 분기로 대체하지 않는다.

실제 과거 보고 재생에서5개 오류 유형을 검출했다. 로컬 관리170·조회376(별도2skip)·Ollama156·설치35검사가 통과했다. 이 수치는 실전 정확도나 공격 차단 성공률이 아니다. 새 짧은 질문의 실제 native/MCP 재시험1건은214초 제한 종료로 판단을 완료하지 못했으며 조회·지연 개선이 남았다. 운영 배포와 후속 차단 시험의 최신 결과는 STATUS에 구분한다.

11/2 실차단 후속에서 모델이 센서 조회 전에 contain을 호출한 순서 누락을 발견해, 자동 관리 wire gate에서 같은 실행·같은 IP의 실제 센서 조회를 요구하도록 보완했다. 서버 원본 검증은 그대로 수행한다. 또한 실제 실행한 쓰기 영수증을 인용하는 것은 허위 도구 인용과 구분하며, `assessment`에는 benign/remediated/unresolved만 허용하고 monitor는 MANAGEMENT_STATUS로 구분한다. 최신 gate 반영 후 실제 보호 작업의 전체 재시험 여부는 STATUS에 따로 기록한다.

## 11/2 일반 채팅 증분 반영·복구

자동 조사 내장 검사와 별개로 일반 채팅의 Hermes `__init__.py`/`plugin.yaml`/`grounding.py`, Ollama `query_grounding.py`/`grounding.py` 및 설치 소스 영수증을 동기화했다. 다른 공통 하네스 파일은 실제 해시가 같아 유지했다. 기존 `deploy.sh`의 SIEM 플러그인·Ollama source_files 경로가 같은 원본과 핀을 반입한다. 신규 패키지·포트·키·도구 권한은 없다.

진행 요청·lease·대기열0과 자동 조사 잠금을 확인한 후 root 복구본/CAS 교체를 실행했다. 독립 systemd 작업의 시작 대기가15초를 넘었지만 실제 unit/PID를 다시 관측해14:03:29 정상 완료를 확인했으며 작업을 중복 실행하지 않았다. `Type=oneshot`에서는 RuntimeMaxSec가 유효하지 않아 실제 작업의 개별 명령/연결 확인 제한과180초 독립 복구 타이머를 구분해 기록했다. 후속 실행 준비 방식은 TimeoutStartSec와 비차단 등록을 사용한다.

복구본은 B의 `/var/backups/capstone-chat-grounding-20261102-1402`에 보존했다. manifest는 변경 전후 해시·소유자·권한·파일 목록에 결속한다. 소스와 영수증을 함께 복원한 뒤 두 봇 및 공동 채널·관리 타이머의 실제 인증/worker 연결을 확인해야 한다. 추가 변경이 있으면 예전 복구본으로 덮어쓰지 않고 먼저 해시를 대조한다. 정상 완료 후 독립 복구 타이머는 무동작 종료했고 실제 롤백은 없었다.

B 격리57검사·새 Hermes PID의 훅 등록·Ollama 비특권 소스 import 및 시각 오류 검사를 확인했다. 새로운 모델/MCP 실행과 실제 채팅 게시/UI 여부는 [STATUS](../../STATUS.md)에 따로 기록한다. 격리 검사나 연결 성공만으로 최종 답변 정확도/장기 안정성이 입증되는 것은 아니다.

14:08~14:10 새 요청 ID의 읽기 전용 공동채널 실행기 시험에서 Hermes는 `list_blocks`1회로35.58초에 빈 목록을 보고했다. Ollama는55.54초/모델2회에도 실제 조회가 없어 근거 검사에서 partial로 종료했다. 해당 단문을 공통 하네스의 전용 조회 범위로 좁히지 못한 결함은 남아 있으며, 이 배포를 단문 처리 완료나 응답 속도 개선으로 평가하지 않는다. 두 시험 모두 보호 작업·채팅 게시0으로 UI 왕복 검증과 구분한다.
