## 확인한 원인과 변경

실제 모델이 `since_kst`, `until_kst`, `lookback_minutes`를 함께 선택했다. 이전 공개 MCP schema는 이를 허용했지만 실행 검사는 거절했다. 앞선3센서×8시간 조합 중9개가 불일치했고, 후보 실행에서3회의 도구 오류가 발생했다.

| 형식 | 허용 조건 |
|---|---|
| 상대 기간 | `lookback_minutes` 또는 생략. 종료 시각 `until_kst`를 함께 지정할 수 있음 |
| 정확한 시작·종료 | `since_kst`와 `until_kst`를 함께 지정하고 `lookback_minutes`는 생략 |
| 날짜·시각 | 초와 `+09:00` 포함, 최대6자리 소수초. 달력 유효성·미래/보관 범위·양수/최대24시간은 실행부에서 추가 검사 |

Wazuh/Suricata/ModSecurity/웹 접근4도구의 공개 schema에 의존·배제 조건을 추가했다. Native 첫 선택/후속 읽기와 SDK의 모델 선택에는 같은 조건을 두 개의 닫힌 객체 분기로 전달한다. 원래 등록 schema와 정확 인자 검사는 실제 MCP 호출 전에 그대로 수행한다. 모르는 조건은 임의로 제거하지 않는다. 도구·권한·로그 쿼리·모델·추론 강도는 바꾸지 않았다.

초기 설치 검증기가 예전 도구수28/37, 별도 시험은32/41을 기대하던 문제도 발견했다. 현재 정책의 **읽기35+보호9**에 연결하고 보안 이벤트7도구와 보호 경계를 함께 검사한다. 단일 `deploy.sh`의 기존 소스 복사 경로를 사용한다. 새 패키지·키·포트·설정 입력은 없고, 운영 서버에 초기 설치기를 다시 실행하지 않았다.
