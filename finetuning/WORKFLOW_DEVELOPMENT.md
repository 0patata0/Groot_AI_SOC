**현재 학습본에 공통 역할 지침을 주어도, 모델 출력만으로 실제 조회와 정확한 보고를 보장할 수 없었다.** 개발용16사례에서 조회 없이 조회했다고 쓴 FW·DNS·서비스 답변3개를 확인했다. 설치된 Ollama 하네스의 기존 근거 검사는 세 답변을 모두 검출했다. 보정 후 실제 답변·Hermes·채팅 검증은 이번 시험에 포함하지 않았다. [재현 원장](WORKFLOW_DEVELOPMENT_REVIEW.json) · [현재 평가 범위](EVALUATION_SCOPE.md) · [운영 상태](../STATUS.md).

## 기존 운영 방어와 평가기 수정

| 점검 | 결과와 한계 |
|---|---|
| 대상 확인 | 실제 설치 `runtime.run`이 대상 미지정 질문을 확인 질문으로 반환. 네트워크·subprocess 금지, 모델/MCP0. 다른 분기와 채널 전달은 미시험 |
| 무조회 주장3개 | 설치된 `harness.violations`가 FW·DNS·rule-worker 답변을 모두 검출. 실제 수리 호출·최종 게시 결과를 대신하지 않음 |
| 최신 진단 스키마 | 기존 평가기는 journal의 추가 조건·메타데이터를 지원하지 않아 모델 요청 전에3fixture를 거절했음. 알려진3/5조건을 검사하고 의존성·대상·상한·알 수 없는 조건 거절을 유지하도록 평가기만 수정 |
| 수정 검증 | 로컬49검사, 기존 B환경 진단15검사, 서버 표준 Draft2020-12와18인자 구조 반례 일치. 16fixture/15기준 호출 모두 현재 스키마 유효. 실제 도구의 추가 시간/상태 검증까지 실행한 것은 아님 |
| 재현 오류 | 최초 B 시험 파일의 경로 배치 오류는 모델 호출 전 수정. 근거 수집기의 supervisor 로그 허용 목록 누락2회도 보존·수정. 모델/운영 실패로 합산하지 않음 |

운영 소스·스킬·MCP·생성 설정·모델·권한·서비스는 변경하지 않았다. 하네스 변경을 하지 않았으므로 이번 평가기 수정에 공식 Harness²를 실행했다고 표시하지 않는다. 최신45스키마는 명시 반입 목록에 추가했으며 과거44스키마는 재현용으로 유지한다. 데이터 본문·원자료·가중치는 Git에 넣지 않는다.

근거73개·3,883,007바이트의 SHA와 감독/작업자 종료를 확인한 뒤 B 자체 시험85파일·4,228,173바이트를 제거했다. 설치 소스7개는 불변이며 Ollama·공동 검토 채팅 서비스 active를 관측했다. 이 확인에서 Hermes 컨테이너/채널 상태까지 새로 검증했다고 확대하지 않는다. 기존19파일 PREPARED후보·복구본·G_Harness2는 보존했다.

## 사용 이력과 다음 단계

개발 validation16은 이번 모델 진단·수동 검토에 사용했으므로 이후 미사용 평가로 부르지 않는다. 원래 source fixture의 지문을 [사용 원장](EVALUATION_USAGE.json)에 기록하되, 공통 정책/현재45도구를 적용한 실제 wire 입력과 동일한 지문이라고 주장하지 않는다. 실제21요청 본문 SHA는 별도 원장에 보존했다. test16은 이번 실행에 요청하지 않았으며, 이것만으로 그 자료의 과거 미사용·독립성을 인증하지 않는다.

다음은 검수한 추가 읽기 관측과 동등한 복수 경로를 준비하고, 현재 운영의 보정·최종 게시까지 새 채팅에서 확인하는 것이다. 하네스를 고치면 기존 공통 스킬 우선·공식 Harness²·동결·회귀·정확 승인·관리자 경유 적용·새 채팅 순서를 따른다. 기존19파일 승인 대기 후보와 이번 결과를 섞거나 자동 적용하지 않는다. 이 결과만으로 새 학습·모델 승격·운영 정확도 또는30/60초 채팅 목표 달성을 선언하지 않는다.
