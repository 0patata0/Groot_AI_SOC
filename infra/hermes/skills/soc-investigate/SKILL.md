# SOC 사건 조사·상관분석
SOC_WORKFLOW_INVESTIGATE_V1

LLM이 관제 주체로 사건을 조사하고 위험·조치 필요성·후속 확인을 판단한다. 경보 발생, 실제 성공/피해, 대응 집행, 위험 해소를 구분한다.

- 원 요청·사건 시각·센서/규칙 이름공간·출발지/목적지와 실제 자산 등록을 확인한다. 수집 agent를 공격 대상 호스트로 바꾸거나 IP만으로 이름·실습 승인을 추정하지 않는다.
- 원 사건과 이후 구간을 구분해 필요한 센서·앱/호스트 근거를 읽는다. 사건 관계는 실제 시각·주소/자산·거래/흐름 식별자·원문 좌표로 설명한다. 여러 룰 매칭을 여러 공격으로 세지 않는다.
- WAF 응답과 백엔드 접근, IDS 경보와 방화벽 상태, Wazuh 경보와 실제 호스트 행위를 분리한다. 403·경보0건·현재 active·기한 만료만으로 침해 실패/종결을 단정하지 않는다.
- manager 자체 로그와 agent 사건 경보를 구별한다. 보호 대상의 영향 확인에는 등록된 실제 agent와 사건/후속 구간을 사용하고, 출발지/룰 필터로 다른 호스트 징후를 제외한 표본을 전체 영향으로 확대하지 않는다.
- PAM/SSH 인증 성공·세션/서비스 로그, 낮은 경보 레벨은 승인된 정상 활동의 충분한 근거가 아니다. 정상화·시험 여부·원인 판단에 필요한 별도 근거를 조사하고, 없으면 무엇이 부족한지 남긴다.
- 조치 타임라인은 요청 등록·최초 적용 확인·임시 기한·현재 관측·종료 처리 확인을 각 원필드에 연결한다. 미기록된 적용 시각을 만료/TTL로 역산하거나 등록 시각으로 대체하지 않는다.
- 결과·표본/기간·수집/보관 한계·미확인 자산과 필요한 다음 조사를 추적한다. 종결 최소 검사는 충분한 의미 검증을 대신하지 않는다. 실제 판단 메타데이터는 실행기 계약에 맞추고 내부 제어 줄은 감사에만 둔다.
- 교차 검토도 필요한 근거를 직접 대조한다. 상대 보고의 결론·잘못된 범위를 복사하지 말고 누락·모순·확인된 일치와 남은 한계를 구별한다. 출력은 공통 soc-output을 재사용한다.
