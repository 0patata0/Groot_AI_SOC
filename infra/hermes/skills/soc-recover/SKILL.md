# SOC 장애 진단·복구
SOC_WORKFLOW_RECOVER_V1

서비스·수집 경로의 가용성과 관제 공백을 조사한다. 사건 조사와 연관되면 해당 절차를 함께 사용하고, 보호된 복구 변경은 soc-change 절차로 연결한다.

- 오류 메시지·대상·발생/관측 시각과 현재 상태를 구분한다. 등록된 실제 진단 대상·수집 시각·TTL·표본/잘림을 확인한다. agent/호스트와 관리 컨테이너를 혼동하지 않는다.
- 프로세스·MCP 전송·인자/대상 오류·로그 수집·색인·저장소·알림 전달 중 어디까지 실제 확인했는지 구분한다. 응용의 요청 거절을 네트워크 단절로, 미조회/오류를 정상으로 표시하지 않는다.
- systemd oneshot의 inactive/dead만으로 실패를 단정하지 않는다. Result·종료 종류/코드·실패 unit·해당 시각의 실제 사건 근거를 함께 확인한다. 현재 snapshot을 임의 과거 journal이나 전체 서버 건강으로 확대하지 않는다.
- 기존 작업/실행 handle이 살아 있으면 같은 실행을 관찰한다. 관측 시간 초과·일시적 접속 실패만으로 종료를 선언하거나 재시작하지 않는다.
- 원인과 복구 필요성을 판단하고, 현재 MCP가 지원하는 고정 작업 범위에서 후보·영향·검증·원복을 준비한다. 일반 shell/sudo/Docker·패키지 설치·임의 unit/config 제어로 권한을 확대하지 않는다.
- 복구 후 실제 서비스뿐 아니라 수집·색인·진단/알림 전달의 필요한 구간을 확인한다. 프로세스 active나 재시작 성공만으로 누락 복구·전체 무손실·사건 해소를 선언하지 않는다.
- 지원되지 않는 진단·복구와 미확인 구간을 명시하고 다음에 필요한 근거/도구를 남긴다. 확인된 결과·조치·승인·남은 공백은 공통 soc-output으로 보고한다.
