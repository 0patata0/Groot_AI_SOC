# 근거 기반 응답 가드레일

두 봇의 관제 판단은 실제 MCP 결과에 연결한다. `SOUL.groot.md`의 필수 역할에 증거 기준을 두고, 공통 `chat_contract.py`와 `soc_management_run.py`가 답변을 내보내기 전 확인 가능한 주장·상태를 검사한다. 프롬프트 준수와 코드 검사 통과는 전체 정확성을 보장하지 않는다.

| 계층 | 적용 기준 | 한계 |
|---|---|---|
| SOUL / 공통 역할 | 관측 사실·근거 있는 해석·미확인을 구분한다. 근거가 부족하면 실제 등록 읽기를 추가하고, 기억·다른 봇 동의를 현재 증거로 쓰지 않는다. | 모델이 지시를 어길 수 있으므로 이것만으로 완료하지 않는다. |
| 보고 스키마 | 제한된 오류 이력만으로 무해·복구 종결하지 않는다. 현재 관제 지표가 있는 서비스 보고에는 현재 상태 설명을 요구한다. | 필수 필드 존재가 의미 정확성이나 요청 완수를 보장하지 않는다. |
| 출력 근거 검사 | 검토 상태 수를 처리·전송 대기로 바꾸는 표현, 실제 지표와 다른 건수, 비교 관측 없는 추세, 두 관측과 반대 방향의 추세, 근거 없는 정상·재시작 부재 등을 검사한다. | 명시된 한국어/필드 표현과 관측 구조에 한정한다. 모든 표현·인과관계·생략을 검출하는 범용 판정기가 아니다. |
| 정정·실패 처리 | 기존 제한 정정 기회와 추가 읽기를 사용한다. 거절된 결론은 성공으로 게시하지 않고, 실패 시 확인된 근거와 판단 미완료를 보존한다. | 정정 실패를 정확한 최종 답변이나 사건 해결로 세지 않는다. |
| 실제 변경 | 기존 MCP의 정확 후보 승인·증거·보호 주소·TTL·작업 허용 범위를 계속 검사한다. | 이 변경으로 도구·쓰기·sudo·Docker 권한을 늘리지 않는다. |

`review_required_cases`는 검토 상태 합계다. `pending_reports`, `running_cases`, `overdue_cases`와 의미가 다르며, 이 지표들이 양수여도 검토 수를 다른 지표에 옮겨 쓸 수 없다. 같은 절대 시각을 UTC/KST로 달리 표기한 자료는 두 번의 비교 관측이 아니다. 같은 표본에서 한계 설명 뒤에 별도의 단정을 붙여도 그 단정은 검사 대상이다.

SOUL에 남아 있던 “원문 journal 조회가 아니다”라는 과거 설명도 바로잡는다. 실제 진단 MCP의 `view=journal`은 등록 대상·기간·행 수를 제한한 원문 발췌이며, 현재 snapshot·정제 오류 이력·제한 발췌의 범위는 서로 다르다. 임의 shell 권한은 아니다.

## 검증 범위

2026-11-08 개발 비교의 실제 모델 출력 12개를 재생했다. 새 균형 학습본의 보고 5개 각각에서 적어도 하나의 근거 위반을 검출했고, 추가 근거 요청 1개는 오답으로 세지 않았다. 질문 누락·문장 의미·출처 오해에 대한 수동 검토도 별도로 남겼다. 이 재생은 새 질문에 대한 모델 정확도나 100% 할루시네이션 방지율이 아니다.

초기 회귀에서는 영문 필드 뒤 한국어 조사와 `검토 사건` 표현의 검사 누락을 발견해 수정했다. 최종 Linux9프로필1,627회(고유1,599) PASS/skip0,10:45:54 B16파일 적용·10:53:03 28manifest/보호9·양봇 연결/4서비스·유휴 큐·원복 확정을 확인했다. 새 자연어 질문은 Ollama70.691초/조회0, Hermes136.214초/6조회 중1기간오류로 모두partial이다. 확인 없는 완료는 거절했지만 요청을 완수하지 못했으며 등록 대상의 자연어 연결·필수 과거/현재 읽기가 후속 과제다. [STATUS](../../STATUS.md)에 구분한다. 새 OS 전체 설치·보호 쓰기·공격 E2E를 이번 검사로 대신하지 않는다.

## 설치와 복구

진입점은 `deploy.sh`다. 기존 `source_bundle`, SIEM 역할, Ollama 설치기의 공통 소스 복사 경로가 SOUL·공통 계약·고정 실행기·query 플러그인을 함께 배포한다. 새 deb/wheel/image·포트·자격·모델 변경은 없다. 운영 반영은 관리자231 경유, 원본 파일/소유권/권한/해시 백업, 유휴 큐 확인과 독립 원복 타이머를 사용한다. SOUL은 일반 대화의 선호나 봇 자체 수정으로 바꿀 수 없다.

운영 모델은 기존 원본35B를 유지한다. 새 학습본의 등록·GPU 추론 성공과 운영 적격은 별개이며, 미사용 평가와 실제 MCP·채팅 검증 전 승격하지 않는다.

Mac 작업용4폴더16,288,309B와 서버 격리4폴더1,888파일30,157,562B를 확인 후 제거했다. 운영 원본 백업·시험 원문·가중치는 보존했다.
