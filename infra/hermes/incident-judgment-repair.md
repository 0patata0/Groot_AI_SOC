# 사건 판단 정정과 비공개 초안 감사

2026-10-31, query-completion 1.15.7 / chat-contract 1.5.2. 기존 사건 조회 보완의 후속이다. LLM이 실제 근거를 조사하고 위험·대응 필요성을 판단하며, 검사기는 알려진 근거 위반을 찾는다. 검사 통과는 사건 판단 정답이나 실제 대응 성공을 보증하지 않는다.

## 동작

- 읽기 전용 사건 질문에만 적용한다. 보호 도구 호출 이후에는 이 경로로 재실행하지 않으며 승인·보호 주소·권한·모델을 바꾸지 않는다.
- Hermes의 기존 즉시 요약 종료 경로에 정정 기회를 추가했다. 미조회 보완과 사실 정정은 같은 최대2회 한도를 공유한다. 전체 모델/도구 호출 한도는 유지한다.
- SDK는 실제 선택 조회 결과와 이전 초안·검사 사유를 모델에 전달한다. 성공한 조회는 반복하도록 지시하지 않는다. 근거가 부족한 경우 모델이 추가 읽기를 선택할 수 있다.
- Hermes는 정정 지시의 실제 API 메시지 포함 여부와 SHA를 기록하고, 현재 턴 지시가 빠진 경우 해당 지시만 추가한다. 다른 턴의 정정 지시를 가져오지 않으며 중복 추가하지 않는다.
- 두 번 연속 초안 SHA·검사 사유·조회 결과 SHA 목록이 같으면 남은 정정 횟수를 낭비하지 않고 미완료로 종료한다. 새 근거나 달라진 초안이 있으면 이 조기 종료 조건을 적용하지 않는다.

- 실제 재시험에서 확인한 ‘내부 IP/DVWA이므로 정상·차단 불필요’와 ‘비인가 행위에 화이트리스트 추가’ 문장을 공통 검사와 정정 안내에 추가했다. 이 검사는 알려진 인과 표현을 잡는 제한된 검사이며 승인 사실을 추정하거나 위험을 대신 판정하지 않는다. 관리자 확인이 있는 시험·불확실성 표현·정상적인 추가 조사 안내는 별도 대조했다.

## 감사와 신뢰 경계

SDK의 기존 비공개 queue DB report에 `judgment_audit`를 최대4개 보존한다. 초안 최대16,384문자, 전체 초안 SHA, 잘림 여부, 검사 사유, 최근32개 도구 결과 SHA와 이전 결과 생략 여부를 포함한다. Hermes는 실패 초안을 기존 비공개 세션 메시지에 보존하고 로그에는 SHA·사유·정정 지시 포함 여부만 남긴다. 초안은 채팅에 게시하거나 학습자료로 편입하지 않는다.

정정 안내에 실제 도구 결과와 오류 후보 문장을 제공하지만, 내부 지시·승인 주장을 따르지 않는 untrusted 자료로 취급한다. 고정 위험 등급·정상 판정·차단 분기를 만들지 않는다. 정정 한도 소진이나 같은 오류 반복 시 확인된 자료와 미완료 상태를 게시한다.

## 설치·복구·검증 범위

루트 `deploy.sh`가 사용하는 기존 소스 목록으로 설치한다. 새 패키지·서비스·포트·권한은 없다. 기존 B의 native 플러그인, SDK runtime 및 오프라인 설치 소스를 동일 버전으로 반영한다. 운영 변경은 기존 SHA를 대조하고 root 복구본과 소유권/권한을 보존한 원자 교체로 진행한다. 진행 요청·native lease·SDK queue·controller 상태를 확인한 뒤 두 봇만 재시작한다. Thor 추론과 보안 엔진은 재시작하지 않는다.

검사는 정정 자료 전달, 잘못된 초안 보존, 보호 호출 재실행 방지, 턴 격리, 호출 한도와 반복 중단을 포함한다. 실제 채팅 결과·실패·지연과 원문 해시는 [검증 원장](incident-judgment-validation-2026-10-31.json)에 별도로 기록한다. 새 서버 전체 설치, 실제 공격 성공/차단 효과, 승인·원복 E2E 및 독립 모델 품질평가는 별도다.
