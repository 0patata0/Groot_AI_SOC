## 원인과 수정

16:36 KST A/B/C의 현재 failed unit은0이었다. B의 지난3시간 기록에는 `controller_already_running` 54회가 있었다. 기존 조사·채팅 또는 비공개 계측이 제어기 잠금을 보유한 동안15초 타이머가 실행되면 중복 실행을 차단했지만, 이를 exit1로 반환해 systemd 실패 경보가 반복됐다. 이번 비공개 성능 계측도 해당 경보를 발생시켰다.

`Store.locked()`가 실제 비차단 flock 충돌만 `ControllerBusy`로 구분한다. 예약 실행 `--once`는 `status=deferred`를 기록하고 exit0으로 끝난다. 잠금을 해제한 뒤 기존15초 타이머가 다시 조회한다. 충돌한 실행에서는 broker 조회·모델 호출·보고 전송·사건 복구·커서 전진을 하지 않는다. 사건 처리 완료나 보안 정상 판정으로 바꾸지 않는다.

DB·파일/권한·통신 오류와 같은 문자열을 가진 일반 예외는 계속 실패한다. 명시적 `--review-case`가 잠금을 얻지 못하면 실패를 반환하여 접수하지 않은 요청을 성공으로 알리지 않는다. 잠금·실행 제한·승인·TTL·경보 룰·과거 로그는 유지한다. 장시간 작업 또는 멈춘 잠금 소유자의 상태 점검을 대신하는 수정은 아니다.
