# 하네스 정리 범위와 순서

2026-11-08 사용자 지속 지시에 따라 이후에도 공식 Harness²로 **구성 정리 → 동결 → 회귀 → 운영 대조·배포 → 새 채팅** 순서로 진행한다. Harness²는 구조·편집 경계·변경 목록 확인을 보완하며 후보는 확인한 실패 근거로 작성한다. 단순 구조 검사를 실제 봇 검증으로 부르지 않는다.

| 영역 | 단일 기준 | 이번 정리 |
|---|---|---|
| 역할·권한·보호 | SOUL + MCP/worker의 강제 검사 | 역할 우선순위와 승인/보호/TTL 유지. 문구 중복을 이유로 집행 검사 삭제 금지 |
| 절차 선택 | workflow_contract + soc-query/investigate/change/recover | 조회와 사건 판단 구분. 기존 스킬 재사용, 유사 스킬 신규 복제 없음 |
| 질문·도구 범위 | 공통 harness의 structured_read/tool_scope | 단순 경보·로그 누락 보완. 모호한 필터·복합 판단·쓰기·peer는 별도 경로 유지 |
| 결과 표 작성 | 공통 lookup_report → 종류별 renderer | SDK 두 지점·Native 두 지점·공동 채널이 같은 순서 사용. 실제 조회를 모델이 선택하고 호출한 뒤 표현만 공통화 |
| 완료 판정 | 실제 영수증 SHA·기간·필터·반환 상태 | 오늘 KST 구간, 제한 표본/전체, 0건/실패 구분. 문자열 표 생성만으로 성공 처리 금지 |
| 출력 지침 | soc-output 한 스킬 | 단일 장비/단일 행도 표. 상세 설명만 필요한 줄글. 원문·승인 diff 보존 |
| 전송·표 정규화 | 공통 chat_markdown | 이미 있는 표 보존, 별도 명시 항목만 표 변환. 각 설치 사본 SHA 확인 |
| 정기 보고 | soc_bot | 정책 전후 0/0 반복 제외·룰 설명 표시·관측 출발지와 실제 공격자 구분 |

정리용 감사 표면에는 SOUL 원본·5개 SKILL·조회/실행/채널/출력/증거·권한 모듈을 함께 넣는다. 실행기의 안전 검사는 불변 컨텍스트로 대조한다. 프레임워크용 스킬 색인은 검사 전용이고 실제 프롬프트에 추가하지 않는다. 이력에 기록된 최초 정리는 8개, 후속 경보 조회 정리는 그 안의 3개 후보 파일만 편집 대상으로 허용하며 테스트·평가기·보호 코드는 편집 표면과 분리한다.

## 별도 미완료

일반 복합 판단 정확도·실제 응답 지연, 사건 카드 색상, 승인형 임시 OS 작업, 자체 스킬 후보 승인 연결, Suricata 인라인/장비별 실트래픽 시험은 별도 작업이다. 구조 정리와 위 단문 각1회 성공으로 이 기능들을 완료했다고 표시하지 않는다. 프레임워크 임시 설치는 결과·변경 patch·SHA·인계 자료를 보존한 뒤 제거했다.
