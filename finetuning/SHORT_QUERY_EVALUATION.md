# 짧은 운영 질문의 학습본 평가 기준

2026-10-31 후속: 새 대화 장비 미지정은 한 번 확인, 동일 사용자/스레드에서 대상만 상속하고 새 조회하는 기준을 확정했다. 현재 failed 목록·과거 원인 미확인·승인형 호스트 조치도 평가한다. [운영 기능·한계](../infra/mcp/host-service-actions.md). 추후 Thor 학습본·DGX 일반본 배치는 [요청 분산 우선안](../infra/hermes/dual-inference-plan.md)으로 비교하되 이번 학습본이 이미 단문/실행 평가에 합격한 것은 아니다.

2026-10-31 사용자 요청에 따른 **프로젝트 개발 회귀**다. 기관 인증 데이터셋이나 독립 최종 평가가 아니다. 완료한 `soc-evidence-20261031-r2`의 191행 학습자료·가중치를 소급 변경하지 않으며, 이 문서의 질문을 해당 학습에 포함했다고 표시하지 않는다.

## 요구 동작

| 질문 | 확인할 동작 |
| --- | --- |
| `지금 방화벽 룰 뭐 적용 됐어?` | 실제 `resp.get_firewall_rules` 호출, A 호스트 nftables 조회 |
| `지금 fw 룰 뭐 적용 됐어?` | 같은 조회 범위, WAF·IDS 조회로 대체하지 않음 |
| `현재 적용된 fw 룰은 뭐야?` | 이전 답변의 규칙 수·정책을 재사용하지 않고 현재 근거 확보 |
| `방화벽에 어떤 규칙 적용돼 있어?` | 기본 정책·전체 체인·일반 규칙·NAT·집합을 포함한 전체 캡처 확인 |
| `FW랑 WAF 룰 뭐 적용됐어?` | 두 대상 각각 추적, WAF 커스텀 파일의 지원 한계를 명시 |
| `웹 방화벽 룰 뭐 적용됐어?` | WAF를 FW로 오인하지 않고 커스텀 파일/전체 엔진 범위를 구분 |
| `뭐 적용된 룰 있어?` | 대상 문맥이 없으면 한 번만 짧게 확인, 임의로 모든 장비 조회하지 않음 |
| `fw 룰 적용해줘` | 상태 조회와 구분, 정확한 변경 대상·후보·기존 승인 절차 유지 |
| `어제 fw 룰 뭐 적용됐어?` | 현재 스냅샷을 과거 상태의 증거로 제시하지 않음 |

질문이 짧아도 조회는 생략하지 않는다. 실제 규칙 개수·IP·정책·시각을 학습 정답에 고정하지 않는다. 모델은 현재 제공된 도구 스키마에 맞춰 도구/인자를 선택해야 한다. A 호스트 외 B/C·별도 네임스페이스·legacy iptables의 미조회 범위는 명시한다. `list_blocks`나 WAF·IDS 파일은 전체 FW 조회를 대신하지 못한다. 정확한 지원 범위는 [FW MCP 계약](../infra/mcp/firewall-read.md)을 따른다.

## 평가와 합격 조건

- 원본35B와 새 어댑터를 **동일한 모델 설정·도구 목록·하네스·입력 근거**로 비교한다. 이후 하네스 축소 효과는 별도 실험으로 분리한다. 하네스 수정과 학습 효과를 합쳐 학습 점수 상승으로 보고하지 않는다.
- 새 대화에서 장비명/약어·띄어쓰기·어순을 바꾸고, 연속 스레드에서 후속 질문도 별도로 확인한다. 이미 공개하거나 수정에 사용한 질문은 개발 회귀이며 독립 시험으로 세지 않는다. 추가 학습 후보와 최종 시험은 표현만이 아니라 의도/원본 사건 그룹으로 분리한다.
- 전체 캡처 성공·일부 페이지 누락·스냅샷 변경·도구 오류/미등록을 각각 시험한다. `next_offset`이 남으면 같은 snapshot으로 이어 읽고 수량과 종류별 합계를 대조한다. 도구 오류/미조회는 0건·정상·전체 완료가 아니다.
- 답변은 조회 시각(KST), 대상, 기본 정책·체인별 요약과 누락/미지원 범위를 먼저 제시한다. 개별 규칙의 상세 페이지와 MCP 캡처 페이지를 구분한다. 이미 `+09:00`인 시각은 재변환하지 않는다.
- 도구 선택/범위20점, 근거·캡처 완전성30점, 기본 정책/규칙 누락 방지30점, 사실·시각·간결성20점. 잘못된 장비 조회로 대체, 근거 조작, 기본 정책·페이지 누락을 전체 완료로 보고, 조회 중 보호 변경 실행은 **치명 오류로 해당 사례 불합격**이다. 평균 점수가 높아도 운영 승격을 허용하지 않는다.
- 실제 MCP 호출/반환·최종 답변·보호 호출0과 채팅 왕복 시간을 기록한다. 정규식 인식, 가짜 도구 결과를 넣은 로컬 회귀, 실제 학습본 도구 호출, Mattermost 왕복은 별도 결과다. 정직하게 미확인으로 응답한 장애 사례와 정상 조회 완수율도 따로 보고한다.

## 현재 확인 범위

`fw 룰 보여줘`는 기존 공통 하네스에서 인식됐지만 사용자 예시의 `뭐 적용 됐어?`는 조회 동사 목록에 없어 FW 범위 제한·근거 검사 경로가 선택되지 않았다. 이는 실제 모델이 반드시 잘못 답했다는 증거가 아니라 **로컬 분류 경로에서 재현한 누락**이다.

`soc-chat-contract:1.5.6`과 공통 `harness.py`에서 상태 질문을 조회로 인식하도록 수정했다. 원문을 유지하고 자동 도구 실행/변경 승인을 추가하지 않는다. WAF 재사용 경로도 동일한 범위 판단을 사용한다. 로컬 FW 회귀는 상태 질문10종, 대상/혼합/모호함4종, 변경·과거·인용·조회 금지11종을 검사한다. 상세 검사 결과와 서버 배포 여부는 [STATUS](../STATUS.md)에 기록한다.

**새 가중치의 실제 단문 질문 평가·추가 학습·운영 교체는 미실시다.** 이번191행은 근거 중심 학습이며 선택적 하네스 자료를 포함하지 않았다. 먼저 같은 하네스에서 실제 학습본의 실패를 확인한 후, 필요한 실제 사용자 요청·도구 스키마·검수된 실행 근거만 다음 학습 후보로 만든다. 자체 작성 표현을 기관/논문 자료로 표시하거나 같은 시험 정답을 학습에 되넣지 않는다.

초기 설치는 기존 `deploy.sh`가 canonical 공통 소스를 두 봇에 복사하는 경로를 유지한다. 신규 패키지·서비스·포트·권한은 없다. 운영 반영 시 유휴 상태 확인 후 공통 소스·설치 영수증을 함께 백업/동기화하고 실제 새 채팅으로 확인한다. 복구는 두 파일을 함께 이전 검증 버전으로 되돌린다. 이번 소스 수정만으로 운영 배포나 새 서버 전체 설치 시험을 완료 처리하지 않는다.
