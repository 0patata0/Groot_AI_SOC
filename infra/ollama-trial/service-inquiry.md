# 서비스 조사 추가 읽기 실행

`more_evidence=true`는 조회 완료가 아니다. Ollama SDK에서 이 응답을 받으면 모델이 선택한 등록 읽기 도구의 정확한 입력 스키마로 호출 계획을 생성하고, 검증 후 MCP를 호출해야 한다. 새 도구 영수증으로 다시 판단한다.

이전 실제 채팅은 추가 근거 요청 3회 뒤 원래 질문을 일반 에이전트에 반복 전달했다. 모델 호출 7회/109.325초 동안 실읽기는 초기 3회에 머물렀고, 최종 초안의 처리 지연 주장은 검증기에서 거절됐다. 후속 읽기 도구 선택이 실행으로 이어지지 않은 런타임 문제와 모델의 의미 오류를 구분한다.

## 구현 경계

- 기존 읽기 allowlist·도구 입력 JSON Schema·호출 예산·시간 제한을 사용한다. 모델이 추가 읽기의 대상과 인자를 선택하며 고정 코드가 사건 판단을 대신하지 않는다.
- 계획의 요청 nonce와 전체 묶음을 검증한 뒤 호출한다. 보호 도구·존재하지 않는 도구·출력 필드를 입력으로 사용하는 계획은 실행하지 않는다.
- 같은 읽기 전용 조사 안에서 이미 성공한 **동일 도구/동일 인자**가 포함된 계획은 전체를 거절한다. 실제 실패한 읽기의 재시도나 바뀐 페이지·표본 수·조회 인자는 이 규칙으로 막지 않는다. 값이 같은 별칭/기본 인자까지 정규화한 중복 방지는 아직 아니다.
- 거절 사유와 미실행 여부를 모델에 돌려준다. 모델은 다른 읽기나 확인된 사실·기능 공백 보고를 선택할 수 있다. 같은 거절 계획이 다시 나오면 미완료 상태로 종료한다. 없는 원인·정상·복구를 만들어 성공 처리하지 않는다.
- 생성 JSON·조회 전 영수증 SHA·거절 계획은 감사에 남긴다. 내부 추론문은 저장하지 않는다. 실제 읽기 결과가 추가되었는지 확인하며, 제안만으로 실행했다고 기록하지 않는다.

## 실패를 포함한 검증

첫 후보는 실제 MCP 연결에서 추가 조회를 수행했지만, 이미 본 대기열과 현재 상태를 반복해 112.651초/12모델 호출/11실읽기 후 미완료로 끝났다. 보호 쓰기는 0회였다. 이 후보는 운영에 적용하지 않았다.

중복 계획 피드백을 추가한 수정본은 SDK291검사를 통과했다. 앞선 공통·Native·query·peer·설치 프로필과 합산한 고유 검사는1,444개/skip0이다. 최초7프로필 검사 후 SDK 코드만 수정하고 SDK291개를 다시 검사한 결과이며,1,444개를 마지막 수정 뒤 모두 재실행했다는 뜻은 아니다. 실제 수정 후보는38.731초/5모델/3읽기로 종료했으나 판단 미완료였다. 02:19:32 KST runtime/영수증2경로를 운영 확정하고15소스/보호8·양봇 연결/실행부·4서비스·큐0을 확인했다. Hermes는 재시작하지 않았다. [검증 원장](service-inquiry.validation.json) · [현재 현황](../../STATUS.md).

운영 실제 채팅에서 같은 ISO 시간 질문은41.642초/3실읽기/5모델·partial, 새 표현의 압축 KST 시간 질문은78.365초/조회0·partial이었다. 원문 SHA3개와 감사 기록·표1개/코드블록0을 확인했으나 UI 전수 검증은 아니다. 시간 표현만 ISO로 바꾼 로컬 재현에서 필수3읽기 계획이 복원돼 공통 기간 인식 공백을 분리했다. 두 채팅 모두 조사 성공으로 세지 않는다.

별도의 호출 스키마 후보4출력은 같은 완료 조회를 선택하거나, 중복 금지 스키마를 어기거나, 처리/검토 상태를 모호하게 설명해 비채택했다. 검사 통과만으로 복합 판단이 해결됐다고 표시하지 않는다.

## 복구·설치

변경 대상은 SDK `runtime.py`와 이에 대한 테스트다. 단일 `deploy.sh`의 기존 SDK 소스 설치·SHA 영수증 생성 경로가 같은 파일을 사용한다. 신규 패키지·포트·인증정보·sudo/Docker 권한은 없다. Hermes 공통 계약과 Native 실행 소스는 바꾸지 않는다. 실제 새 OS 전체 설치나 보호 쓰기·공격 E2E 검증은 이번 범위가 아니다.

운영에 반영할 때에는 이전 런타임/영수증 백업·독립 원복 타이머를 만들고, 대기열이 비었을 때 해당 채팅 실행부를 갱신한다. 소스·영수증·보호 설정·서비스·양봇 연결·대기열을 확인한 뒤 원복 타이머를 해제한다. 현재 스위치 `CAPSTONE_SERVICE_REPORT_COMPACT=0`은 기존 일반 조사 경로로 되돌리는 복구 옵션이며, 검증한 정상 기본값은1이다.
