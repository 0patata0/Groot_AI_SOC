## 검증 중 보완한 로컬 결함

1. **잘못된 offset:** Python이 `+09:60` 같은 값을 정규화해 받아들이던 경로를 제한했다. 관측 시각은 거절하고 원천 시각은 `invalid`로 표시한다.
2. **프로토콜 불일치:** `TCP`와 숫자 `6`, `UDP`와 `17` 등이 같은 상관 키가 되도록 알려진 IP 프로토콜 번호를 통일했다. 모르는 번호는 문자열로 유지한다.
3. **많은 WAF 규칙 ID의 처리 비용:** 중복 검사에 집합을 사용해 최초 순서를 유지하면서 반복 목록 검색을 제거했다.
4. **출력 상한:** 정제 JSON을 **프로젝트 한도 32KiB**로 제한한다. 초과하면 `normalized_event_too_large`로 레코드 전체를 거절하고 다음 입력을 처리한다. 규칙 배열을 자르거나 일부 ID를 조용히 버리지 않는다.

32KiB는 Wazuh 공식 이벤트 크기를 뜻하지 않는다. 현재 스키마의 제한된 문자열과 logtest 요청 포장 여유를 고려한 프로젝트 정책이다. 정확히 32,768바이트 출력은 로컬·설치 엔진에서 통과했고, 1바이트 초과와 다음 레코드 복구는 로컬에서 검증했다. 원천 입력 한도 1MiB와 출력 한도는 별개다. 실제 agent→manager 경로의 별도 제한은 후속 검증 대상이다.

독립 부하 확인은 Mac Python 3.12.5/Darwin arm64에서 합성 WAF ID 30,000개·입력 약 919KB를 약 0.055초에 출력 초과로 거절했다. 별도 메모리 추적 실행은 약 0.364초·추적 피크 약 16.5MiB였다. 전체 프로세스 RSS나 운영 서버 지속 부하 측정은 아니다.

## 운영 연결을 막는 WAF 입력 문제

현재 `/home/groot_a/capstone/secstack/logs/modsec/audit.log`의 8,432바이트·4줄을 확인했다. 네 줄 모두 일반 JSON 파서는 읽지만 **`transaction.response.headers.Server`가 한 번씩 중복**된다. 현재 strict 파서는 원천에 관계없이 중복 JSON 키를 거절하므로 네 줄 모두 정제 전에 거절됐다. 파서를 묵시적인 마지막 값 우선 방식으로 완화하지 않았다.

추가 진단에서는 메모리 사본의 요청·응답 헤더를 통째로 제외한 뒤 나머지 필드 변환을 확인했다. 4건 모두 변환되며 원문 `DetectionOnly`·`action=observed`가 유지됐지만, `time_stamp`는 `Mon Oct 12 18:00:36 2026` 같은 **offset 없는 형식**이라 전부 `timezone_missing`이었다. 이 진단 사본은 원문 수용 성공이나 증거 해시 검증으로 계산하지 않는다. 실제 수집 경로에는 사용하지 않았다.

현재 WAF 컨테이너의 `date`는 UTC였다. 이것만으로 과거 네 레코드가 생성될 당시의 시간대를 확정하지 않는다. 수집 어댑터에는 다음이 필요하다.

- 중복 키의 경로를 보존해 검사하고, 제외할 헤더와 IP·시각·규칙 ID 등 판단에 사용하는 필드를 구별하는 명시적 처리 정책. 판단 필드의 중복은 계속 거절해야 한다.
- 생성 당시 원천 시간대 근거와 원본 바이트/위치 보존. 근거가 없는 시각은 계속 품질 문제로 남기고 KST를 임의 부여하지 않는다.
- 거절 레코드의 격리·계수·재처리 경로. stderr만 남기고 원문과 연결을 잃는 수집기를 만들지 않는다.

## 방화벽 동작 의미와 배포 후속 조건

라이브 룰에서 `FW_SSH_RATE`는 같은 룰에 drop이 있었고, `FW_DROP_IN`·`SPOOF`·`AGENT_BLOCK` 로그 뒤 다음 룰은 drop이었다. `FW_SHADOW_OUT` 뒤에는 drop이 없었다. 이 검사는 룰 위치·verdict 대조이며 특정 로그 패킷의 최종 처리를 캡처한 시험은 아니다.

현재 모듈의 `SPOOF/AGENT_BLOCK=observed`는 보수적인 일반 계약을 유지한다. 이 값이 실제 허용됐다는 뜻은 아니며, 배포 시점의 고정 룰 프로필과 결속해 더 정확한 drop 의미를 부여할지는 수집 설계에서 결정해야 한다. `FW_DROP_OUT/FWD`는 이번 실제 표본에 없었다.

후속 순서는 WAF 입력 정책·원천 시간대 근거 → 회전/체크포인트/재전송/격리 수집기 → 별도 환경의 상관 룰/중복/시간창 → agent 전달·Indexer·큐 부하 검증이다. `copytruncate`, 재부팅, 부분 줄, 디스크 상한 및 장애 복구까지 통과하기 전에 운영에 연결하지 않는다. 병렬 정제 입력이 큐 부하를 줄인다고 가정하지 않는다.
