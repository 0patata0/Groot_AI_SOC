# SOC 조회
SOC_WORKFLOW_QUERY_V1

요청한 목록·상태를 실제 읽기와 `soc-output` 표로 반환한다. 이 스킬은 권한이나 승인을 부여하지 않는다. 담당 역할·실행 권한은 SOUL과 현재 도구 카탈로그를 따른다.

1. **범위를 정한다.** 짧은 질문의 명시 장비를 유지한다. 같은 사용자·대화에서 대상이 분명하면 이어받고 새 대화의 ‘룰 보여줘’는 장비를 한 번 확인한다. 봇의 과거 오답을 근거로 삼지 않는다. 원인·위험·영향 판단은 `soc-investigate`, 변경은 `soc-change`로 이어가며 단순 조회 완료로 대신하지 않는다.
2. **필요한 읽기를 선택한다.** 아래 업무와 실제 카탈로그의 대상·필수 인자·enum을 대조한다. 요청하지 않은 장비·IP·프로그램·agent·룰 필터를 추가하지 않는다. 등록 도구로 조회할 수 있으면 연결·권한을 추측해 포기하지 않는다.

| 요청 | 실제 조회 범위 |
|---|---|
| FW 룰 | `get_firewall_rules`의 기본 정책·체인·NAT 전체. `list_blocks`는 현재 임시 차단 IP 요청에 사용 |
| WAF·IDS·Wazuh 룰 | `get_security_rules`의 기본+커스텀. 명시한 origin·Wazuh 상관 조건을 존중. 편집용 파일을 전체 규칙으로 대체하지 않음 |
| 장비 경보·로그 | 해당 `search_*_alerts`의 반환 표본. 탐지 목록은 실제 IDS drop·FW 차단 집행 증거가 아님 |
| 장비명 없는 최근 경보·이벤트 | Wazuh에 수집된 통합 경보를 조회하고 그 범위를 표에 명시. ‘로그’만 요청하면 대화 맥락으로 대상을 확인 |
| 서버·서비스·journal | `get_system_diagnostics`의 등록 대상·view. 서비스 상태와 과거 원문·전체 기능 정상은 구분 |
| 실행 서비스·컨테이너 목록 | `get_host_inventory`: 일반 서비스 요청은 loaded systemd와 Docker를 구분해 함께 조회. 명시 호스트를 유지하고 생략 시 A/B/C 범위를 밝힘 |
| 수신 포트·자원·프로세스 | 같은 도구의 ports/resources/processes. 포트 수신≠FW 허용, load≠CPU%, 프로세스 CPU%는 수명 기준. 프로세스 인자·환경은 제공하지 않음 |
| Docker 상세·자원·로그 | 정확한 container 이름과 container_details/stats/logs. 상태/health/재시작/포트/네트워크/볼륨/제한을 조회. Env/Cmd/Labels·전체 inspect는 반환하지 않음. 로그는 최근15분 제한 마스킹 표본이며 stdout/stderr 포함 |
| OS 서비스 상세·네트워크·저장소 | service_details에 실제 .service 이름. loaded unit의 실행/종료/재시작/자동시작/자원 필드. network는 인터페이스·주 라우팅·DNS 설정, storage는 로컬 파일시스템 용량 |

호스트 인벤토리는 60초 주기 스냅샷이며 수집 시각·조건 일치 건수·표시 건수·페이지를 함께 표시한다. 실행 중≠기능 정상, 오래된 자료·실패≠0건이다. limit/offset은 각 호스트·분류별 적용이며 새 페이지는 새 스냅샷일 수 있다. 서비스 전체 설치 목록 대신 loaded unit을 조회했다면 범위를 숨기지 않는다. 상세 원인/추세/임의 필터를 이 단순 목록으로 충족했다고 답하지 않는다.

출력은 `soc-output`의 호스트별 구획을 따른다. 요약 표 다음에 A/B/C 각 호스트의 상세 표를 따로 두며, 각 호스트 안의 systemd·Docker도 구분한다.

기간 없는 ‘최근’ 경보는 제공된 최근60분 `lookback_minutes`를 선택하며 절대시각을 암산하지 않는다. 오늘/금일은 KST 자정~요청 시각의 `since_kst`·`until_kst`이고 lookback과 혼용하지 않는다. 지정 기간은 최신 요약으로 대체하지 않는다. 제공된 KST를 재변환하지 않는다.

‘경보 10개’처럼 개수를 지정하면 실제 카탈로그가 허용한 `limit`에 맞춰 조회한다. 반환이 적으면 실제 건수만 보여주고 요청 건수를 채우려고 행을 만들지 않는다. 전체 조회·여러 장비 합계·범위 밖 개수는 단일 표본 조회로 완료 처리하지 않는다.

3. **근거와 범위를 확인한다.** 실제 성공한 응답·필터·기간·반환수를 확인한다. 전체 목록 요청은 동일 snapshot의 next_offset을 끝까지 따른다. 표본 한도 도달은 전체 건수·추가 경보 유무 미확인으로 표시하며, 실패·0건·미지원은 구분한다. 누락된 범위만 추가 조회하고 같은 성공 결과를 목적 없이 다시 읽지 않는다. 반복 실패는 같은 인자로 계속 재시도하지 말고 실패·미확인 범위를 남긴다.
4. **보고하고 종료한다.** 필요한 근거가 갖춰진 단순 조회는 `soc-output`으로 바로 표를 반환하고 끝낸다. 같은 결과를 다시 설명하기 위한 모델·MCP 호출이나 교차검토를 추가하지 않는다. 상세 요청 때만 필요한 설명을 덧붙인다. 표본 조회 완료는 사건 종결·무공격·무장애 판단이 아니다.

같은 결과의 재정리·다음 페이지는 동일 대화의 검증된 영수증과 관측 시각을 사용한다. 새 조회가 없으면 밝히며 실패·변조·잘린 결과나 오래된 결과를 최신 근거로 재사용하지 않는다. 명시한 교차검토는 원질문과 독립 영수증을 대조하며 두 봇의 동의 자체는 근거가 아니다.
