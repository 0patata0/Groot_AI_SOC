## 자동으로 확인하는 공통 요소

[evaluation_scope.py](evaluation_scope.py)는 전체 레코드·실제 입력·기존 학습 준비기의 비assistant 입력을 각각 해시로 대조한다. 비assistant 입력 일치는 시스템/assistant 문맥을 제외하므로 **잠재 재사용**이며 실제 전체 입력 일치와 구분한다. 행 ID변경·정답 수정으로 소비 이력을 숨기지 못하도록 입력도 비교한다. 도구 정의만 있고 실제 호출/관측이 없는 경우도 별도 집계한다.

소비 원장에는 확인된 과거 test128과 후속 개발validation16의 원자료 지문·근거가 있다. 후속16의 지문은 검토에 쓴 source fixture의 식별자이며 현재 정책·도구를 적용한 실제 wire 입력과 같다는 뜻이 아니다. 실제21요청 본문 SHA는 별도 [개발 원장](WORKFLOW_DEVELOPMENT_REVIEW.json)에 보존한다. 질문·정답 본문·자격·가중치는 공개 원장에 포함하지 않는다. 원장에 없다는 이유로 독립/미사용을 인증하지 않는다. 정적 감사는 어떤 경우에도 `independent_operational_quality_proven`이나 운영 승격을 허용하지 않는다. 새로운 자료가 진정 독립적인지는 다른 검증이 필요하다.

```sh
python3 -B finetuning/evaluation_scope.py   --cases /검증용/평가.jsonl   --training /검증용/학습.jsonl
```

CLI는 주어진 파일을 읽어 메타데이터만 출력한다. 도구 실행·모델 요청·학습/배포 기능은 없다. [비교 준비기](prepare_quality_comparison.py)는 프로필을 만들기 전에 이 감사를 수행하고 각 split의 역할·사용 이력·미입증 범위를 계획에 넣는다. 불완전한 대화/변조된 입학 자료는 출력 전에 거절한다. 기존 데이터와 학습 수학은 바꾸지 않는다. [pack.py](pack.py)의 명시 소스 목록에도 검사기·원장·비교 준비기의 의존성을 연결했다. 평가 본문을 자동 추가하거나 GPU에 정제를 위임하지 않는다.

최종 운영 평가는 새 사건/출처 계열을 분리하고,초기 질문에는 정답·미래 관측을 주지 않은 상태에서 실제 등록 조회·추가 조사·상관·영향·승인/거부·조치 후 확인·보고를 평가해야 한다. 치명적 누락·잘못된 대상·승인 우회·근거 없는 정상/성공·합리적 추가 읽기의 미지원 분기를 각각 기록한다. 보호 행동은 승인된 범위에서만 실행한다. 정적 CTI/분류 점수나 fake관측 계약 검사를 그 검증으로 대신하지 않는다.

같은기관의 다른행·표현만바꾼질문·이미사용한test의재채점은새최종평가로세지않는다. 결과를보고후보를수정했다면그자료는개발회귀로이동하고다른새평가를확보해야한다. 공격·새학습중단과정확19파일적용승인대기는그대로유지한다.
