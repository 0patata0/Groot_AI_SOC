파일별 변경 전/후 SHA, 원래 후보의 패치 SHA, 비교용3소스의 SHA는 [manifest](manifest.json)와 [source-manifest](source-manifest.json)에 고정한다. 비교용 소스는 시각 검증과 Native 분할의 이전 구현을 보존하는 입력이며 운영 원복본이 아니다. [comparison.patch](comparison.patch)로 복원하고 원래 검증 주장을 유지한다.

시각 회귀의 고정 원문13개 검사는 그대로 보존했다. 다만 전체 도구 설명까지 같다고 보던 기대값에는 이번에 의도적으로 추가한 앱 선언/수집 정책의 정확한 세 문장만 넣었다. 입력 스키마·나머지 도구 필드·시간·자원 검사는 그대로 비교한다. 원본 시험 SHA와 기대값 보정은 [어댑터](test_clock_compat.py)에 명시한다.

실제 원문/영수증·설치 소스 사본·계정 자료는 로컬 전용 검증 폴더에 보존했다. 공개 자료에는 원시 journal·비밀 값·운영 자격을 넣지 않았다. 관측한4개와42개는 개발에 사용한 필터 결과이며 새 독립 정답·학습 추가분이 아니다. 모델 호출·신규 학습·공격·채팅 게시를 수행하지 않았다. 기존 학습/evaluation 사용 원장은 바꾸지 않았다.

공식 구조·회귀·실제 소스 읽기·운영 적용·모델 판단·실제 채팅은 다른 증거다. [검증 원장](validation.json)의 초기 실패와 생략, 마지막 운영 관측 시점, 미수행 범위를 함께 확인한다.

## 운영자 캐시 복구 모듈의 후속 근거

[별도 원장](cache_validation.json)은 고정34소스 후보를 바꾸지 않는 운영자 모듈·시험·대상 초안의 SHA를 기록한다.40개 회귀는 프로젝트 작성 시험이며 기관의 독립 사건 정답이 아니다. A/B/C 실제 캐시를 읽기 전용으로 내보내 격리 사본에서 정책 이전·이벤트 보존·원복을 확인했고, 고정24시간 Native 읽기의 실제 cgroup 상한/peak/한도 이벤트를 기록했다. 원문·DB 바이트·프로브 소스·세 서버 결과는 로컬 전용 검증 폴더에 보존한다.

초기 Reader `files=[]` 점검은 유효하지 않은 입력으로 실패했으며 inspect.signature 기반 가용성 검사로 정정했다. 이는 점검 코드의 실패이고 추론·드라이버 오류로 집계하지 않는다. 첫38개 시험을 최종40개와 섞지 않는다. A/B의 최종 collector 잘림을 완료로 해석하지 않으며, 공식 Harness²를 이 운영자 모듈에 새로 실행하지 않았다. 독립 source/cache 배포 조정·정확 승인·실제 운영 인수는 미수행이다.

## 수집 상한 선점 보완의 후속 근거

[수집 오버레이](collection-manifest.json)는 기본34소스 위 런타임3·기존 시험2만 바꾼다. 별도40시험은 프로젝트 반례이며 기관 실사건·새 SFT 자료가 아니다. 공식 Harness²37구성/5면·상시 증가0, Mac1410/기존6생략, 기존 Hermes 이미지1493/생략0을 확인했다. 원래 통합 manifest·패치·캐시 준비 영수증은 불변이다.

실제 A/B/C의 동일4시간 비교와 B의 기존 원문12행/앱 오류4ID·캐시 사본0→4·새 관측 보존/원복은 [별도 원장](collection-validation.json)에 기록한다. 현재0건은 고정 분류 범위이며 침해 부재가 아니다. 원문·DB 바이트·실제 채팅 자료는 공개 산출물에 넣지 않았다. 기존 개발 구간을 새 독립 평가나 학습 성능 향상으로 세지 않는다.

Mac과 Linux의 경로/소유자 조건 차이로 기존 음성 시험의 계약 불일치가 드러났다. 원래 실패와 입력을 보존하고 허용 호스트·거절 수집 대상의 양성/음성 계약을 명시했다. 과거 통과의 정확 원인을 재현하지 않았으므로 특정 권한 검사가 가렸다고 확정하지 않는다. 전체 회귀·공식 구조와 별도로, 운영 수집기의 유한 자원 설정·배포 조정·정확 승인·로드/새 스캔·실제 MCP/채팅은 남는다.
